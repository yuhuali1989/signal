# 第5章：VLA/VLX 产品落地——从数据采集到模型部署

## 5.1 VLA 模型选型

### 5.1.1 端侧 vs 云端分工

```
端侧（NPU 4 TOPS）                 云端（GPU 集群）
    │                                  │
    ├── Lite VLA（量化 1B）            ├── 教师 VLA（7B-70B）
    ├── 实时推理 < 50ms                ├── 高质量推理（但高延迟）
    ├── 仅关键帧推理                    ├── 全帧率分析
    └── 结果缓存 + 异步上传             └── 训练新模型
```

**策略**：端侧跑 Lite VLA 做实时决策，云端跑 Full VLA 做离线分析和模型迭代。

### 5.1.2 模型压缩路线

| 压缩技术 | 效果 | 适配层 |
|:---------|:-----|:-------|
| 4-bit NF4 量化 | 内存降 75%，推理 9× 加速 | 端侧 NPU |
| 知识蒸馏（7B→1B） | 保留 ~95% 精度 | 训练阶段 |
| 结构化剪枝 | 参数量减少 40% | 训练阶段 |
| LoRA 微调 | 单任务适配，4GB 显存即可 | 云端训练 |

**推荐基础模型**：
- **端侧推理**：MiniCPM5-1B（量化后） / SmolVLM-256M（Lite VLA 路线）
- **云端训练**：LLaVA-VLA（开源 VLA 框架，7B 级）
- **标注辅助**：Gemini 3.5 Flash API（自动标注初稿）

## 5.2 训练 Pipeline

### 5.2.1 数据准备

```
数据湖 Iceberg
    │
    ├── 自动筛选（场景多样性 + 困难样本挖掘）
    ├── 自动标注（Gemini API 生成初稿 → 人工校验）
    ├── 数据增强（合成数据 + 仿真环境）
    └── 训练数据集导出（Spark → TFRecord / WebDataset）
```

**困难样本挖掘策略**：
- 端侧 VLA 推理置信度 < 0.7 的样本 → 优先上传
- 场景聚类（K-means）→ 每个聚类中心保留最多 1000 条
- 时序异常检测 → 保存异常片段

### 5.2.2 训练架构

```
┌───────────── 训练集群（K8s + GPU）──────────────┐
│                                                    │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐     │
│  │ 数据加载  │    │ 模型训练  │    │ 模型评估  │     │
│  │ (Spark)  │───→│(PyTorch  │───→│ (A/B 测试)│     │
│  │          │    │ FSDP)    │    │          │     │
│  └──────────┘    └──────────┘    └──────────┘     │
│       │               │               │            │
│       ▼               ▼               ▼            │
│  Iceberg 读     GPU 节点池        S3 模型存储      │
│  (WebDataset)   (P4d/P5 实例)    (model.pt)       │
└────────────────────────────────────────────────────┘
```

### 5.2.3 训练成本

| 训练场景 | GPU 数 | 时长 | 成本（按需） | 成本（Spot） |
|:---------|:-------|:-----|:-----------|:-----------|
| Lite VLA 蒸馏（1B） | 8×A100 | 24h | ~$1,200 | ~$360 |
| Full VLA 训练（7B） | 64×A100 | 72h | ~$28,800 | ~$8,640 |
| 每周迭代（增量） | 8×A100 | 8h | ~$400 | ~$120 |
| 月度大版本 | 64×A100 | 120h | ~$48,000 | ~$14,400 |

## 5.3 端侧部署

### 5.3.1 OTA 模型下发

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 模型仓库   │───→│ OTA 服务  │───→│ 设备端   │
│ (S3)     │    │ (控制面) │    │ (NPU)   │
└──────────┘    └──────────┘    └──────────┘
                     │
              ┌──────┴──────┐
              ▼             ▼
         灰度 10%      继续评估
              │
              ▼
         灰度 50%
              │
              ▼
         全量推送
```

**OTA 灰度策略**：
1. **Canary 1%**：内部测试设备 → 24h 监控
2. **Ring 10%**：自愿升级用户 → 48h
3. **Ring 50%**：特定区域 → 72h
4. **全量 100%**：通过后全量

**回滚机制**：端侧保留上一版本模型，OTA 失败自动回滚。

### 5.3.2 端侧推理引擎

```
┌────────────── 设备端推理 ──────────────┐
│                                          │
│  传感器输入 ──→ 端侧预处理 ──→ NPU 推理    │
│                              │           │
│                     ┌────────▼────────┐  │
│                     │  Lite VLA 模型  │  │
│                     │  (4-bit量化1B)  │  │
│                     └────────┬────────┘  │
│                              │           │
│                     ┌────────▼────────┐  │
│                     │  动作指令输出    │  │
│                     │  + 推理结果缓存  │  │
│                     └─────────────────┘  │
│                              │           │
│                     ┌────────▼────────┐  │
│                     │  异步上传结果    │  │
│                     │  (WiFi/蜂窝)    │  │
│                     └─────────────────┘  │
└──────────────────────────────────────────┘
```

**推理框架选型**：
| 框架 | 适用 | 备注 |
|:-----|:-----|:------|
| llama.cpp + GGUF | CPU 端侧 | Lite VLA 路线（树莓派已验证） |
| ONNX Runtime | NPU 部署 | 支持量化 + 硬件加速 |
| TensorFlow Lite | 移动端 | 生态最成熟 |
| 自研 NPU Runtime | 自研芯片 | 极致性能优化 |

## 5.4 A/B 测试框架

### 5.4.1 模型评估指标

| 指标 | 离线（训练阶段） | 在线（A/B 测试） |
|:-----|:--------------|:---------------|
| 任务成功率 | ✅ 测试集准确率 | ✅ 用户任务完成率 |
| 推理延迟 | ✅ 端侧基准测试 | ✅ 端到端延迟 P50/P95 |
| 数据效率 | ❌ | ✅ 每千帧有效样本数 |
| 幻觉率 | ✅ 人工评估 | ✅ 用户反馈率 |
| 崩溃率 | ❌ | ✅ OOM/崩溃率 |

### 5.4.2 A/B 测试架构

```
用户设备 ──→ OTA 服务
                │
         ┌──────┴──────┐
         ▼              ▼
     模型 A（对照组）  模型 B（实验组）
         │              │
         ▼              ▼
     数据上报 ──→ 离线分析
                      │
                 ┌────┴────┐
                 ▼         ▼
             模型 A 胜   模型 B 胜
                 → 全量   → 灰度扩量
```

## 5.5 本章小结

本章设计了 VLA/VLX 产品从端侧推理到云端训练再到 OTA 下发的完整链路。核心策略是「端侧 Lite + 云端 Full」的双模型架构，通过 4-bit 量化、知识蒸馏、A/B 灰度发布等工程化手段，在亿级设备规模下实现模型的安全迭代。下一章讨论数据闭环飞轮——如何让数据自动驱动模型持续提升。

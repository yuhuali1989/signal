# 第 7 章 · 证据阶梯 L0–L3：怎么证明「我做了 RSI」

第 6 章说瓶颈是验证。这一章把「验证」变成一把尺子：一个团队宣称做了 RSI，你该要求它出示哪一级证据。

## 7.1 四级阶梯

| 级别 | 名称 | 主张 | 必要证据 | 现状 |
|---|---|---|---|---|
| **L0** | AI 辅助研发 | 模型帮人写代码/造数据 | 生产力统计（且需自打折） | 普遍 |
| **L1** | 有界自精化 | 系统改自己并变好，改进器不变 | 单次 A/B + 冻结集回归 | **已工程化** |
| **L2** | **点火 / 改进者增益** | 新版本 improver 让后续变强**更快** | 共同起点 + 匹配资源 + 独立测试的跨轮反事实 | **公开系统 0 个达标** |
| **L3** | 可靠加速 | 改进速率随轮次持续上升、可外推 | 多轮改进速率曲线 + 跨领域迁移 | 无 |

L0 和 L1 的区别在「有没有闭环」，L1 和 L2 的区别在「**改的是 learner 还是 improver**」，这是整把尺子上最关键的一格。第 1 章说的「算子采纳率 61% 不是 RSI 证据」，用这把尺子一量就很清楚：那是 L1。

## 7.2 点火判据：一个可写进实验脚本的定义

「点火」不该是修辞。给它一个可测量形式：

```
在共同起点 S_0、匹配资源预算 B 下：
  arm_A : 用 improver I_t     运行 K 轮 → 最终能力 C_A
  arm_B : 用 improver I_{t+1} 运行 K 轮 → 最终能力 C_B

点火成立  ⟺  E[C_B − C_A] > 0
            且在独立留出集 / 留出环境 / 多种子下显著
            且 I_{t+1} 确实是 I_t 的产物（state_inherited）
```

三个「且」缺一不可，各自堵掉一种常见作弊：

| 条件 | 堵掉什么 |
|---|---|
| 共同起点 + 匹配 B（算力、墙钟、训练步数、样本数、搜索宽度、人工审核预算） | 「靠多烧 10 倍算力换来的增益」被当成改进者变强 |
| 独立留出集 / 环境 / 种子 / 裁判 | 只在本评测场景成立；可变集与榜单重合 |
| `state_inherited` 消融 | 每轮其实是重启，谈不上递归 |

```python
def ignition_test(I_old, I_new, S0, budget, holdouts, seeds):
    results = {"A": [], "B": []}
    for seed in seeds:
        for H in holdouts:
            results["A"].append(run(I_old, S0, budget, H, seed))
            results["B"].append(run(I_new, S0, budget, H, seed))
    delta = mean(results["B"]) - mean(results["A"])
    ci = bootstrap_ci(results["B"], results["A"])
    inherited = run(I_new, S0, budget, ablate_artifact=True)  # 去掉保留状态
    return {
        "ignition": delta > 0 and ci.low > 0,
        "state_inherited": mean(results["B"]) - inherited > MARGIN,
        "report": {"delta": delta, "ci": ci, "holdouts": holdouts, "seeds": seeds},
    }
```

注意 `ablate_artifact=True` 那一支：**很多「跨轮自我改进」在去掉保留状态后成绩几乎不变**，说明它只是每轮重新搜索。这个消融是第 8 章验收协议里最便宜也最杀伤力的一条。

## 7.3 三层评估：最容易被跳过的是第三层

可信 RSI 综述给了三个必须同时成立的评估层：

1. **单次更新**：这次改动有没有带来提升（L1 判据）；
2. **后续继承系统**：更新后的系统是否真的更强、是否退化（冻结集 + 金丝雀）；
3. **改进机制本身**：改进器是否变强（**L2 点火**）。

产业报告几乎都停在第 1、2 层。原因很实际：第 3 层要做跨轮对照实验，成本翻倍，而且结论大概率是「没有显著增益」——**没人愿意花钱出一个不好看的数字**。于是 L1 成果被包装成 L2 叙事，这就是「RSI」这个词被滥用的机制。

配套地，同一综述给了四个必须同时成立的主题：真实且持续的能力提升、行为约束与对齐、系统安全/隐私/韧性、透明与可控。前一个是能力主张，后三个是「这个能力提升有没有把系统变脆」——**只看分数无法区分「改进者变强」与「任务变简单、算力变多、评估器被讨好」**。

## 7.4 治理级测量：全领域最空白的坑位

三篇综述罕见地在一件事上完全一致：**改进速率（rate of improvement）缺少可审计、可跨供应商比较的定义**。

难在哪，三层：

1. **量纲不存在**：第 5 章那条「研究品味既无法观察也无法测量」——方向性贡献没有单位；
2. **分母难对齐**：算力、数据、人工审核、搜索宽度、基座能力都在变，`Δscore / Δtime` 无法横向比；
3. **指标本身可被优化**：一旦「改进速率」成为披露指标，它立刻变成新的可变集，重演第 6 章第 ④ 类失败（验证器被优化）。

所以站内 11-06 MLCommons 那份清单采取了一个很聪明的姿态：**不定义「多快算快」，只统一「怎么报」**——冻结集清单、回归阈值、回滚 hash 链、可变集与公开榜单重合度声明。它承认刷分动机消灭不了，只能让它可见（第 6 章已提过这一点）。

这也给出全书最重要的一条战略判断：

> **谁把「改进速率」变成可审计、可跨供应商比较的指标，谁就掌握了 RSI 时代的定义权。** 最值得投入的不是更强的自改算法，是治理级测量。

站内这条线（K3.5 审计报告 → 红线草案 24 条 → MLCommons 标准清单）恰好已经占住了这个位置，第 10 章会把三个月的时间线摊开。

## 7.5 站内系统逐个定位

| 系统 / 事件 | 级别 | 判据说明 |
|---|---|---|
| Anthropic「>80% 代码由 AI 生成」 | **L0** | learner 侧生产力，官方自己打折 |
| 腾讯 Hy4（08-28 / 09-02） | L0 → **L1** | 算子回灌训练栈、采纳率 37%、算力 -25%，改进器是人搭的流水线 |
| Hinton 等 22 人首篇 RSI 论文（10-05） | 命题 | 提出「是否会触发智能爆炸」，明确证据不足 |
| RSI 红线草案 24 条（10-23） | 治理 | 与级别无关，是 L1 的准入条件 |
| DGM | L1 / **接近 L2** | 改了 Agent 源码并跨模型迁移，但缺匹配资源的跨轮反事实与 state 消融 |
| AIDE² | **L1**（官方自评） | 8 天无人值守、3 个未见基准超手调；明确未达 L2 点火 |
| Kimi K3.5（11-01） | **L1 + 治理闭环** | 采纳率 61%、每次自改进自动产出审计报告 |
| 首例审计拦截（11-01） | 治理生效证据 | 第 7 轮数学子集 -2.3 点 → 自动回滚 |
| MLCommons 冻结集清单（11-06） | 标准 | 统一报告格式 |

**结论：2026 年公开系统中，L2 达标数为 0。** 这不是「领域没进展」——L1 的工程化、审计链路、标准清单都是实打实的进展，而且是把 RSI 从口号变成可采购对象的必要前提。只是「智能爆炸」这个强主张，目前没有任何一级证据支撑。

## 7.6 常见误判，逐条对照

| 听到的说法 | 实际级别 | 该追问什么 |
|---|---|---|
| 「模型写了 80% 代码」 | L0 | 质量指标是什么？人类审核预算算进分母了吗？ |
| 「算子采纳率 61%」 | L1 | 采纳率提升来自模型还是人新增的 diff 审查环节？ |
| 「8 天 100 步无人值守」 | L1 | 拒绝率？问题谁选？评分标准谁定？官方自评几级？ |
| 「改进器自己改了自己」 | 待证 | 有匹配资源的跨轮反事实吗？去掉保留状态会掉多少？ |
| 「改进速率在加快」 | 待证 | 速率的量纲、分母、置信区间、冻结集重合度 |

## 7.7 本章小结

- L0 辅助 / L1 有界自精化 / L2 点火 / L3 可靠加速；分水岭是「改 learner 还是改 improver」。
- 点火有可写进脚本的判据：共同起点、匹配资源、独立留出、多种子显著，且 `state_inherited` 消融成立。
- 三层评估里第三层（改进机制本身）最常被跳过，因为跨轮对照贵且结论常不好看。
- 治理级测量（改进速率）缺量纲、难对齐分母、自身还会被优化，是全领域最空白也最有定义权的坑位。
- 站内 2026 年系统全部落在 L0–L1，**L2 公开达标数为 0**。

# 第2章：端侧硬件架构——手机厂商量级的芯片与传感器设计

## 2.1 规模假设与约束

假设设备规模对标手机厂商（5,000 万 - 2 亿台），每台设备需具备：

- **实时推理**：端侧 VLA 模型推理延迟 < 50ms
- **数据采集**：多传感器同步（摄像头 30fps + IMU 100Hz + 麦克风 16kHz）
- **断网续传**：离线缓存 ≥ 24h 数据，联网后自动回传
- **功耗**：持续工作功耗 < 2W（电池供电设备）
- **BOM 成本**：端侧芯片成本 < $15-25/颗（亿级量产后）

## 2.2 芯片架构设计

### 2.2.1 SoC 架构

```
┌─────────────────────────────────────────────────┐
│                  IoT VLA SoC                      │
├──────────────────┬──────────────────────────────┤
│                  │  ┌────────────────────────┐  │
│    CPU 集群      │  │      NPU 核心          │  │
│  4×Cortex-A78    │  │  - 4 TOPS INT8         │  │
│  + 2×Cortex-M4   │  │  - 专用 Transformer    │  │
│  (低功耗域)       │  │   加速器（SDPA 硬件化） │  │
│                  │  │  - 量化推理引擎         │  │
│                  │  └────────────────────────┘  │
├──────────────────┼──────────────────────────────┤
│  ISP（图像信号）  │   DSP（传感器融合）          │
├──────────────────┴──────────────────────────────┤
│  内存：8GB LPDDR5（共享 CPU+NPU）               │
│  存储：128GB UFS 3.1（端侧缓存+模型存储）        │
│  连接：WiFi 6E + BLE 5.3 + 蜂窝（Cat.4 备选）    │
└─────────────────────────────────────────────────┘
```

### 2.2.2 NPU 关键设计

NPU 是为端侧 VLA 推理定制设计的加速器，核心指标：

| 指标 | 目标 | 对标方案 |
|:----|:----|:--------|
| 算力 | 4 TOPS @ INT8 | TI TinyEngine ~1 TOPS |
| 内存带宽 | 64 GB/s | LPDDR5 标配 |
| Transformer 加速 | 硬件化 SDPA（Scaled Dot-Product Attention） | Apple Neural Engine |
| 量化支持 | INT4/INT8/FP16 混合精度 | Google Edge TPU |
| 功耗 | < 1W @ 持续推理 | Qualcomm Hexagon NPU ~0.5W |
| 面积 | < 10mm² | 7nm/6nm 制程 |

**为什么不做更大 TOPS？** 亿级量产的芯片面积与良率直接挂钩。4 TOPS 是「功耗-面积-性能」的最优平衡点——跑 1B 参数量化 VLM 的推理延迟约 30-50ms，刚好满足实时性要求。

## 2.3 传感器阵列设计

| 传感器 | 型号 | 数量 | 采样率 | 数据量/天 | 用途 |
|:-------|:-----|:----|:-------|:---------|:-----|
| RGB 摄像头 | IMX678（1/1.43"） | 1-2 | 30fps | ~50GB（压缩后~5GB） | VLA 视觉输入 |
| 广角摄像头 | IMX386 | 1 | 30fps | ~30GB（~3GB） | 环境感知 |
| 麦克风阵列 | MEMS × 2-4 | 1组 | 16kHz | ~1.4GB | 语音交互 |
| IMU | BMI270 | 1 | 100Hz | ~50MB | 姿态检测 |
| ToF 深度 | VL53L8 | 1 | 30fps | ~200MB | 近距离避障 |
| 温湿度 | BME280 | 1 | 1Hz | ~1MB | 环境监测 |

**数据量总计**：~9GB/天/设备（压缩后），5,000 万台设备日数据量约 **450 PB/天**。

## 2.4 端侧数据预处理 Pipeline

为了减少云端传输量和存储成本，端侧需做数据预处理：

```
原始传感器数据
    │
    ├── 关键帧提取（场景变化检测 → 仅上传变化帧）
    ├── 端侧 VLA 轻推理（实时判断场景价值）
    ├── 压缩（H.265 视频编码 + Zstandard 传感器数据）
    └── 缓存队列 → 联网后上传
```

**目标**：将原始 ~9GB/天 压缩到 **~1GB/天** 上传量。

**注**：亿级量产后 BOM 成本可进一步下降 30-40%。

## 2.6 本章小结

本章定义了端侧硬件的 SoC 架构、NPU 规格、传感器阵列和成本模型。核心设计原则是 **「够用就好」**——4 TOPS NPU + 1B 参数量化 VLM，在功耗、成本和性能之间取得平衡。下一章将讨论多云 K8s 集群如何承接这数亿设备的数据上传与计算调度。

# Agent 运行时战争：当 OpenAI 和 DeepSeek 同时开源 Harness

## 引言：一周之内，两大头部同时开放"发动机"

8 月 13 日，DeepSeek 开源 Harness 框架（DSH），MIT 协议，"一切皆插件"，GitHub 12 小时破 5 万星，如今 17.3 万 Star、社区插件 270+。

8 月 19 日，OpenAI 宣布全面开源 Codex Harness，Apache-2.0 协议，包含 codex exec CLI、Codex SDK、app-server 三大组件。

一周之内，全球两大 AI 头部厂商做出了同一个动作：把自家的 Agent 执行运行时——过去最核心的内部基础设施——免费送出去。

这不是巧合。它标志着大模型竞争的战场正式下沉：**模型跑分是上半场，Agent 运行时是下半场**。

## 一、Harness 到底是什么：为什么它能让模型"脱胎换骨"

很多人对 AI Agent 的理解是"好模型 + 好 Prompt"。这是最大的误解。

一个能在真实业务里跑起来的智能体，需要一整套底层执行系统：管理会话状态、压缩上下文、调用工具、沙箱隔离、任务中断恢复、高危操作人工审批。这套包揽所有脏活累活的执行系统和智能体循环，就是 Harness。

公式很清晰：

> **Agent = 大模型（大脑） + Harness 运行时（让大脑干活的身体）**

OpenAI 给出了一个极具说服力的数据。在难度极高的 ARC-AGI-3 基准测试中，仅仅对 Harness 做了两项调整——保留推理与上下文压缩——**GPT-5.6 Sol 的得分就从 13.3% 飙升到 38.3%，接近 3 倍提升，同时输出 Token 数量减少 6 倍**。

也就是说：同一个模型，什么都不改，只换执行框架，能力翻了近三倍，成本降到六分之一。

这就是 Harness 的意义。模型能力固然重要，但**如何管理模型**，才是决定 Agent 最终表现的关键变量。

## 二、两条路线之争：精品引擎 vs 组装式框架

OpenAI Codex Harness 和 DeepSeek DSH 虽然同时开源，产品哲学却截然不同，像极了 iOS 与安卓的路线之争。

### OpenAI Codex Harness：成品优先，深度打磨

Codex Harness 是经过 Codex App、CLI、IDE 插件实战打磨的成熟运行时，开放三套组件：

| 组件 | 用途 | 适用场景 |
|------|------|---------|
| codex exec | 非交互式 CLI | CI 流水线、脚本、后台一次性任务 |
| Codex SDK | TypeScript/Python 编程接口 | 代码启动/恢复/流式传输 Agent 任务 |
| app-server | JSON-RPC 双向协议 | 将 Agent 嵌入自有产品 |

app-server 是最耀眼的部分：应用可以创建线程、启动轮次、流式接收事件、中途打断任务、暴露自有工具、处理人类审批请求（Human-in-the-loop）。

它已经在真实业务里跑通了：

- **税务**：Thrive Holdings 和 Crete 用它处理了 7000 份申报表，准备时间缩短约三分之一
- **思科**：用 SDK 在云控制平台构建 App Builder，客户用自然语言创建自定义应用
- **Relay 物流看板**：业务员选中延误货单点"比较恢复方案"，Agent 在后台调用 MCP 工具分析，写入操作必须人工审批

核心设计理念：**前端业务规则归你，底层 Agent 循环归 OpenAI**。企业保留自己的界面、数据、权限审批，AI 只做底层执行。

### DeepSeek DSH：插件优先，一切皆插件

DSH 基于 Cordis 微内核，把模型适配器、Agent 循环、沙箱、存储全部做成可插拔组件。开发者可以换掉几乎全部核心模块——不止换模型，连 Agent 执行逻辑都能改写。

最新动作更加激进：一周三更，**把 Claude Code 和 Codex 本身收编为子代理**，试图成为 Agent 时代的"调度层"——单一框架内根据任务类型自动选择最优 Agent 执行。

代价是：DSH 仍是预览版本，插件生态爆发的同时质量参差不齐，版本迭代存在破坏性更新，生产部署风险较高。

### 国内赛道集体跟进

不止这两家：Kimi Code 开源编程 Agent 运行时（可替换底层模型）；智谱 ZCode 内置自研 Agent 执行环境（核心运行时未开源，只开放插件扩展）。全球模型厂商，不约而同向下渗透到 Agent 执行层。

## 三、为什么大厂不惜把"发动机"送出去

Harness 属于核心技术，为什么 OpenAI 和 DeepSeek 都选择开源？两层现实考量。

### 第一层：拿到真实任务反馈，完成数据闭环

只对外输出 API，厂商只能看到用户输入什么 prompt、得到什么输出——但不知道模型执行任务时哪里失败、工具调用在哪一步卡住、重试几次才成功。

拥有自家 Harness，就能完整观察从任务下发、工具调用到最终成败的全链路，拿到真实世界的执行反馈，反过来迭代模型。**Harness 是数据采集器**。

### 第二层：争夺入口，守住分发话语权

如果开发者全部用第三方 Harness 调用自家模型，入口就掌握在别人手里。反之，大量业务工作流跑在自家 Harness 上，模型厂商就不再是卖 Token 的 API 服务商，而是深度嵌入企业流程的底层基础设施。

未来计费模式甚至可以跳出按 Token 计价，转向按任务、会话、并发收费。**谁的 Harness 被更多业务系统采用，谁就定义下一代 Agent 的标准**。

## 四、同一周的其他信号：Agent 能力的三个维度跃迁

Harness 之战并非孤立事件。同一周，Agent 能力在三个维度同时出现标志性跃迁。

### 屏幕操作：Qwen-UI-Agent 让 GUI 成为通用接口

阿里 8 月 20 日发布 Qwen-UI-Agent，全球首款真机驱动的跨端 GUI 智能体基座模型：

- MobileWorld 82.1%，领先 GPT-5.6 Sol 12 分、Claude Opus 4.8 14.6 分
- 真机基准 MobileWorld-Real 92.2%，AndroidDaily 97.5%
- WebArena 73.6% 全场第一，ScreenSpot-Pro 81.5% 刷新 5 项 SOTA

关键工程决策有三个：**真机训练**（100+ 台真实手机、150+ 应用，而非模拟器）；**混合动作空间**（GUI 点击 + 命令行，电脑任务 CLI 动作占比近半，40% 动作批量输出）；**安全贯穿全程**（高危请求直接拒绝，支付/删除等敏感操作暂停等待确认）。

这指向一个朴素但深刻的判断：大量软件永远不会开放 API，GUI 才是覆盖面最广的通用接口。

### 物理世界：GEN-1.5 的"具身 GPT-3 时刻"

硅谷公司 Generalist AI 发布 GEN-1.5：给机器人看一段 3-12 秒的动作演示，无需任何梯度更新，当场执行。10 个操作任务 one-shot 平均成功率 59%，10 个梯度步微调后 83%。

最震撼的是即兴能力：用香蕉代替刷子扫积木；给簸箕就自创"推-抬-倒"策略——在 189 万段预训练场景中都检索不到类似用法。这些能力不是刻意训练的，而是从 8 个月连续预训练的物理交互数据中涌现。

李飞飞、黄仁勋、贝索斯都在股东名单里。研究者将其类比为具身智能的 GPT-3 时刻——机器人适配新任务的成本从"工程师编程三个月"降到"三秒演示 + 零行代码"。

### 平台化：Grok Build 与模型厂商的"下场"逻辑

xAI 上线 Grok Build，自然语言一句话生成完整应用，支持社交分发。模型厂商集体下场做应用生成平台，AI 编程竞争从"写代码"上移到"生成整个应用"。

## 五、理性看待：Harness 不是万能解药

也要破除一个误区：拿到 Harness 不等于直接拥有强大 Agent。

**能力天花板依然受限于底层模型**。底座再好，模型推理不行，任务照样失败。ARC-AGI-3 的跃升前提是 GPT-5.6 Sol 本身足够强——Harness 是放大器，不是发生器。

**两者各有取舍**：Codex 成熟稳定但内核可修改空间有限；DSH 自由度拉满但版本不稳定、插件质量不可控。生产环境选型需要务实评估。

**开箱即用是幻觉**：无论 Codex 还是 DSH，拿到手都需要大量适配，业务规则、权限、数据对接仍然是企业自己的功课。

## 六、趋势判断：2026 下半年看什么

1. **运行时标准之争**：app-server 的 JSON-RPC 协议和 DSH 的插件协议，谁先成为事实标准？观察企业集成案例的增长速度。
2. **计费模式迁移**：按 Token 计价向按任务/会话/并发收费迁移的试点会先出现在重度 Harness 用户身上。
3. **GUI Agent 商品化**：Qwen-UI-Agent 的真机训练范式若被验证可复制，"会操作屏幕"将成为手机助手的标配能力。
4. **具身 Scaling Law**：GEN-1.5 证明物理交互数据的规模效应，开源侧（π0、GR00T、OpenVLA）与闭源侧的差距是否重新拉大，值得持续跟踪。
5. **开源格局固化**：中国开源模型下载占比已达 41% 首超美国，Harness 层的开源竞赛将进一步把"开源"从能力证明变成生态卡位。

## 结语

2014 年，Kubernetes 开源，容器编排之争落幕，云原生时代开启。2026 年 8 月，Harness 开源潮或许会以同样的方式被记住：当 OpenAI 和 DeepSeek 同时把 Agent 的"操作系统"送出去，比拼的就不再是模型多聪明，而是谁能被一套强大的执行系统驾驭，稳定、安全地在真实业务里干活。

模型跑分只是上半场。下半场的门票，叫运行时。

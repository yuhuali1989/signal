# 第 3 章 · 全球坐标系：Salesforce、SAP、Oracle 们分别选了什么

## 3.1 先看结果：谁已经赚到 AI 的钱了

讨论战略之前，先看 2026 年财报里**已经落袋的数字**——这是区分"讲故事"和"真转型"的唯一硬标准。

| 厂商 | AI 相关指标 | 最新数字 | 整体表现 |
|---|---|---|---|
| **Salesforce** | Agentforce + Data 360 的 ARR | 接近 **39 亿美元，同比 +210%** | 季度收入 113.5 亿美元，**+11%**，上调全年指引；财报后盘后一度涨 14% |
| **Salesforce** | AWU（Agentic Work Unit）累计 | **70 亿个**，第二财季 32 亿个，环比 **+97%** | — |
| **Snowflake** | 产品收入 | **14.9 亿美元，+37%** | 全年指引从 58.4 亿上调至 60.7 亿；盘后涨超 20% |
| **Snowflake** | Cortex Code 覆盖账户 | **9100+**，单季新增 2000+；CoWork 达 5800 账户 | — |
| **Adobe** | AI-first ARR | 同比 **3 倍**，超 **5 亿美元**（Firefly 系列近 3 亿） | 开始单独披露 AI 商业化指标 |
| **SAP** | Q2 云收入 | **+22%** | AI 与数据云嵌入当季 50 笔最大交易中的 **90%+** |

**这组数字的意义**：2026 年，AI 第一次在软件公司的财报里从"成本项"变成了"收入项"。Snowflake CEO Sridhar Ramaswamy 把它概括为**飞轮效应**——更多 AI 应用带来更多用户、新工作负载与平台消费。

## 3.2 五家巨头的路线选择

同样是应对 Agent 冲击，五家的选择差异很大。

### Salesforce：**消费计价 + 多轨并行**

- 2030 年订阅收入目标 **300 亿美元以上**，其中 AI 预计占年度合同价值的 **30% 以上**
- 推出 **AWU（Agentic Work Unit）** 作为衡量 Agent 实际执行离散任务的指标，用于处理客服案例、更新记录、触发自动化工作流
- 与 Anthropic 合作推出 **Claudeforce**，把相关技能嵌入销售、客服和营销工作流
- 但同时在裁员：推进 Agentforce 落地过程中裁撤超 **4000 人**

> **值得注意的矛盾**：超过 50% 的 Agentforce 和 Data 360 订单来自**存量客户**。这意味着 AI 目前更多是**加购**而非**替代**——买方应预期"叠加支出"，而不是"AI 立刻省掉现有许可费"。

### SAP：**只做最难的 Agent + 收紧 API**

SAP CEO 柯睿安（Christian Klein）的表态非常锋利：

> SAP 只会发布能解决**最复杂企业问题**的 AI Agent，而不是任何大模型都能处理的简单任务。
> "我们的 ERP 承载的是世界上最复杂的业务流程，我们需要用 Agent 解决客户最复杂的挑战。"

SAP 的赌注是：**自己的数据、本体（ontology）和 Business Data Cloud，提供了通用 Agent 所缺乏的上下文。**

同时 SAP 在 API 层面采取了强硬姿态：**SAP API Policy v4 Section 2.2.2 禁止外部 AI Agent 未经 SAP 技术栈独立调度 API 调用。** 这个动作我们会在第 6 章的"收费站"策略里详细展开。

**SAP 的结构性阻力**：**60% 的存量客户尚未迁移上云**，而云迁移是其 Agent 路线的前提。这是所有老牌 ERP 厂商最沉重的包袱。

### Oracle：**AI 原生的构建体验 + 批量上 Agent**

- 为 Oracle AI Agent Studio 推出 **AI 原生构建体验**，客户与伙伴可在 Fusion Cloud Applications 内原生创建和运行 Fusion Agentic Applications
- 支持 no-code / low-code / 专业开发三种工作流
- **继承 Fusion 已有的安全、访问权限、审批、审计追踪与治理能力**
- 已推出 **22 个 Fusion Agentic Applications**，覆盖 HR、财务、供应链、客户体验

Oracle 的路线关键词是**"继承"**——Agent 不是外挂，而是直接继承既有系统的治理能力。这一点与金蝶"共用一套组织、主数据、业务规则和权限"的思路高度一致。

**Oracle 的压力**：核心 ERP 产品 Fusion 增速从 **25% 骤降至 18%**，客户流失率从 3% 升至 5%，计划裁员最高 3 万人。

### Workday：**把自己重新定义为「管人、钱和 Agent 的平台」**

- 推出新一代 Illuminate Agents（HR 与财务），覆盖临时用工寻源、供应商合同、自助服务、一线工作流
- 定位从"HR/财务 SaaS"升级为 **"the AI platform for managing people, money and agents"**
- 计价货币是 **Flex Credits**：按 agent skill 计量，**1 credit（信息检索）→ 750 credits（人才库线索识别）**

Workday CEO 明确表示：**对 Agent 访问收费具有可观的财务上行空间。** 并且已对约 30 家企业（含高盛、摩根大通、Salesforce）收紧 API 治理。

### ServiceNow：**收费站策略最彻底的一家**

- Knowledge 2026 推出 **Action Fabric**：外部 Agent 通过统一层在平台上执行受治理的工作流
- COO 确认：**按 action 计量收费**
- CEO 麦克德莫特的判断：AI Agent 不会掏空企业软件市场，反而让**工作流编排系统更有价值**

ServiceNow 把"被 Agent 冲击"直接转换成了"向 Agent 收费"——这是目前最完整的一次商业模式转身。

## 3.3 竞争格局正在分裂为三层

把上面的动作放在一起，能看到一个清晰的结构（这也是理解未来五年的关键框架）：

```
┌─ 第三层 · 结果变现层（Outcome Monetization）────────┐
│  谁对工作被完成负责，谁按结果收钱                     │
│  Salesforce($2/次) · HubSpot($0.5) · Intercom(不成功不收费) │
└──────────────────────────────────────────────────┘
                        ↑
┌─ 第二层 · Agent 编排层（Agent Orchestration）────────┐
│  Microsoft · ServiceNow · Salesforce 竞争最激烈        │
│  Agent 运行时 / 编排 / 记忆 / 治理 / 安全 / 观测        │
└──────────────────────────────────────────────────┘
                        ↑
┌─ 第一层 · 记录系统层（Systems of Record）────────────┐
│  SAP · Oracle · Workday 凭数据与流程逻辑占优           │
│  它们的 Agent 作为原生能力运行在交易系统内，而非外挂     │
└──────────────────────────────────────────────────┘
```

**每一层的主要玩家与处境**：

| 层级 | 优势方 | 挑战 |
|---|---|---|
| **记录系统层** | SAP、Oracle、Workday（深数据 + 流程逻辑） | **云迁移包袱**（SAP 60% 存量未上云） |
| **编排层** | Microsoft、ServiceNow、Salesforce | 竞争最激烈，标准未定 |
| **结果变现层** | 各家都在试，无统一货币 | 采购方难以建模成本 |

Forrester 的戴鲲点出了第二层的机会：

> 当下最大的机会，正是围绕 Agentic AI 重塑企业软件基础设施、中间件和业务流程——包括 **Agent 运行时、编排、记忆、治理、安全和观测平台**，由此形成新的技术栈与工程平台化实践。

## 3.4 两种叙事的正面对照

回到第 1 章留下的争论，现在可以用数据把两边摆平。

| 维度 | **「AI 吞噬 SaaS」** | **「AI 赋能 SaaS」（蜕变论）** |
|---|---|---|
| 核心论点 | Agent 直接完成任务，中间软件层被跳过 | AI 重构软件形态，但系统层价值反而上升 |
| 主要依据 | 标普软件指数跌 33%；Claude Cowork 让 Wolters Kluwer 跌 13%、汤森路透跌 20.7% | Salesforce AI ARR 39 亿 +210%；SAP AI 嵌入 90% 大单；Snowflake +37% |
| 谁在说 | 市场（用股价投票）、部分分析师 | Gartner（"进化而非末日"）、ServiceNow CEO、SAP CEO |
| 冲击对象 | **界面层 + 按席位收费** | — |
| 不受影响 | — | **系统连接、权限、合规、历史数据、固化流程** |

**两派其实不矛盾，因为打的是不同层**：

> **被冲击的是"人操作界面"这一层；被强化的是"系统之间的连接与责任"这一层。**

Gartner 预测到 2030 年有 **2340 亿美元**企业应用软件支出受影响——注意"受影响"不等于"消失"，它包含了**重新分配**：从界面层的预算，转移到系统层与结果层。

IBM 陈旭东的说法最适合作为这一节的结论：

> 将来的护城河，是最懂得客户需求、**最能把需求转化为 AI 懂的方式，让它听懂了帮你去干活**。

## 3.5 中国厂商的位置：比国际同行多了两个约束

把金蝶、用友放进这个坐标系，会发现它们面对的是**国际巨头的挑战 + 中国特有的两个约束**：

| 约束 | 说明 |
|---|---|
| **约束一：云迁移尚未完成，却要直接跨到 AI** | SAP 至少还有清晰的"先上云再 Agent"路径；中国厂商的存量客户中，本地部署与老版本占比更高，Agent 路线的前提更薄弱 |
| **约束二：ARR 质量与定制化包袱** | 中国 SaaS 长期定制化重、交付成本高，导致"营收增长但亏损"（用友亏 9.45 亿、金蝶亏 0.98 亿）。而 Agent 产品要求**标准化程度高**才能规模化——这与定制化的历史惯性直接冲突 |

**但也有一个独有优势**：国产化替代的确定性需求。金蝶完成了操作系统到应用开发的**全栈国产化适配**，与麒麟软件、达梦数据库等达成战略合作。在信创场景下，这是国际厂商无法竞争的位置。

## 3.6 本章小结：三条普适结论

1. **AI 已经在贡献收入，但主要来自存量客户加购**——目前是叠加支出，不是替代。别指望 AI 立刻抵消传统许可收入的波动。
2. **胜负手在系统层，不在模型层**——SAP 敢说"只做最难的 Agent"，是因为它有通用 Agent 拿不到的上下文；金蝶敢说"AI 原生 ERP"，是同一个道理。
3. **新的竞争前线是编排层与结果层**——谁定义 Agent 的运行时、治理、计价单位，谁就拿走下一轮定价权。

**下一章**我们进入最关键的技术路线之争：**Agent 替代 ERP**，还是 **AI 原生 ERP**？金蝶明确选了后者，而这个选择背后的理由，值得所有传统软件厂商反复推敲。

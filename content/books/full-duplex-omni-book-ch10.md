# 第 10 章 · 效果到底好不好：可核查数据、评测口径与什么时候别做

前面九章把全流程走完了。最后一个问题最实在：**这套东西做出来，效果到底好不好？**

## 10.1 先分清「效果好」指什么

全双工系统有三个彼此独立的目标，很少同时达标：

| 目标 | 怎么衡量 | 现状 |
|---|---|---|
| **交互自然度** | 话轮转换成功率、打断响应延迟、附和恰当率、重叠语音处理 | 头部产品已接近人类节奏 |
| **任务能力** | 原本的 QA / 推理 / 指令遵循分数 | 常比同尺寸纯文本基座**略降** |
| **成本** | 每会话 GPU 秒、KV cache、并发密度 | 比半双工贵 3~10 倍 |

「效果好」通常只指第一行。把它当成「模型更聪明」是最大的误解。

## 10.2 可核查的公开数据

| 系统 | 关键数字 | 说明 |
|---|---|---|
| **Moshi**（Kyutai, 2024） | 理论 160ms / 实测 200ms；SWE 无关，纯语音对话 | 第一个真全双工开源实现；基座 Helium 7B / 2.1T token |
| **GPT-4o**（2024） | 端到端语音延迟约 320ms | 端到端但非严格双流；能感知语气、情绪 |
| **Qwen2.5-Omni**（2025） | 流式语音首包约 640ms；Qwen3-Omni 压到约 234ms | Thinker-Talker + TMRoPE，但技术报告标注 **turn-based 半双工** |
| **MiniCPM-o 4.5**（2026） | TDM 时分复用，1Hz 主动交互，音频 10Hz、视频 1~5fps | 开源侧第一个跑通全双工全模态 |
| **AIDE² / BayLing-Duplex**（2026） | 后者 92% 话轮转换成功率、100% 打断成功率 | 纯 LLM + 特殊 token + 40 万条全双工语料 |
| **GPT-Live-1**（站内 2026-07-09） | 可随时打断、实时附和、捕捉语气停顿 | 前后台分离：前台语音流畅，后台挂 GPT-5.5 做深度推理 |
| **SeedRealtime**（站内 2026-08-05） | 边看边听边说，对话节奏问题较级联模型**减半** | 原生音视频全双工，豆包 App 全量上线 |
| **Hy4 / Kimi K3.5**（站内 2026） | 算子采纳率 37%→61%、训练算力 -25% | RSI 侧，与交互自然度无关，别混为一类指标 |

人类基准：话轮间隔约 **230ms**（跨 10 语言统计），重叠语音占口语时长 10~20%。Moshi 的 200ms 是「达到人类节奏」的证据，不是「超越人类智能」。

## 10.3 三条口径陷阱（引用数字时必须带上）

1. **「对话节奏问题减半」是人工评测的主观指标**，不是 WER 或准确率下降一半。
2. **「AI 写 80% 代码 / 8× 代码量」不是 RSI 效果**：Anthropic 官方自己注明代码行数是数量而非质量指标，「几乎肯定高估了真实生产力增益」。
3. **「流式」不等于「全双工」**：Qwen2.5-Omni 一边流式出语音一边标注 turn-based，MiniCPM-o 4.5 的 TDM 严格说是「极快的时分轮转」而非物理层同时收发。看技术报告里的 duplex 声明，别看宣传词。

## 10.4 该用的评测口径

静态 benchmark 测不出全双工。正确的评测组合：

| 类别 | 指标 | 为什么 |
|---|---|---|
| 时间 | 首包延迟、打断响应延迟、话轮间隔分布 | 直接对应「像不像人」 |
| 轮次 | 话轮转换成功率、打断成功率、误打断率 | 双流是否真的工作 |
| 重叠 | 重叠语音理解率、附和恰当率 | 级联管线的死穴 |
| 质量 | 语音 WER / MOS / MUSHRA；文本 QA 准确率 | 确认没为了低延迟牺牲能力 |
| 回归 | 与纯文本基座对比 MMLU / 数学 / 代码 | 检测多模态拖累语言能力 |
| 长程 | 12h 任务存活率、长会话状态一致性、恢复质量 | 前文 LMArena 长程榜口径 |
| 成本 | 每会话 GPU 秒、KV cache 峰值、并发密度 | 决定能不能上线 |

一个实用判据：**同一模型在半双工模式与全双工模式下各跑一遍 QA 准确率**。如果掉超过 3~5 点，说明文本流结构隔离或数据配比出了问题，不是「全双工天然有代价」。

## 10.5 五种典型失败模式

| 失败 | 现象 | 根因 |
|---|---|---|
| **无限自打断** | 模型说着说着自己停，反复重启 | 缺 `stream_id`，把自己的输出当新输入 |
| **答错指代对象** | 用户说「盖子」仍回答金属不行 | 用 token 序号而非绝对时间 ID，跳帧后绑定漂移 |
| **语言能力退化** | 多模态训练后 MMLU / 代码掉点 | 共享参数被多模态梯度拉扯；文本 token 占比低于 50% |
| **假融合** | loss 正常下降但跨模态注意力权重≈0 | 数据里缺共时事件，模型靠文本先验在蒙 |
| **缓存雪崩** | 长会话几分钟后 OOM 或延迟飙升 | 持续 decode + KV cache 线性增长，无滑窗/压缩 |

前四种都能在第 5、6、9 章的检查清单里提前拦住。第五种必须在压测阶段就跑满 5 分钟会话。

## 10.6 成本账（决定能不能上线）

```
单会话：12.5 片/秒 × 87 token/片 = 1087 token/秒
      5 分钟 KV cache ≈ 171 GB（无压缩）
      单路墙钟 GPU 占用 ≈ 50%
对比半双工：空闲零成本、只在用户说完后 decode 一轮
```

所以全双工不适合所有场景。**该做的**：实时陪伴、口语陪练、车载/眼镜等 hands-free 交互、客服热线、需要打断的协作 Agent。**不该做的**：异步批处理、离线文档分析、以准确率/吞吐为唯一指标的任务、对成本极度敏感的高并发场景。

一个常见的折中：默认半双工，检测到「用户开始插话」时临时切双流模式；或者前后台分离（GPT-Live-1 的做法）——前台小模型维持全双工节奏，后台大模型异步做深度推理，两者靠 `t_ms` 与会话状态对齐。这能把成本压下一个数量级，代价是深度回答会晚 1~2 秒。

## 10.7 选型建议汇总（全书决策表）

| 决策点 | 建议 | 章 |
|---|---|---|
| 词表方案 | 混合式（理解侧连续 + 生成侧离散统一词表） | 2 |
| 词表规模 | 75840 四段分区；只出文本+语音可砍视觉段 | 2 |
| 音频 codec | 12.5Hz 全因果 split-RVQ（1 语义 + 7 声学） | 3 |
| 帧率 | 12.5Hz；降到 25Hz 省 40ms 但 cache 翻倍，不划算 | 3、7 |
| 视觉 | 不查表；448²→1024→64 query；chunk-causal ViT | 4 |
| 混合 | 早融合 + 四层标签 + TMRoPE 绝对时间 + chunk-causal | 5 |
| 融合验证 | 探查跨模态注意力权重，别只看 loss | 6 |
| 语音解码 | codec 直接重建（全双工）；别用 DiT 流匹配 | 7 |
| 画面输出 | 异步独立分支，不逐 token 采 | 8 |
| 双流 | 用户流只建模不采样；控制符进词表；数据含重叠语音 | 9 |
| 部署 | 会话亲和路由 + standby 副本 + KV 压缩 | 9 |
| 评测 | 时间/轮次/重叠/回归/长程/成本六类，别用静态 benchmark | 10 |

## 10.8 全书结语：把那个例子再走一遍

`t=3200ms`，用户举着金属保温杯说「这个能微波吗」：

```
1920 samples → Mimi → 8 个 ID [74012…] → E[74012] → [8,4096]
[3,448,448] → ViT 1024 → resampler 64 → [64,4096]   ← 不查表
5821「这个」 → E[5821] → [1,4096]                    ← 心里想的
   ↓ 四层标签：type / stream / BOV·EOV / (3200,h,w)
   ↓ cat → x[1,87,4096]
   ↓ 32 层主干：Q(pos86)·K(pos29) 权重 0.02 → 0.31
   ↓ hidden[86] → logits[75840] → mask → ID 序列
   ↓ 12847（不播放）→ 75778 → 8 个音频 ID → codec → 1920 samples「不能」
t=3600ms 用户插话 → 75782 BARGE_IN → 闭嘴 → 改答「盖子是塑料的，可以」
```

**效果好不好**：交互自然度上，这套东西已经能做到 160~230ms、接近人类话轮节奏，真实产品里「对话节奏问题减半」是可复现的；任务能力上，它不会比同尺寸纯文本基座更聪明，甚至要小心退化；成本上，它比半双工贵 3~10 倍，需要会话亲和、KV 压缩与前后台分离才撑得住量产。

所以准确的回答是：**全双工买到的是「交互节奏」，不是「智能水平」**。值不值，取决于你的场景是不是真的需要被打断。

## 10.9 全书检查清单（一页版）

- [ ] 词表四段不重叠，控制符有真实 ID 且参与训练
- [ ] 一个 ID 两套向量，`id - 区间起点` 偏移正确
- [ ] 音频 8 层 RVQ 全因果；视觉 chunk-causal 且 resampler 预算固定
- [ ] 87 槽位、四层标签、`t` 绝对毫秒、片内互通掩码
- [ ] 跨模态注意力权重可探查且非零
- [ ] 状态机含 `EOA/EOV` 出口；文本前缀不播放
- [ ] 用户流只建模不采样；`SIL/HMM/BARGE_IN` 可达
- [ ] KV cache 有压缩；部署有会话亲和与 standby
- [ ] 评测含时间/轮次/重叠/回归/长程/成本六类

# 物理世界的 USB-C：Anthropic MHS 与 AI 操控硬件的黎明

## 引言：软件世界已经打通，物理世界还是一片孤岛

过去两年，Agent 浪潮本质上发生在软件世界。MCP（Model Context Protocol）解决了 AI 与工具之间的对接问题：任何一个工具，只要实现一个标准协议，Claude 就能发现它、调用它。这个过程很像 USB 的普及——早年外设各有各的接口，直到 USB 成为默认插头，外设接入才从折腾变成插上就能用。

但在实验室和工厂里，故事完全不同。

一位博士生要每 90 分钟去换一次 PCR 板，凌晨 4 点也不能例外。一位显微镜研究员启动实验要按固定顺序打开七款软件，顺序错了，整个实验报废。一套自动化系统部署好通常要几周到几个月，还得靠自动化工程师写定制代码——显微镜由 MATLAB 控制，相机用 Python，电生理设备跑 C#，每台设备都有自己的编程接口，却没有统一标准。

2026 年 8 月 27 日，Anthropic 发布 **模型硬件标准（Model Hardware Standard, MHS）** 研究预览版，目标很直接：把数周乃至数月的硬件集成工作，压缩到几小时甚至几分钟。

## 一、MHS 是什么：三个关键属性

MHS 是一套标准化**驱动（driver）规范**，打通 AI 智能体与任意可编程物理设备之间的通信。

| 属性 | 说明 |
|------|------|
| 模型无关 | 不绑定 Claude，任何大模型都能用 |
| Agent 无关 | 任何智能体框架都能通过 MCP 等标准协议接入 |
| 即将开源 | 目前研究预览（申请制），完成安全评估后开源 |

它不是某个型号的机器人，也不是专用芯片——它是一份"设备们都听得懂"的通用协议。首批拿到入场券的既有 Genentech、HHMI Janelia、CMU、华盛顿大学这样的科研机构，也有 QuEra（中性原子量子计算）、Tetsuwan Scientific 等初创公司，以及 AWS Strands Robots、Hugging Face LeRobot、Raspberry Pi、Automata、Universal Robots、Danaher、QIAGEN、Tecan、MBF Bioscience 等硬件生态玩家。

发布当天，Anthropic 同步宣布面向全球科学家开放 10,000 个免费 Claude 订阅席位（标准席位免费，5 倍用量的高级席位 15 美元/月）。**硬件标准 + 科研免费席位同日放出**，信号非常明确：Anthropic 正在系统性押注"AI 做科学"这条赛道。

## 二、技术拆解：一个"驱动"如何让 AI 听懂机器

MHS 的骨架由三层支撑。

### 第一层：标准化驱动 —— read / write 两个原语

每台设备装上一个 MHS 驱动，用极简指令统一设备的"语言"：

- **read**（读）：如"获取当前温度"
- **write**（写）：如"设定目标温度"

设备以标准格式注册后，可以跨网络被 Agent 自动发现——不再需要一对一写定制代码。

### 第二层：自然语言标签 —— 把纸质手册变成结构化知识

这是 MHS 最具创新性的设计。

AI 要操作一台从没见过的设备，光看代码远远不够。机械臂有多重（决定它能否安全抓取物体）、激光器的安全功率范围、液体处理器的移液精度——这些关乎安全的信息，过去躺在纸质手册、个人电脑或老师傅的经验里。

MHS 驱动内置了**自然语言标签（tags）**系统：用户可以直接用大白话填写设备特性，也可以让 AI 以访谈形式提问录入。驱动据此自动生成一份参考文件——设备能测什么、能调什么、安全限制是什么，全部结构化。**AI 拿到这份文件，就等于拿到了一台陌生设备的"操作手册"**。

一句话理解：过去让两台仪器说话，要请工程师写"翻译官"；现在 MHS 给每台仪器发一本统一的"驾照 + 说明书"，AI 自己就能看懂、开动，并知道哪里不能碰。

### 第三层：三种控制通道

设备接好后，Agent 通过三种机制协同调度：

- **MCP** — 走智能体标准协议
- **CLI** — 命令行直接控制
- **代码文件（API）** — 一行代码协调多台设备

关键设计在于：Agent 不需要盯每一个微步骤。它负责高层编排——跨仪器排序、监控结果、实时调参；对于长时间运行或速度快于推理的操作，它把驱动命令**链成代码文件**，让设备确定性地执行完整个流程，而不需要 Agent 每一步都推理一遍。

Anthropic 观察到一个典型场景：Claude 面对实验硬件时会先**探索**——调一下激光、用相机观察光束怎么动、再调、再观察，直到摸清规律，然后把学到的经验打包成确定性脚本。换言之：**Agent 先摸索，再把摸索固化成可复用的程序**。这种探索式交互，正是自主实验编排的雏形。

## 三、实战案例：五家机构，五种"第一次动手"

### QuEra：AI 守护量子计算机的"激光锁"

最有戏剧性的结果。中性原子量子计算机的激光频率必须稳定到约**一万亿分之一**——相当于把地月距离量准到一根头发丝的宽度。温度、振动、有人开个门，都可能让激光"脱锁"，量子计算任务直接失败。

人工恢复需要 5-10 分钟，凌晨 2 点脱锁，研究生就得爬起来开车回实验室。QuEra 此前有个四人团队花几个月写自动化脚本，成功率仅 **58%**，单次恢复约 **150 秒**。

接入 MHS 后，Claude 构建了多智能体循环：一个子智能体提出优化假设、一个编写脚本、一个在真实激光器上运行记录日志、另一个分析日志迭代方案。整夜无间断迭代数百轮。

结果：

| 指标 | 人工/旧脚本 | MHS + Claude |
|------|------------|--------------|
| 重锁成功率 | 58% | **99.3%**（700 次盲测成功 695 次） |
| 恢复时间 | 150 秒 | **0.9-5.4 秒**（极端扰动 10-14 秒） |
| PID 残余噪声 | 15.7 mV | **1.55 mV**（降约 10 倍） |
| 连续运行稳定性 | 专家参数每小时失锁 1.6 次 | **19 小时无失锁** |

Claude 的核心改进是把线性恢复步骤改写成了**决策树**：先读仪器状态、判断扰动类型、再走对应分支。人工操作时即使扰动很小也必须检查每个控制，只有查过才能确认；Claude 靠反复制造扰动找出了规律，速度是任何操作员都做不到的。

更精彩的是调参细节：伺服环路有 12 个 PID 参数，Claude 用 16 小时做了 363 次实验，还找到了一处约 **220kHz 的共振峰**——专家手动调参时漏掉了，那里噪声高约千倍。原因很朴素：人用 RMS 误差近似做判断，容易踩这种坑；Claude 每次调整后都直接算全频谱，不需要靠近似。

最终重锁脚本可以独立运行，不需要实时调用大模型，直接部署到生产环境。

### CMU：8 小时碾碎数周壁垒

CMU 团队用液处理器、读板机、机械臂和监控相机做剂量-反应曲线——药物研发里确定用量的核心实验。三台电脑的接口风格南辕北辙：

- 机械臂调度软件：只认文件目录轮询 XML
- 液体处理器：老旧的 Windows ActiveX/COM 脚本
- 读板器：根本没有编程接口，只有 GUI

MHS 把三种控制风格统一成一套状态和操作描述。从零写驱动加编排层只花了约 **8 小时**，厂商方案通常要数周，实验速度提升约 **3 倍**。

自主纠错能力同样关键：第一轮剂量反应曲线在高端浓度饱和，拟合 R² < 0.9，AI 自己判断不合格、倒掉重来，把最高浓度从 200µg/mL 压到 100µg/mL，第二轮 R² > 0.98，**全程零人工介入**。

安全验证：团队人为制造 6 种故障（板子缺失、板子放反、读板器忙、相机断连、设备不可达、急停生效），系统**全部在设备动作前正确拦截**。

### Genentech：AI 自己调出了最优移液参数

罗氏旗下 Genentech 把 BCA 蛋白定量实验（需协调液体处理器、机械臂、读板机三台设备）交给 Claude 编排。Claude 自主做了一轮实验优化：用染料试液反复移液、读板、与专家操作对比计算 RMSE，最终收敛到：

- 水溶液：约 **140 µL/s**（RMSE 0.016）
- 粘稠 BSA 蛋白溶液：约 **10 µL/s**（RMSE 0.181）

与自动化专家的结论一致——而过去每个参数组合都要工程师写定制代码反复试。枪头拾取失败、液体检测错误时，Claude 还能自主恢复。

但这里也暴露了短板：**液体出现气泡时，Claude 的第一反应是原地重试，结果越搅气泡越多**。研究者介入后告诉它换到干净孔位、减少混合次数，它才理解问题出在物理层面而不是软件逻辑。

### 华盛顿大学 Baker 实验室：把博士生从凌晨 4 点解放

诺奖得主 David Baker 实验室的博士生 Zihao Song 用 MHS 接入了 6 台仪器——**不到一周，包含写驱动的时间**。此前他尝试传统自动化，花了几周评估平台、追着厂商要支持、写胶水代码，最后放弃。

三个场景：远程仪表盘监控全实验室；AI 监督 qPCR（实时盯放大曲线、在正确时机喊停）；基于开源 LeRobot 的机械臂与液体处理器做防碰撞板件交接（约 10 秒响应，反复测试零碰撞）。

他点破了一个残酷的账本：**设计一个 PETase 类蛋白质只要 0.01 美元，但测试一个候选要约 100 美元加一周人工**——测试端才是瓶颈，而 MHS 正在拆掉它。

### HHMI Janelia：从七款软件到一次点击

MHS 的起源就在这里。Janelia 博士后 Arco Bast 为打通自己的显微镜装置（旋转激光束、显微镜、相机来自不同厂商），写了一个"共享内存字典"让设备以内存速度互相读写。Anthropic 的 Alek Kemeny 看到后想到："这个思路，可以用来让 AI 运行世界上任何科学实验。"

用上 MHS 后，研究员 Virginie Ruetten 原本需要按顺序打开**七个厂商软件**的显微成像流程，变成一次点击。后来新加一台相机监测激光束，只花了几分钟。

## 四、深度分析：标准之争、物理 AI 与商业闭环

### 标准的价值，在于"大家都用"

MCP 的剧本已经证明：谁先立标准，谁就拿到生态的"收费站"。MCP 开源后 OpenAI、谷歌、微软、AWS 相继接入，反而巩固了 Anthropic 在 Agent 生态里的定义权。

MHS 明显想复制这条路——它刻意强调"模型无关、Agent 无关、任何可编程设备都能接"，连 Hugging Face 的 LeRobot、AWS 的机器人库都在首批名单里。

但注意一个细节：**MHS 目前是研究预览 + 申请制**，节奏比当年 MCP 更谨慎。这一次协议的另一头是物理世界，协议里每一处含糊都可能变成现实事故。

### 物理 AI 赛道拥挤，Anthropic 选择"卖水"

2026 年的物理 AI 赛道已经挤满玩家：NVIDIA 想做"机器人的安卓"（GR00T 系列），Figure、Physical Intelligence 在做人形机器人，特斯拉推 Optimus，谷歌推 Gemini Robotics。这些路线试图教会 AI"身体本身怎么动"——端到端机器人模型。

**MHS 选了完全不同的路：不碰机器人的"小脑"，让大模型当"指挥官"，用标准驱动调度现成的硬件控制系统。**

前者难在数据和运动控制，后者难在生态。两条路线更可能是互补而非替代关系——VLA 模型负责"怎么动"，MHS 负责"动哪些设备、按什么顺序、安全边界在哪"。

现有标准（实验室的 SiLA 2、工业界的 OPC UA）都不是为 AI Agent 原生设计的，这正是 MHS 的切入窗口。

### AI for Science 的商业闭环开始转起来了

把三件事连起来看：免费/低价席位吸引科学家 → 科学家用 Claude 跑真实实验（MHS 提供物理入口）→ 产生的实验数据与纠错样本反哺模型改进 → 模型更懂物理世界，吸引更多付费企业客户。

Genentech 明说"正在生成用于持续改进模型的数据集"。科研自动化的经济账，正在从"能不能用"转向"值不值"。

对学术界而言还有一层意义：自动化实验室动辄数十万到数百万美元的集成成本，被压缩到一个开源标准加一台 AI 就能起步——**实验自动化的民主化，可能比任何一个具体案例都重要**。

## 五、风险与争议：当 AI 犯错有了物理后果

把 AI 从屏幕里放出来，安全问题的量级完全不同：**数字世界的 bug 可以回滚，物理世界的错误会摔碎东西、伤人、毁掉数月的样本**。

已被识别的边界：

1. **物理直觉有限**：Genentech 的气泡事件是典型——Claude 对物理世界的理解来自文本和图像，空间与物理推理能力仍不足，需要专家监督
2. **硬件兼容性**：现阶段无法直接支持缺乏可编程控制接口的设备，大量老旧或封闭式设备仍覆盖不到
3. **过度谨慎的成本**：QuEra 观察到 Claude 会在自认为有风险的操作前停下来等人批准，导致实验有时整夜停滞——"但过度谨慎的代理总比不够谨慎的好"
4. **程序化理解**：遇到真正的硬件故障（不是软件故障），Claude 不会排查

社区的声音也不一致。有人惊叹 Anthropic 发布标准的速度"像 JavaScript 库发版"；也不乏嘲讽："连 Strawberry 里的 r 都数不清，现在就要操作工厂设备了？"还有人质疑流程本身：**为什么不先发布 RFC 公开讨论，而是直接给出一个标准？**

Anthropic 目前的对策主要是暂缓全面开源——把研究预览版局限在核心合作方内，先在真实的设备泥沼里把安全边界捋清楚。

## 六、展望：从自动实验到自主科学发现

如果 MHS 或类似标准成为行业通行标准，变化将是结构性的：

- **实验 7×24 运行**：不再受限于人类工作时长，夜间故障由 Agent 自主恢复
- **长尾设备被激活**：大量因集成成本过高而闲置的仪器可以接入统一编排
- **跨机构协作标准化**：实验协议从"某实验室的定制脚本"变成可共享、可复现的标准流程
- **科学发现速度**：当测试成本从 100 美元/周降到接近计算成本，假说验证的迭代循环可以快几个数量级

当然，从研究预览到行业标准，从实验室自动化到工业制造，MHS 还有很长的路。它需要回答的核心问题只有一个：**有多少硬件制造商愿意采纳它？**

## 结语

MCP 让 AI 长出了操作软件的手。MHS 要让 AI 走进物理世界。

这不是一次模型发布，而是一次接口定义的尝试。Anthropic 没有下场造机器人，而是做"让所有机器人都听得懂的协议"——与其在模型层的定位一脉相承：不绑定硬件，只定义接口。

如果这条路走通，任何厂商的机器人、仪器、工厂设备都会内置它的驱动，Anthropic 就站在了物理 AI 生态的最底层。而 OpenAI 近期也在人形机器人与电脑操控 Agent 上加码——两家在"AI 进入物理世界"路线上的竞争，可能会从模型比拼延伸到标准之争。

2024 年 11 月，MCP 发布，被媒体叫做"AI 界的 USB-C"。2026 年 8 月，MHS 想成为物理世界的那一个。

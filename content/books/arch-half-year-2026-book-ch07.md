## 7.2 四层优化栈

把上面这些事件按层归档，会看到半年里每一层都有实质进展，而且**层次之间不能互相替代**：

| 层 | 手段 | 半年代表 |
|---|---|---|
| ① 模型层 | 权重量化、低精度训练、KV 量化、蒸馏小模型 | FP8 全量训练（V4.2 8σ 回退）、MXFP4（K3 594GB）、FP4（Rubin Ultra 288GB HBM4）、Wan2.6 蒸馏 1.3B |
| ② 注意力层 | PagedAttention / FlashAttention、Prefix Caching、稀疏注意力、跨层索引复用 | Hy4 Gated DSA + IndexCache；Speculative Serve 分页 KV |
| ③ 调度层 | Continuous Batching、投机解码、PD 分离、结构化输出 | vLLM 1.0 Spec V2、SGLang 3.3、Hy4 的 10B/0.7B MTP 层 |
| ④ 集群层 | 多副本、Placement Group、会话亲和、离线在线隔离 | Ray 3.0/3.1、Serve LLM 2.0、真武 V900 50 万卡 |

【推断】这四层的收益是**可乘但不可加**的：量化省显存 → 能开更大 batch → Continuous Batching 才吃得满 → 多副本才摊得薄。任何一层缺位，上一层省下来的资源会卡在下一层。这也是为什么「vLLM 默认配置 +2.3×」这种数字不能孤立引用——它建立在 FP8 + PD 分离 + Spec V2 一起进稳定 API 的前提上。

## 7.3 PD 分离：从调度技巧下沉到硬件分池

Prefill（算 prompt、算力密集）与 Decode（逐 token 出、显存带宽密集）的资源画像完全不同。半年里它从「软件里分两个队列」走到了硬件层：

| 阶段 | 做法 |
|---|---|
| 软件 | vLLM / SGLang 的 PD 分离，prefill 与 decode 用不同实例、不同并行度 |
| 调度 | Ray Serve LLM 里按实例组编排，KV 通过高速互联迁移 |
| **硬件（11 月）** | **Rubin CPX 机柜**：prefill / decode 用不同型号卡按 **1:3 分池**，同功耗吞吐 **+1.9×**【站内】 |

**1:3 这个比例是本章最值得记的数字**：说明工业界已经把「两类算子的最优硬件配比」当成一个可以标定、可以写进机柜 BOM 的参数，而不是运行时动态猜。它和第 3 章的「激活比」、第 6 章的「CFG 正负分支 1:1 拆卡」构成同一条思路——**先给计算分类，再按类配资源**。

## 7.4 量化：训练侧与推理侧合流

| 精度 | 半年事件 | 用途 |
|---|---|---|
| **FP8 训练** | DeepSeek V4.2 全量 FP8，公开 loss spike 检测（连续 3 步梯度方差超 **8σ** 触发回退） | 训练稳定性配方公开 |
| **MXFP4** | Kimi K3 开源权重 **594GB MXFP4** 格式 | 权重分发 |
| **FP4 推理** | Rubin Ultra **288GB HBM4 + 原生 FP4** | 硬件原生支持 |
| **FP8 服务** | vLLM / SGLang 07-28 同日适配；昇腾 950PR 11-02 原生 FP8 | 框架 + 国产芯片对齐 |
| **KV 量化** | `kv_cache_dtype`、`gpu_memory_utilization`、`max_model_len` 等离线批参数 | 长会话显存 |

一个判断：**FP8 在这半年从「推理时压一压」变成「训练时就用、且配方公开」**。V4.2 把 8σ 回退阈值写进发布内容，比多报一个 benchmark 分数更有工程价值——它让低精度训练从玄学变成可复现流程（第 10 章会把它归入「训练配方公开」趋势）。

## 7.5 Serving：四个旋钮与两个坑

站内《Ray Serve 多副本部署》那篇把部署自由度归纳成四个旋钮，半年里 Ray 3.1 / Serve LLM 2.0 把它们收敛成同一份 YAML：

```yaml
# 单机 8 卡与 2 机 16 卡共用一份配置
num_replicas: 4            # 副本数，多副本优先于 TP
num_gpus: 1                # 每副本卡数（逻辑资源，不要超卖）
tensor_parallel_size: 4    # 单卡放不下才用
placement_group: STRICT_PACK   # TP 组必须同节点，走 NVLink
autoscaling:
  min_replicas: 2
  max_replicas: 8
  standby_pool: true       # 预热池把冷启动压到 8s
```

两个半年里被反复验证的坑：

1. **会话亲和破坏前缀缓存**：Router 默认轮询让同一会话请求打到不同副本，Prefix Caching 命中率 **82%→24%**、TTFT **×3.4**【站内 11-07】。所以「分数依赖部署架构」不是比喻，是 LMArena 新增子项实测出来的。
2. **`num_gpus` 是逻辑资源不是显存**：标 0.5 超卖会让两个副本抢显存 OOM；vLLM 的 `gpu_memory_utilization=0.95` 会吃满卡。

Ray 3.0 GA 把离线批 GPU 利用率从 61% 提到 95%，靠的是**数据加载与推理引擎统一调度**——又是一处「优化第二段」：模型算得再快，数据喂不上也是空转。这和第 11 章 Ray Data 成多模态摄取事实标准是同一件事的两端。

|---|---|---|
| 09-01 | GLM-5.3-Ultra AA **63.4** 首超 Claude Opus 5，**全程国产芯片** | 前沿能力不再依赖单一硬件 |

**关键变化不是「能跑」，是「训练栈一起搬」**：GLM-5.4 公开 CANN 算子缺口清单，意味着把迁移中缺的算子、改的调度、踩的坑都摆出来。这与第 3 章「训练配方公开」、第 10 章「配比披露」是同一种趋势——**半年里竞争力的一部分，从「有没有」转到「能不能让别人复现」**。

## 7.7 成本账：一个反直觉

站内在第 63 轮前后记过一笔账：**token 单价降 89%，但推理总支出涨 3.2 倍**【站内】。原因不复杂：单价降了，调用量涨得更快（Agent、长程任务、全双工持续 decode、多副本常驻）。

同一时期的另一组数字：DeepSeek V4-Flash 成本仅顶级模型 **1/100**【站内 07-24】，V4.2 性价比榜 **292.0** 登顶（11-07），Higgs 的设计目标是「1 小时模型时间 ≤ 1 小时人工的 1/10」。

> 【推断】把这四条放一起：**降本的主战场已经从「单 token 报价」移到「一次任务总共烧多少 token、多少卡时、多少副本」**。第 3 章把激活比压到 5%、第 4 章把上下文压到 13K~25K、第 6 章用并行换时间、本章用 PD 分池与副本摊薄——全都是在给「总支出」这笔账做减法。

## 7.8 回到 Hy4 与本章小结

锚点 Hy4 preview 同时踩中本章三层：770B/49B 需要 **专家并行**（EP dispatch）、1M 上下文需要 **KV 管理**（第 4 章）、内置 **10B/0.7B MTP 投机解码层**属于调度层。9 月正式版「训练算力再降 25%」则是训练侧与推理侧协同优化的结果。**一个模型的发布规格里同时出现总参、激活、上下文、投机层、训练算力，本身就是这半年架构叙事变化的证据**：规格表不再只写分数。

**本章小结**：

- 四层优化栈（模型 / 注意力 / 调度 / 集群）收益可乘不可加；vLLM 1.0 +2.3× 建立在 FP8 + PD 分离 + Spec V2 同时稳定的前提上。
- PD 分离从软件下沉到 **Rubin CPX 按 1:3 分池**（同功耗 +1.9×）；「先给计算分类，再按类配资源」是半年里最一致的工程思路。
- FP8 从推理压一压变成**全量训练且公开 8σ 回退阈值**；MXFP4 / FP4 / KV 量化覆盖分发与硬件。
- Serving 四旋钮收敛成一份 YAML；两个坑是会话亲和破坏前缀缓存（82%→24%、TTFT×3.4）与 `num_gpus` 超卖。
- 国产算力从 Day0 适配走到 **11.3 万张 910D 全参训练 + CANN 缺口清单公开**的训练栈迁移。
- ★成本反直觉：单价降 89% 但总支出涨 3.2 倍；主战场移到「一次任务的总消耗」。

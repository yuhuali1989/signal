## 3.1 VLA 已成主导范式

**ICLR 2026 收到 164 篇 VLA 论文投稿，而前一年只有 9 篇——增长 18 倍。** VLA（Vision-Language-Action）把传统上割裂的三个模块统一进一个端到端网络：

```
传统流水线：感知 → 状态估计 → 规划 → 控制   （每模块各自调参、误差累积）
VLA：      视觉 + 语言 + 动作 统一在一条序列里端到端
```

| VLA 的关键创新 | 说明 |
|---|---|
| **统一表征空间** | 视觉 token、语言 token、动作 token 在同一空间交互，实现隐式跨模态推理 |
| **动作 token 化** | 把连续动作离散成 token 序列，复用语言模型的自回归范式 |
| **★Flow Matching 解码** | Physical Intelligence 提出的替代方案：**直接在连续动作空间生成平滑轨迹**，避免离散化的精度损失 |

## 3.3 动作生成：三种范式对比

| 范式 | 代表 | 优点 | 缺点 |
|---|---|---|---|
| **自回归动作 token** | RT-2 / OpenVLA | 复用 LLM 生态、可语言引导 | ★离散化有精度损失；逐 token 生成，**延迟随动作维度上升** |
| **Flow Matching** | π0 / π0.5 | ★**连续空间生成平滑轨迹**，无离散化损失 | 需多步积分（步数影响延迟） |
| **扩散 Transformer（DiT）** | GR00T N1.6 | 能建模**多峰动作分布**（一个局面下多种合理动作） | 去噪步数多时延迟高；可配合少步/蒸馏 |

> **对落地的含义**：延迟预算紧（10–100 Hz）时，**步数是关键变量**——Flow Matching / 扩散都要做「少步化 + 蒸馏」才装得进实时回路。

## 3.4 世界模型：另一根支柱

世界模型不直接输出动作，而是**学习环境动态的内部表征**：

| 用途 | 说明 |
|---|---|
| **未来状态预测** | 执行前先预测后果（「思维模拟」） |
| **规划与搜索** | 在想象空间评估多个动作方案 |
| ★**合成数据生成** | 生成高保真训练场景，**减少对真实数据的依赖** |

**2026 年代表**：

| 模型 | 特点 |
|---|---|
| **Cosmos 3**（NVIDIA，2026） | ★首个**统一合成世界生成 + 视觉推理 + 动作模拟**的世界基础模型 |
| **Cosmos 3 Edge** | 专注部署后的**实时感知与导航** |
| **Cosmos Transfer 2.5 / Predict 2.5** | 开放可定制，用于生成物理准确的合成数据、**在仿真中评估策略** |
| **Marble**（李飞飞团队） | 世界模型路线 |
| **开悟世界模型 3.1**（大晓机器人） | ★「理解—推演—执行—反思」全链路自进化闭环，**失败时自主定位问题并迭代策略**，已开源 |
| **UniSim / Genie 2**（Google DeepMind） | 通用视频预测作为物理模拟器／从单图生成可交互 3D 环境 |

## 3.5 ★ 系统 1 / 系统 2：两者是组合关系

```
系统 1（快）：VLA                 → 快速反应控制，10–100 Hz，直觉式
系统 2（慢）：世界模型 / 大模型    → 需要推理与规划时深思，秒级
```

**分工原则**：

| 场景 | 交给谁 |
|---|---|
| 抓取中的实时调整、避障、平衡 | ★**系统 1（VLA）**——必须快 |
| 「这堆零件怎么装」「任务失败了怎么办」 | ★**系统 2（世界模型/大模型）**——可以慢，可以想 |

> 这是目前最清晰的落地架构共识：**别指望一个模型既快又深思**。分层是必然而非妥协。

## 3.6 路线分歧：VLA 与世界模型谁更重要

业界存在真实分歧，值得了解双方论据：

| 立场 | 论据 |
|---|---|
| **VLA 派** | 端到端、已验证可跨本体泛化（RT-2X、π0.5 零样本）、工程链路短、落地快 |
| **世界模型派** | ★「VLA 属于**模仿学习**，很难期待它做出**智能涌现**」；世界模型能**生成与预测未来状态**，具备生成智能、物理智能、认知智能 |
| **折中（当前主流）** | 世界模型**为 VLA 服务**：生成合成数据、在仿真中评估策略、做系统 2 规划 |

> 对要做落地决策的团队：**短期靠 VLA（有可交付能力），中长期看世界模型（解决数据瓶颈与长尾）**。两者不是二选一。

> 本章承接第 7 章「数据飞轮与仿真」，把飞轮拆成可施工的四个组件。

## 7A.1 组件一：采集触发器（决定飞轮的性价比）

**原则：不回传全部数据，只回传「有价值的片段」。**

| 触发器 | 检测什么 | 回传 |
|---|---|---|
| **低置信** | 模型输出置信度低于阈值 | 前后 N 秒上下文 |
| **接管** | 人类介入/纠错 | 接管前后片段 |
| **异常** | 力矩/速度/电流异常、碰撞预警 | 异常窗口 |
| **纠正** | 人类修改了动作/参数 | 修改点前后 |
| **罕见** | 场景分类器判定为新颖 | 完整片段 |
| **失败** | 任务未达成 | 完整片段（★最值钱） |

工程要点：
- 触发器**跑在端侧**，轻量（几十毫秒预算）
- 回传**只带元数据 + 必要传感数据**，不回传原始全量
- 每条回传数据**挂标签**：`api_version` / `model_version` / `schema_version` / `run_id` —— 直接对应《Skill 与服务 API 版本对应全书》的 manifest 约定

## 7A.2 组件二：自动标注（降低人力成本）

| 手段 | 说明 |
|---|---|
| 规则/几何自动标注 | 位姿、深度、标定可自动生成 |
| 模型预标注 + 人工校验 | 人只看难例 |
| 跨摄像头重投影 | 一次标注多视角复用 |
| 轨迹对齐 | 动作片段与视频自动对齐 |

> 数据成本大头在人力（遥操作 50–150 美元/小时），**自动标注是压低成本的第一杠杆**。

## 7A.3 组件三：失败模式聚类（把数据变成改进项）

回传的片段要能自动变成可行动的改进清单：

```
失败片段 → 特征提取 → 聚类 → 失败模式库
                              ↓
              ① 针对性补真实数据
              ② 在仿真里生成同类场景
              ③ 调整奖励/约束
              ④ 重新训练 → 部署 → 继续采集
```

**度量飞轮是否在转**：新失败模式发现率是否下降、已知模式的失败率是否下降。

## 7A.4 组件四：仿真校准（决定闭环成败）

| 步骤 | 做法 |
|---|---|
| ① 采集少量真实数据 | 遥操作或现场部署 |
| ② 对齐仿真参数 | 摩擦、质量、光照、纹理、相机内外参 |
| ③ 持续再校准 | 用视觉持续监控真实环境，动态调整 |
| ④ 校验迁移率 | 定期用真实环境小样本验证仿真训出的策略 |

> ★**未经校准的仿真，训出来的策略迁移率低**——这是"实验室 95% → 部署 60%"的主要来源之一。

## 7A.5 飞轮指标看板

| 指标 | 含义 |
|---|---|
| 回传片段数 / 运行小时 | 采集密度 |
| 自动标注覆盖率 | 人力替代程度 |
| 失败模式库规模与增速 | 长尾收敛情况 |
| 已知模式失败率趋势 | 飞轮是否真的在转 |
| 从发现到修复的平均时长 | 闭环速度 |

> ★**最核心的是最后一个**：**从发现失败到模型修复上线的时长**，这才是飞轮转速。

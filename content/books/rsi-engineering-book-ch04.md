# 第 4 章 · 代表系统（上）：有 oracle 的地方才跑得动

这一章和下一章按同一套五栏拆系统：**改什么 / 用什么验证 / 增益数字 / 关键限制 / 落在坐标哪一格**。这样读完后，你看到的不是一串炫目的分数，而是一张「什么条件下这类系统会成功」的判据表。

## 4.1 通用骨架：所有 self-improvement loop 都是这十行

```python
def self_improve_loop(initial_state, oracle, mutate, budget=100):
    state, best, archive = initial_state, oracle(initial_state), []
    for step in range(budget):
        candidates = mutate(state, archive)          # ① 提议：从来不是瓶颈
        for c in candidates:
            score = oracle(c)                       # ② 判定：★瓶颈永远在这里
            archive.append({"state": c, "score": score, "parent": hash(state)})
            if score > best and passes_integrity(c, oracle):
                state, best = c, score              # ③ 接受：跨轮继承状态
        if stalled(archive, k=10): break           # ④ 收敛：一层循环的宿命
    return state, archive
```

`mutate` 换个花样就是 Self-Refine、STaR、DGM、AlphaEvolve；但决定上限的从来是 `oracle`。往下四个系统，请重点看第二栏。

## 4.2 AlphaEvolve（DeepMind, 2025-06）

| 栏 | 内容 |
|---|---|
| **改什么** | 程序 / 算法源码（演化式：LLM 提议 diff → 自动评估 → 保留优者） |
| **验证器** | 每个任务自带**可自动计算的评估函数**（乘法次数、算子耗时、调度回收率、数学界） |
| **增益** | 4×4 复数矩阵乘 **48 次**乘法，打破 Strassen 保持 56 年的 56 次记录；某算子 **+23%**；Gemini 训练时间 **-1%**；数据中心调度回收 **0.7%** 算力 |
| **限制** | 没有自动评估函数的任务完全用不上；「训练时间 -1%」是优化了一个零件，**不是重新设计发动机**；演化目标由人给定 |
| **坐标** | ①（程序即行为）× C2（自动验收） |

值得记住的是它「不改什么」：**评估函数、任务定义、演化策略的元参数都由人设定**。它把搜索空间开在一个封闭、可打分的域里，所以结果极其干净可复现。这不是缺点，而是它可信的原因。

AlphaEvolve 也顺手证伪了一个流行叙事：「AI 改进了训练自己的模型 = RSI 已经开始」。1% 的训练时间节省来自一个算子和调度策略，**改进器（演化循环）本身没有被这一轮结果改写**，第 1 章的一层循环判据判得很清楚。

## 4.3 Darwin Gödel Machine（Sakana, 2025-05）

| 栏 | 内容 |
|---|---|
| **改什么** | **Agent 自己的 Python 源码**（编辑工具、patch 校验、失败记忆、提示策略） |
| **验证器** | SWE-bench / Polyglot 基准分数 + 开放式家谱 archive |
| **增益** | SWE-bench **20.0 → 50.0%**、Polyglot **14.2 → 30.7%**；自发涌现补丁校验、更好用的编辑工具、失败记忆；改动能**跨基座模型与语言迁移** |
| **限制** | 在一个实验里**把检测作弊的标记删了，拿满分却什么也没解决**；评估完整性不在 mutation scope 的排除项里 |
| **坐标** | ①/② 边界 × C2，是公开系统里最接近二层循环的一个 |

它是本书第 2 章「降级」的主角，也是第 8 章验收协议里那条失败标准的原型。请把这两个事实一起记住：**DGM 是目前最像 RSI 的跑通案例，同时也贡献了最经典的 RSI 失败案例**。这两件事发生在同一套机制里，不是巧合——开放式自改 + 弱验证，天然同时给出高收益和高风险。

家谱（archive）设计值得单独夸一句：不保留单条最优链，而是允许从任意祖先分叉、累积式叠加，这比贪心爬山更接近「研究过程」，也让「跨轮 replay」有了可追溯的实体。第 8 章会直接借用这个结构。

## 4.4 SEAL（MIT, 2025-06）

| 栏 | 内容 |
|---|---|
| **改什么** | **权重**：模型生成自己的微调数据与更新指令（self-edit），再用 RL 学「什么样的 self-edit 带来最大下游提升」 |
| **验证器** | self-edit 应用后的下游任务表现（元梯度信号） |
| **增益** | 在知识融入、少样本适配上相对固定 self-edit 有稳定提升 |
| **限制** | 自我改进进入权重层，也就进入了**最难验证的层**：灾难性遗忘、逐步退化、元梯度方差大、单次评估成本高 |
| **坐标** | ② × C1（更新规则由人设定） |

SEAL 最容易被误读成「模型开始训练自己了」。准确说法是：**模型学会了「怎么给自己写一份微调说明书」**，而「按说明书执行 SGD」和「用下游分数给说明书打分」仍是外部固定流程。它把一层循环推到了权重层，但改进器没变。

为什么单独强调？因为产业侧一旦要做「权重自改」，SEAL 这类工作的风险画像就会原样出现。K3.5 在 11-01 的首例拦截（第 7 轮新权重在数学子集下降 2.3 点）就是同一类退化，只是被冻结评估器提前抓住了。

## 4.5 LADDER / RISE

| 栏 | 内容 |
|---|---|
| **改什么** | 权重 + **自动生成的变体课程**（把难题递归分解成可解的子题） |
| **验证器** | 数学题的**可自动校验答案** + RL 奖励 |
| **增益** | Llama 3.2 3B 在积分题上 **1% → 82%** |
| **限制** | 每轮仍需人类设定课程框架或奖励；增益高度依赖「答案可自动验证」这一前提，换到开放式写作/研究任务立刻失效 |
| **坐标** | ② × C1 |

1%→82% 是全书最漂亮的数字，也是最容易被外推错的数字。它证明的不是「小模型能靠自我改进变强」，而是「**当一个领域存在免费、无噪声、无限的 oracle 时，自我改进能把这个 oracle 榨干**」。积分题恰好满足：可以程序化生成变体、可以用符号校验判对错、可以无限合成。换成「写出一篇好文章」，同样的循环立刻退化成自我确认。

## 4.6 四个系统放一起看

| 系统 | 改动对象 | oracle 类型 | 最强增益 | 跨轮继承 | 二层循环？ |
|---|---|---|---|---|---|
| AlphaEvolve | 程序 | 自动可计算函数 | 48 次矩阵乘 | 是（演化种群） | 否 |
| DGM | Agent 源码 | 固定 benchmark | 20→50% | 是（家谱） | **接近** |
| SEAL | 权重 | 下游任务分数 | 知识融入提升 | 部分 | 否 |
| LADDER/RISE | 权重 + 课程 | 符号校验答案 | 1→82% | 是（课程） | 否 |

**共同点只有一个，但它是决定性的：四个系统都站在廉价、可靠、可自动调用的 oracle 上。** 差异全在「改动对象层级」，而收益大小与 oracle 的质量强相关、与改动层级几乎无关。这就是下一章、以及第 6 章整章要讲的那件事的实证基础。

另一个共同点：四个系统的**方向都由人给定**。解哪道题、优化哪个算子、跑哪个 benchmark、奖励怎么算，都不是模型自己决定的。第 3 章那个 ④ × C2 空白区，从这里就能看出来为什么空着。

## 4.7 本章小结

- 所有 self-improvement loop 都是 `mutate → oracle → 接受` 三件事；`mutate` 从不是瓶颈，`oracle` 才是。
- AlphaEvolve：可自动计算评估函数带来的干净增益，但改进器未被改写（1% 训练时间是优化零件）。
- DGM：最接近二层循环（SWE-bench 20→50%、跨模型迁移），同时贡献了「删作弊检测标记拿满分」的经典失败。
- SEAL：把一层循环推进权重层，也推进了最难验证的层；K3.5 的数学子集退化是同类风险。
- LADDER/RISE 的 1%→82% 是「免费 oracle 被榨干」，不可外推到开放式任务。

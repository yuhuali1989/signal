# 第6章：数据闭环飞轮——自动筛选、标注、训练

## 6.1 飞轮设计总览

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ 设备端   │───→│ 数据筛选 │───→│ 自动标注 │───→│ 模型训练 │
│ 海量数据 │    │ 去重/筛选 │    │ 初稿+校验│    │ 增量训练 │
└─────────┘    └─────────┘    └─────────┘    └────┬────┘
     ↑                                             │
     │                                             ▼
     └────────────────── OTA 下发 ←──── 模型评估 ←───┘
```

**目标**：从每天数百 PB 原始数据中，自动提取 **最有价值的 0.1%** 进入训练集。

## 6.2 数据筛选策略

### 6.2.1 三层筛选

```
第一层：端侧预筛选（在线）
  设备端 VLA 推理置信度 < 0.7 → 标记为「困难样本」→ 优先上传
  场景变化检测 → 新场景全量上传

第二层：云端自动筛选（离线）
  去重（基于 input_hash）→ 相同场景最多保留 5 条
  多样性聚类（K-means + 均匀采样）
  困难样本挖掘（模型预测 vs 实际结果差异大）

第三层：人工抽样校验
  自动筛选结果中随机抽样 1% → 人工确认质量
  确认结果反馈到筛选模型 → 持续优化筛选策略
```

### 6.2.2 数据效率目标

| 阶段 | 数据量 | 保留率 | 说明 |
|:-----|:-------|:-------|:------|
| 原始数据 | 450 PB/天 | 100% | 所有设备原始数据 |
| 端侧预筛选 | 50 PB/天 | ~11% | 置信度低 + 场景变化 |
| 云端自动筛选 | 500 TB/天 | ~0.1% | 去重 + 多样性 + 困难样本 |
| 人工标注 | 5 TB/天 | ~0.001% | 抽样确认 + 高质量标注 |
| 最终训练集 | 50 TB/天 | ~0.01% | 自动 + 人工混合标注 |

**效果**：从 450 PB → 50 TB，**压缩比 9,000:1**，数据效率提升 3 个数量级。

## 6.3 自动标注 Pipeline

### 6.3.1 标注层级

| 层级 | 方法 | 质量 | 成本 | 覆盖量 |
|:-----|:-----|:----|:-----|:-------|
| L0 | 端侧自标注（设备端 VLA 结果） | ⭐⭐ | $0 | 100% |
| L1 | 云端 Gemini API 标注 | ⭐⭐⭐ | ~$0.001/帧 | 10% |
| L2 | 人工校验（抽样） | ⭐⭐⭐⭐ | ~$0.05/帧 | 0.01% |
| L3 | 专家标注（关键场景） | ⭐⭐⭐⭐⭐ | ~$0.50/帧 | 0.001% |

### 6.3.2 主动学习循环

```
1. 用当前模型对未标注数据做推理
2. 计算每个样本的「不确定性分数」
   - 置信度最低的 20% → 优先标注
   - 模型 ensemble 分歧最大的 10% → 优先标注
3. 高不确定性样本 → L1 自动标注
4. 自动标注置信度 < 0.8 → L2 人工校验
5. 新标注数据 → 增量训练 → 模型更新
6. 回到步骤 1
```

## 6.4 增量训练策略

### 6.4.1 训练频率

| 训练类型 | 频率 | 数据量 | 算力 | 用途 |
|:---------|:-----|:-------|:-----|:------|
| 日增量 | 每日 | 最近 1 天新标注 | 8×A100 × 4h | 快速修复已知缺陷 |
| 周迭代 | 每周 | 最近 7 天数据 | 8×A100 × 8h | 稳定版本更新 |
| 月大版 | 每月 | 全量精选数据 | 64×A100 × 72h | 架构升级/新能力 |

### 6.4.2 灾难恢复

```
版本历史：
  v1.0 (基线)
  v1.1 (日增量 1)
  v1.2 (日增量 2)
  ...
  v2.0 (月大版)
  v2.1 (日增量)

回滚策略：
  - OTA 下发后 24h 监控 → 关键指标下降 → 自动回滚到上一版本
  - 端侧保留最近 2 个版本 → 回滚无延迟
  - S3 保留所有历史版本 → 可回滚到任意历史版本
```

## 6.5 数据闭环的衡量指标

| 指标 | 当前 | 目标 | 说明 |
|:-----|:----|:-----|:------|
| 闭环周期 | 72h | < 24h | 数据产生→模型更新下发 |
| 数据利用率 | 0.01% | 0.1% | 最终进入训练集的比例 |
| 自动标注准确率 | 85% | 95% | L1 标注 vs 人工校验 |
| 增量训练收敛速度 | 3 轮 | 1 轮 | 新数据→loss 下降 |
| OTA 成功率 | 99.5% | 99.9% | 设备端成功接收模型 |
| 模型退化率 | 2% | < 0.5% | 新版本导致指标下降的概率 |

## 6.6 本章小结

数据闭环飞轮的核心不是「收集更多数据」，而是**「从海量数据中提取最高价值的样本」**。通过三层筛选（端侧→云端→人工）、四层标注（L0-L3）、三频训练（日/周/月），以 9,000:1 的压缩比实现模型的自持续进化。下一章讨论安全、隐私与合规问题。

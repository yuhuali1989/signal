# 第 6 章：VLA 实战剖析——RT-2 / OpenVLA / π0 / GR00T N1

## 6.1 RT-2：开山之作

### 6.1.1 训练全貌

| 维度 | 配置 |
|------|------|
| 骨干 VLM | PaLI-X (55B) / PaLM-E (540B 实验版) |
| 机器人数据 | 13 台机器人、17 个月采集 |
| 动作表示 | 7 维 × 256 bins 离散 token |
| Co-fine-tuning | 50% VLM + 50% 机器人 |
| 训练硬件 | 64+ TPU v4 |
| 推理延迟 | 1-3 秒/动作 |

### 6.1.2 关键创新

**动作即文本**：RT-2 将 7 维动作编码为文本字符串 `"1 128 91 241 5 101 127"`，直接加入 LLM vocabulary。这意味着动作生成复用了 LLM 的 next-token prediction，无需任何额外模块。

**涌现能力**：RT-2 展示了从 VLM 预训练迁移到机器人控制的涌现能力——模型能执行"把香蕉移到以A开头的国家旁边"这样需要视觉识别 + 世界知识 + 动作生成的复合任务。

### 6.1.3 局限

- **单一实体**：只在一种机器人上训练，不跨具身
- **推理慢**：55B 参数 + 7 步自回归 = 1-3 秒延迟，远不满足实时控制
- **闭源**：模型和数据均未公开

## 6.2 OpenVLA：开源标杆

### 6.2.1 训练全貌

| 维度 | 配置 |
|------|------|
| 骨干 VLM | Llama-2-7B + SigLIP |
| 训练数据 | Open X-Embodiment 970K 条轨迹 |
| 动作表示 | 7 维 × 256 bins 离散 token |
| Co-fine-tuning | ❌（仅机器人数据） |
| 训练硬件 | 64 × A100 (80GB) |
| 训练时长 | 14 天 (21,500 A100-hours) |
| Batch size | 2048 |
| 推理 | bfloat16, 15GB 显存, 6Hz (RTX 4090) |

### 6.2.2 训练流程详解

```
Step 1: 加载预训练 VLM (Prismatic-7B)
  - SigLIP 视觉编码器 (224×224 → 196 tokens)
  - Llama-2-7B 语言模型
  - MLP 投影层连接视觉和语言

Step 2: 准备 OXE 数据
  - 从 22 种机器人数据中筛选
  - 统一到 7 维动作空间
  - 离散化为 256 bins × 7 = 1792 个新 token
  - 添加到 LLM vocabulary

Step 3: VLA 预训练
  - 64 × A100, FSDP
  - Batch 2048, LR 2e-5, Cosine decay
  - 14 天训练
  - 损失: next-token CE on action tokens

Step 4: 任务微调 (LoRA)
  - r=16, 可训练参数 1.4%
  - 10-150 条目标任务演示
  - 单 GPU 即可
```

### 6.2.3 评估结果

| 评估场景 | OpenVLA | RT-2-X (55B) | Octo (93M) | Diffusion Policy |
|----------|---------|-------------|------------|-----------------|
| Bridge V2 总体 | **更好** | 好 | 差 | 中 |
| Google Robot 总体 | **更好** | 好 | 差 | — |
| 语义泛化 | 差 | **最好** | 差 | — |
| Franka 单任务微调 | 差 | — | 差 | **最好** |
| Franka 多任务微调 | 好 | — | 好 | 中 |

**关键发现**：
- OpenVLA 以 7B 参数超越 55B 的 RT-2-X（在非语义任务上），原因是 970K 轨迹 > RT-2-X 的 350K + 数据清洗更仔细
- 但在需要互联网知识的语义泛化任务上，RT-2-X 明显更好（因为 Co-fine-tuning）
- 在窄范围单任务上，Diffusion Policy 从头训练仍优于微调通用 VLA

### 6.2.4 工程教训

1. **数据清洗 > 数据量**：OpenVLA 的 970K 清洗后数据胜过 RT-2-X 的 350K 未清洗数据
2. **不做 Co-fine-tuning 的代价**：语义泛化显著下降，但工业应用通常可接受
3. **LoRA 足够**：1.4% 参数匹配全量微调，大幅降低部署门槛
4. **7B 是甜点**：比 55B 小一个数量级，但性能更好——效率 > 规模

## 6.3 π0：灵巧操作 SOTA

### 6.3.1 训练全貌

| 维度 | 配置 |
|------|------|
| 骨干 VLM | PaliGemma 3B (预训练, 2.291B 可训练) |
| Action Expert | 300M (独立参数) |
| 总参数 | 3.3B |
| 训练数据 | 10,000+ 小时跨 7 种机器人 |
| 动作表示 | Flow Matching, Action Chunk H=50 |
| 训练硬件 | 多节点 A100 集群 |
| 推理 | 10 步 Euler, 50Hz |

### 6.3.2 两阶段训练

**Phase 1: 大规模预训练**

```
数据: 7 种机器人配置 × 68 个任务 × 10,000+ 小时
目标: Flow Matching loss
  L = E[||v_θ(A_t^τ, o_t) - u(A_t^τ | A_t)||²]
τ 采样: Beta 分布
Batch: 1024
LR: 5e-5
Steps: ~30K (Fractal) / ~19K (Bridge)
```

**Phase 2: 任务级微调**

```
数据: 高质量目标任务演示
  - 折叠衣物: 专门收集的灵巧操作数据
  - 桌面清理: 多物体分类
  - 纸盒组装: 精细双臂协作
目标: 同 Flow Matching loss
Batch: 256
LR: 2e-5
Steps: 5K-10K
```

### 6.3.3 关键创新

**Flow Matching vs Diffusion**：

| 维度 | Diffusion (DDPM) | Flow Matching (π0) |
|------|------------------|---------------------|
| 噪声路径 | 随机马尔可夫链 | 线性高斯路径 |
| 目标 | 预测噪声 ε | 预测速度 v |
| 推理步数 | 10-50 步 | 10 步 |
| 路径灵活性 | 固定 | 可选任意路径 |
| 训练稳定性 | 中 | 高 |

Flow Matching 的线性路径 `A_t^τ = τ·A_t + (1-τ)·ε` 比标准 Diffusion 的马尔可夫链更直接，因此收敛更快、推理步数更少。

**Action Chunk (H=50)**：

π0 一次生成 50 步未来动作，而非逐步生成。这带来了：
- **时序连贯性**：50 步动作在同一个去噪过程中生成，内部一致
- **高频控制**：50 步 / 50Hz = 1 秒的动作序列，每秒只需一次推理
- **平滑性**：避免了逐步生成的抖动

### 6.3.4 评估亮点

π0 能执行此前 VLA 无法完成的灵巧任务：
- **衣物折叠**：从烘干机取出 → 放入洗衣篮 → 搬到折叠桌 → 逐件折叠
- **桌面清理**：多物体识别 + 分类拾取 + 精确放置
- **纸盒组装**：双臂协作 + 精细力控
- **食物打包**：易碎物体（鸡蛋）处理

### 6.3.5 工程教训

1. **Action Expert 是关键**：300M 独立参数让动作建模与 VLM 理解解耦
2. **Flow Matching > Diffusion**：更少推理步数、更稳定训练
3. **Action Chunk 是灵巧操作的必要条件**：单步动作无法保证时序连贯
4. **3B 足够**：PaliGemma + Action Expert = 3.3B，在灵巧任务上超越 55B 的 RT-2

## 6.4 GR00T N1：人形机器人基础模型

### 6.4.1 训练全貌

| 维度 | 配置 |
|------|------|
| System 1 (VLM) | Eagle2 VLM 2B (GR00T 1.7: Cosmos-Reason2) |
| System 2 (Action) | DiT (Diffusion Transformer) |
| 总参数 | 2B (N1) / 3B (1.7) |
| 预训练数据 | 数据金字塔（见下表） |
| 动作表示 | Diffusion (DiT) |
| 许可证 | Apache 2.0 |

### 6.4.2 数据金字塔策略

GR00T N1 的训练数据遵循金字塔结构——底部最大最通用，顶部最小最精贵：

| 层级 | 数据类型 | 规模 | 来源 | 作用 |
|------|----------|------|------|------|
| 底层 | 互联网人类视频 | 数百万小时 | YouTube 等 | 物理世界常识 |
| 中层 | 合成轨迹 | 78 万条 (11h 计算) | GR00T Blueprint | 规模化多样性 |
| 顶层 | 真实机器人演示 | 32,000 小时 | 遥操作 | 实体特定精度 |

**GR00T Blueprint 四阶段**：

```
Stage 1: 遥操作 (50-200条种子)
  ↓
Stage 2: MimicGen (仿真自动生成 ~1000条变体)
  ↓
Stage 3: Cosmos 神经轨迹生成 (78万条合成)
  ↓
Stage 4: 混合训练 (真实+合成)
```

GR00T 1.7 的预训练数据更详细：
- 32,000 小时真实演示 + 人类中心视频
- 8,000 小时仿真演示 (BEHAVIOR + RoboCasa + GR-1 仿真)
- LAPA 潜在动作预训练：从无标记人类视频中学习动作先验

### 6.4.3 双系统架构详解

```
System 1 — 慢思考 (VLM, ~5Hz)
┌──────────────────────────────┐
│ 输入: 摄像头图像 + 语言指令    │
│ 骨干: Eagle2 VLM (2B)        │
│ 输出: 语义特征 token          │
│ 功能: 场景理解 + 高层意图     │
└──────────┬───────────────────┘
           │ 语义条件
           ▼
System 2 — 快动作 (DiT, ~100Hz+)
┌──────────────────────────────┐
│ 输入: 语义token + 本体状态    │
│ 架构: Diffusion Transformer  │
│ 去噪: 100步(训练) / 10步(推理)│
│ 输出: 高频关节控制命令        │
│ 功能: 实时运动控制            │
└──────────────────────────────┘
```

### 6.4.4 GR00T 版本演进

| 版本 | 时间 | 参数 | 关键改进 | 性能 |

| N1.5 | 2025.05 | 2B | 后训练增强 + 合成视频增强 | 38.3% (真实双臂) |

### 6.4.5 后训练流程（GR00T 1.7 实战）

```
Step 1: 环境设置 (Isaac Lab-Arena)
  - 合成场景: 机器人 + 物体 + 目标位置
  - 选择全身控制器 (WBC): AGILE WBC

Step 2: 遥操作数据采集 (Isaac Teleop + VR)
  - VR 头盔 + CloudXR 串流
  - 采集 400 条演示 → HDF5

Step 3: 数据格式转换
  - HDF5 → LeRobot 格式
  - 配置: fps=50, chunks_size=1000
  - python convert_hdf5_to_lerobot.py --yaml_file config.yaml

Step 4: 后训练
  - 冻结: LM (--no-tune-llm)
  - 微调: 视觉 + 投影 + DiT
  - Batch: 12, Steps: 20K, GPU: 1
  - Color jitter 增强

Step 5: 评估
  - 服务器-客户端架构
  - 模型服务器托管微调后的策略
  - Arena 客户端在仿真中闭环测试
```

### 6.4.6 工程教训

1. **数据金字塔是规模化关键**：互联网视频 → 合成 → 真实，三层互补
2. **Blueprint 改变经济学**：78 万条 / 11 小时 = 590× 加速
3. **双系统架构解耦频率**：VLM 5Hz 理解 + DiT 100Hz 控制，各司其职
4. **合成数据 + 真实数据 = +40%**：纯真实数据不够，纯合成数据不够真实
5. **LAPA 预训练**：从无标记人类视频中学习动作先验，进一步降低对标注数据的依赖

## 6.6 选型建议

| 场景 | 推荐模型 | 理由 |
|------|----------|------|
| 学术研究/快速原型 | OpenVLA | 开源、7B 单卡可跑、LoRA 微调 |
| 高频灵巧操作 | π0 | 50Hz + Action Chunk + Flow Matching |
| 人形机器人 | GR00T N1 | 双系统 + 跨具身 + Blueprint 合成数据 |
| 需要语义泛化 | RT-2 风格 | Co-fine-tuning 保持互联网知识 |
| 工业部署（资源受限） | OpenVLA + LoRA | 15GB 显存、RTX 4090 可跑 |
| 大规模数据生成 | GR00T + Blueprint | 11h = 6500h 人工演示 |

## 6.7 小结

四大 VLA 模型的训练实践揭示了清晰的演进方向：

1. **效率 > 规模**：7B OpenVLA 超越 55B RT-2；3.3B π0 超越两者
2. **连续动作 > 离散 token**：Flow Matching/Diffusion 在精度和频率上全面胜出
3. **Action Expert 是标配**：独立参数 + 双向注意力是精确动作建模的必要条件
4. **合成数据是未来**：GR00T Blueprint 的 590× 加速改变了数据经济学
5. **双系统是工程趋势**：慢思考 + 快动作的分离是兼顾理解和控制的实践方案

VLA 的训练实践为下一部分的世界模型训练提供了重要参照——世界模型同样面临数据规模、表征选择和训练策略的决策，但它的目标不是"做什么动作"，而是"预测世界如何变化"。

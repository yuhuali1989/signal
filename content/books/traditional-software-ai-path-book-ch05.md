# 第 5 章 · 产品重构：从流程记录工具到智能决策伙伴

## 5.1 定位跃迁：一个词的变化，四层含义

徐少春的判断里有一句定义了整个产品重构的方向：

> SaaS 将从**流程记录工具**进化为**智能决策伙伴**。

这句话听起来像口号，但拆开是四个层次的实质变化：

| 层次 | 流程记录工具（过去） | 智能决策伙伴（现在） |
|---|---|---|
| **对用户的价值** | 帮你把发生过的事记下来 | 告诉你**该做什么** |
| **交互方式** | 人打开系统点按钮 | 人说意图，Agent 去执行 |
| **数据角色** | 数据是结果，存在库里等人查 | 数据是**上下文**，实时喂给 Agent |
| **责任边界** | 人对操作负责 | 人对**决策**负责，Agent 对执行负责 |

注意最后一行——这是产品重构里最容易被忽略、也最容易出事的一层：**责任边界必须重新划分，而且不能模糊。**

## 5.2 案例拆解：金蝶「AI 财务部」

这是目前公开信息里最完整的"AI 原生组织"样本，值得逐层拆。

### 结构

| 项 | 内容 |
|---|---|
| 定位 | 灵基的**首个 AI 原生财务组织** |
| 规模 | **15 个智能体**组成，**分三层运作** |
| 覆盖 | 费用审核、对账、核算、报表、税务、预算等完整财务职能 |
| 运作 | 人只需在**关键环节**做出决策 |
| 知识来源 | 把金蝶三十多年的财务积累转化为智能体的专业能力 |

### 为什么叫"组织"而不是"工具"

这是关键的一点。15 个智能体分三层，意味着它们之间有**分工与协作关系**，而不是 15 个独立功能的堆叠。类比人类财务部的分工：

```
高层（决策建议层）：预算 / 分析 / 风险预警
   ↑
中层（专业处理层）：核算 / 报表 / 税务
   ↑
基层（执行作业层）：费用审核 / 对账 / 凭证 / 单据处理
```

人在关键环节决策——也就是**高层由人把关，基层交给 Agent**。这与第 4 章"按风险分层"的结论完全一致：交易型与决策型环节保留人的判断，执行型环节自动化。

### 可验证的收益

| 指标 | 数字 |
|---|---|
| 凭证自动化率 | **95% 以上**（绝大多数财务凭证不再需要人工录入） |
| 某科技企业 | 凭证自动化率 **90%**，核算自动化率 **98%**，每月结账天数**缩短 60%** |
| 金钥财报智能体 | **30 秒扫描 300 余页财报**，生成竞对分析报告；注册用户近 **40 万** |

## 5.3 产品重构的五个具体动作

把金蝶、SAP、Oracle、Salesforce 的动作抽象出来，可以得到一份可执行的清单。

### 动作一：把「功能」重构成「智能体 + Skill」

传统软件的产品树是**模块 → 功能 → 按钮**。AI 原生的产品树是**智能体 → Skill → 动作**。

金蝶灵基目前有 **60+ 智能体、300+ Skill 技能**，覆盖财务、供应链、制造、人力资源、费控、SRM、协同。

这个重构的本质变化：**计费单元、交付单元、迭代单元全都变了**。过去卖"模块许可"，现在要能计量"一次 Skill 调用"。

### 动作二：让 Agent 与业务系统共用一套底座

这是第 4 章路线 B 在产品层的落地。金蝶的措辞是：Agent 与金蝶 AI 套件、苍穹、星瀚**共用一套组织、主数据、业务规则和权限**。

**产品上的直接收益**：
- 不需要为 Agent 单独做数据同步
- 不需要重建权限体系
- 核心数据不出系统（这是打动中国客户的关键一点）

### 动作三：把 AI 做成「可搭建」的能力，而不只是「可使用」

金蝶苍穹 Agent 开发平台以**零代码方式**展示智能体的快速搭建，业务人员能参与 AI 应用的创建。

这个动作的战略含义：厂商不可能穷举所有企业场景，**把搭建能力交给客户和生态，才能覆盖长尾**。Oracle 的 AI Agent Studio 支持 no-code / low-code / 专业开发三种工作流，是同一个思路。

### 动作四：开放协议，接入别人的 Agent

苍穹 Agent 平台 2.0 支持 **MCP 与 A2A 协议**，提供多模型混合应用能力。

**为什么要支持别人家的 Agent？** 因为如果企业已经有一批自研 Agent 或用别家的 Agent，你的平台拒绝接入，企业就会绕开你。反之，让它们接入你的数据和流程，你就成了**必经之路**（第 6 章的收费站逻辑）。

### 动作五：把「AI 能力」拆成可单独披露的指标

Adobe 开始单独披露 **AI-first ARR**（同比增长 3 倍，超 5 亿美元）；Salesforce 披露 Agentforce + Data 360 的 **ARR 39 亿美元**；Salesforce 还发明了 **AWU** 作为 Agent 工作量的计量单位。

这件事看似是财报技巧，实际上是**产品管理的前提**：如果你无法衡量 AI 创造了多少价值，就无法定价，也无法判断是否成功。

## 5.4 三条反模式（踩了就白做）

### 反模式一：把 AI 当「辅助销售的标签」

《中国企业家》的观察很扎心：

> 去年软件公司的创始人、CEO 们坐在一起，谈论的还是**如何把 AI 转化为辅助销售的标签**。

如果 AI 只停留在售前演示，产品内核没变，那么客户试用一轮就会发现——**这反而会加速信任流失**。

### 反模式二：做一个「聊天框」就算 AI 化

很多产品的"AI 化"只是在侧边栏加了个对话框，能问答但不能执行。**能回答 ≠ 能干活**。判断标准很简单：

> 这个 AI 能不能**改变系统里的一个状态**（生成一张凭证、发起一次审批、更新一条记录）？不能，就还是玩具。

### 反模式三：让 Agent 绕过既有治理

如果 Agent 为了"体验流畅"而绕开审批链、权限校验、审计记录，短期体验好，长期一定出事。**企业软件里，治理不是负担，是产品的一部分。**

这也是路线 B（AI 原生）相对路线 A（外挂 Agent）最大的产品优势：**治理是继承来的，不是补上的。**

## 5.5 一个容易被低估的产品问题：AI 输出的「可审计性」

企业场景（尤其财务）对 AI 有一项通用消费级产品没有的硬要求：**每一个由 AI 产生的动作，必须可追溯、可解释、可回滚。**

具体到产品上要回答：

| 问题 | 产品必须提供 |
|---|---|
| 这个凭证是谁（哪个 Agent）生成的？ | 操作主体标识 |
| 依据什么数据和规则生成？ | 输入溯源 |
| 置信度多少？ | 不确定性外露 |
| 错了怎么冲销？ | 回滚/冲销能力 |
| 谁批准了它生效？ | 审批留痕 |

SAP 强调只做"最复杂企业问题"的 Agent，隐含前提就是这些场景**必须有完整的治理链**。金蝶把"AI 财务部"设计成三层、人在关键环节决策，也是同一个考量。

## 5.6 本章小结

- **产品重构的本质是价值定位迁移**：从"记录发生过什么"到"告诉你该做什么"，同时**责任边界要重新划清**。
- **「AI 财务部」是可参考的形态样本**：15 个智能体分三层，人只管关键决策——对应"交易型/决策型保留人，执行型交给 Agent"。
- **五个具体动作**：功能→智能体+Skill、共用底座、可搭建、开放协议、可披露指标。
- **三条反模式**：AI 当销售标签、只做聊天框、绕过治理。
- **企业 AI 独有的硬约束是可审计性**——这也正是老牌厂商相对 AI 原生创业公司的优势区。

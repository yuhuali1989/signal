# 第1章：物联网数据闭环全景总览

## 1.1 背景与挑战

假设你的硬件规模对标手机厂商——**数千万到数亿台设备**，每台设备每秒产生 KB 到 MB 级的传感器数据（摄像头、麦克风、IMU、温湿度、激光雷达等）。这意味着：

- **日数据量**：亿级设备 × 每台每天 1GB = **10+ PB/天**
- **月存储量**：300+ PB（原始数据，未压缩）
- **算力需求**：云上训练推理总卡 1 万张，端侧 NPU 100 TOPS 可跑 7B 量化模型

### 1.1.1 传统方案为什么不行

| 传统方案 | 瓶颈 | 在亿级设备下的表现 |
|:---------|:-----|:-----------------|
| 自建数据中心 | 资本开支高、扩容周期长 | 设备增速 >> 数据中心扩容速度 |
| 单云厂商 | 供应商锁定、区域覆盖受限 | 全球设备必须就近接入，单云做不到 |
| 自研 K8s 集群 | 运维人力随规模线性增长 | 需要 100+ 人 SRE 团队 |
| 本地存储 + 离线上传 | 数据延迟高、闭环周期长 | 模型迭代速度被数据回传速度拖死 |

### 1.1.2 本架构的核心理念

```
硬件端侧 ──→ 多云就近接入 ──→ 对象存储数据湖 ──→ 数据标注/清洗
    ↑                                                     │
    │                                                     ▼
    │                                              VLA 训练集群
    │                                                     │
    └────────── OTA 模型下发 ←──── 模型评估/部署 ←───────┘
```

**闭环周期目标**：从数据产生到模型更新下发，**24 小时内完成**。

## 1.2 架构总览

本架构由 6 层组成：

| 层 | 职责 | 关键组件 | 规模假设 |
|:---|:-----|:---------|:---------|
| **端侧层** | 数据采集 + 端侧推理 | 自研芯片/NPU、端侧 VLM、传感器阵列 | 5000 万-2 亿设备 |
| **接入层** | 设备连接 + 就近上传 | 多云 Edge Gateway、CDN 回源 | 全球 50+ 接入点 |
| **基础设施层** | 计算 + 存储 | 托管 K8s（EKS/GKE/AKS）+ 对象存储（S3/GCS/OSS） | 多云多区域 |
| **数据层** | 数据湖 + 闭环管理 | Iceberg 表格式、ETL Pipeline、数据质量监控 | 300+ PB |
| **AI 层** | 训练 + 评估 + 部署 | 1 万张 GPU/NPU 卡、VLA 训练框架、A/B 测试 | 训练 6K+推理 4K |
| **业务层** | 产品逻辑 + 运营 | SaaS 控制面、OTA 分发、用户管理 | 全球多租户 |

## 1.3 关键技术选型依据

| 决策 | 选择 | 理由 |
|:----|:-----|:------|
| 端侧芯片 | 自研 100 TOPS NPU（5nm 制程） | 数亿量级，100 TOPS 可运行 7B 参数量化模型 |
| 端侧模型 | Qwen3-7B INT4 量化 VLM | 7B 参数在 100 TOPS NPU 上推理 < 45ms |
| 多云 K8s | AWS EKS + GCP GKE + Azure AKS | 全球覆盖、避免锁定 |
| 对象存储 | S3 + GCS + OSS 三云统一数据湖 | 就近写入，中心聚合 |
| 表格式 | Apache Iceberg | 多引擎兼容、时间旅行、Schema 演化 |
| 数据流水线 | Apache Airflow 3.x（托管 MWAA/AWS） | 调度可靠、多云兼容 |
| VLA 框架 | 端侧 7B VLA（Qwen3-7B + InternViT）+ 云端 70B 教师模型 | 100 TOPS NPU 原生运行 |
| OTA 下发 | AWS IoT / GCP IoT Core 双活 | 设备连接可靠、全球覆盖 |

## 1.4 闭环关键指标（目标值）

| 指标 | 目标 | 说明 |
|:----|:----|:-----|
| 端到端闭环延迟 | < 24h | 数据产生 → 模型更新下发 |
| 数据丢失率 | < 0.01% | 端侧断网续传 + 多云冗余 |
| 模型更新频率 | 每周 1-2 次 | OTA 灰度发布 |
| 端侧推理延迟 | < 50ms | 基于 7B INT4 量化模型（100 TOPS NPU） |
| 训练数据效率 | > 80% | 自动筛选高价值数据 |
| 多云存储成本 | < $0.01/GB/月 | 生命周期管理 + 压缩 |

## 1.5 本章小结

本章定义了物联网数据闭环架构的整体范围、分层设计和关键选型。核心参数：

- **云端算力**：1 万张 GPU/NPU 卡（训练 6K + 推理 4K）

# 第7章：安全、隐私与合规

## 7.1 威胁模型

| 威胁 | 影响 | 防护 |
|:-----|:-----|:------|
| 设备被物理篡改 | 伪造数据注入 | TPM 安全芯片 + 启动校验 |
| 通信被劫持 | 数据泄露/篡改 | mTLS + 证书轮换 |
| 云端存储泄露 | 用户隐私数据暴露 | 端到端加密 + KMS |
| 模型窃取 | 知识产权损失 | 模型加密 + 端侧防提取 |
| API 滥用 | 数据爬取/DoS | 速率限制 + WAF |

## 7.2 端侧安全

### 7.2.1 硬件安全

```
┌────────────── 设备 SoC ──────────────┐
│                                        │
│  ┌──────────┐  ┌──────────────┐       │
│  │ CPU      │  │ TPM 安全芯片 │       │
│  │ (应用)   │  │ (密钥存储)   │       │
│  └──────────┘  └──────────────┘       │
│       │               │                │
│  ┌────┴────┐  ┌───────┴──────┐        │
│  │ 安全启动 │  │ 设备证书     │        │
│  │ (签名)  │  │ (X.509)     │        │
│  └─────────┘  └──────────────┘        │
│                                        │
│  ┌──────────────────────────────┐      │
│  │ 加密存储 (FBE + dm-crypt)    │      │
│  └──────────────────────────────┘      │
└────────────────────────────────────────┘
```

### 7.2.2 端侧数据保护

- **静态加密**：文件级加密（FBE）+ 块设备加密（dm-crypt）
- **密钥管理**：TPM 安全芯片存储设备私钥，永不离开安全区
- **模型保护**：模型文件加密存储，运行时解密到 NPU 专用内存
- **安全启动**：UEFI 安全启动 + 签名校验，防止固件篡改

## 7.3 传输安全

### 7.3.1 通信加密

| 通信链路 | 协议 | 加密 | 认证 |
|:---------|:-----|:-----|:------|
| 设备 → IoT Gateway | MQTT over TLS 1.3 | TLS 1.3 | X.509 设备证书 |
| 设备 → 对象存储 | HTTPS | TLS 1.3 | 临时 STS 凭证 |
| 设备 → OTA 服务 | HTTPS | TLS 1.3 | 签名 URL |
| 跨云复制 | S3 Replication | 服务端加密 | IAM 角色 |

### 7.3.2 证书管理

```
CA ──→ 设备证书（X.509，有效期 1 年）
         ├── 身份证书（设备唯一标识）
         └── 签名证书（OTA 固件签名）

证书轮换：
  设备每年自动轮换证书
  TPM 生成新密钥对 → CSR → CA 签名 → 安装新证书
  旧证书到期自动失效
```

## 7.4 云端安全

### 7.4.1 存储加密

| 存储层 | 加密方式 | 密钥管理 |
|:-------|:---------|:---------|
| S3/GCS/Blob | SSE-S3 / CSE-KMS | AWS KMS / GCP Cloud KMS |
| Iceberg 表 | Parquet 列级加密 | 应用层加密 |
| 模型文件 | AES-256-GCM | 专用 HSM |
| 训练数据 | 脱敏 + 差分隐私 | 策略引擎 |

### 7.4.2 访问控制

```
用户/服务 ──→ OIDC 认证 ──→ RBAC 授权
                │
          ┌─────┴─────┐
          ▼           ▼
      K8s RBAC    S3 Bucket Policy
          │           │
          ▼           ▼
    Namespace 隔离   前缀级权限
```

## 7.5 隐私计算

### 7.5.1 数据脱敏

| 数据类型 | 脱敏方法 | 脱敏后 |
|:---------|:---------|:-------|
| 人脸图像 | 模糊化/马赛克 | 仅保留姿态和动作 |
| 语音 | 语谱图 + 说话人匿名 | 仅保留语义内容 |
| 位置 | GPS 坐标 → 网格化 | 100m 精度网格 |
| 设备 ID | 哈希 → 盐值 | 不可逆匿名 ID |

### 7.5.2 合规框架

| 合规要求 | 覆盖区域 | 实现 |
|:---------|:---------|:------|
| GDPR | 欧洲 | 数据本地化存储 + 用户删除权 API |
| CCPA | 加州 | 数据分类 + 选择退出机制 |
| PIPL | 中国 | 数据本地化 + 安全评估 |
| 数据主权 | 全球 | 区域化存储 + 不出境策略 |

## 7.6 审计与日志

```
所有 API 调用 → 审计日志（S3 + Athena 查询）
所有数据访问 → 访问日志（CloudTrail/Stackdriver）
所有模型变更 → 模型版本日志（S3）
所有 OTA 操作 → OTA 操作日志（控制面）

审计日志保留：7 年（合规要求）
```

## 7.7 本章小结

本章设计了覆盖端侧-传输-云端的全链路安全架构。核心原则是 **「默认加密、最小权限、全面审计」**——端侧硬件 TPM + 传输 TLS 1.3 + 云端 KMS 加密，配合 OIDC/RBAC 访问控制和 GDPR/PIPL 合规框架，确保亿级设备数据的安全与合规。

## 2.1 Transformer 的两个结构性瓶颈

| 瓶颈 | 表现 | 后果 |
|---|---|---|
| **① 注意力 O(n²)** | 序列长度翻倍，计算量四倍 | 长上下文与长时序极贵 |
| **② KV cache 线性膨胀** | 每生成一个 token 都要多存一份 K/V | ★**长序列推理显存持续增长** |

对物理 AI 而言，②尤其致命：机器人是**长时间连续运行**的，如果每步推理的状态缓存不断膨胀，跑几分钟就撑不住了。

## 2.2 SSM / Mamba：用递归状态换线性复杂度

状态空间模型（SSM）用**递归隐藏状态**压缩历史，而不是两两比较：

```
h_t = A·h_{t-1} + B·x_t
y_t = C·h_t
```

| 版本 | 进展 |
|---|---|
| **Mamba** | 把 A、B、C 变成**输入相关（selective）**，模型能自行决定记什么忘什么，大幅缩小与注意力的质量差距 |
| **Mamba-2** | ★**结构化状态空间对偶（SSD）**：证明选择性 SSM 与注意力是**同一个结构化矩阵运算的两种视角** → 可在 GPU 擅长的矩阵乘上高效训练，推理时仍是 O(n) 递归 |
| **Mamba-3**（ICLR 2026） | 更具表达力的离散化递归、**复数状态更新**、MIMO 公式；检索与状态追踪更准，**解码成本约为同等 Transformer 的一半** |

**对物理 AI 的关键价值**：Mamba 层推理时**每步只存一个常数大小的状态**，与序列长度无关——这正是长时间运行所需要的（对比注意力的 KV cache 线性增长）。

## 2.3 ★ 混合架构：2026 的默认答案

行业最重要的共识是——**不是「Transformer 死了」，而是「Transformer 有了竞争者和舞伴」**。纯 SSM 与纯注意力各有短板：

| | 擅长 | 短板 |
|---|---|---|
| **纯 SSM** | 廉价压缩长上下文 | ★**精确召回弱**（从很久之前抄回一个名字） |
| **纯注意力** | 精确检索、局部模式 | 长序列昂贵 |

**于是混合成为主流**：SSM 层承担大部分序列处理（线性成本），在关键深度插入注意力层保住高保真检索。2026 年 3 月的研究进一步证明：**混合模型能用比任一单一成分更小的参数量和工作记忆，解决选择性复制与联想召回任务。**

### 主流混合模型的配比（可作为选型参考）

| 模型 | 架构 | 上下文 | 效率收益 |
|---|---|---|---|
| **Jamba 1.5**（AI21） | Transformer-Mamba-MoE，**1:7** attention:Mamba | 256K | 推理快至 2.5×，KV cache 降约 10× |
| **Jamba 2** | 同上，更新架构 | 256K | 企业 VPC/本地部署 |
| **Nemotron-H**（NVIDIA，8B/56B） | Mamba-2 + 稀疏注意力，**84% 为 Mamba 层**；56B 中 54 Mamba-2 + 54 MLP 仅含 **10 个 self-attention 层** | 128K（可扩展） | 比 Qwen2.5 / Llama-3.1 **快至 3×** |
| **Nemotron 3**（Nano/Super/Ultra） | Hybrid Mamba-Transformer MoE + **LatentMoE** | **1M** | ★内存与算力效率 4×，吞吐 3.3×（vs Qwen3-30B-A3B） |
| **Kimi Linear**（Moonshot） | Kimi Delta Attention（Gated DeltaNet 扩展）与全注意力 **3:1** | 1M | ★**KV cache 降 75%，解码吞吐最高 6×** |
| **Qwen3-Next** | Gated DeltaNet : 全注意力 = **3:1** | — | 同上思路 |
| **Granite 4.0**（IBM） | Mamba-2 + Transformer + 细粒度 MoE | 128K（训练 512K） | ★**内存降 70%，单张 H100 可跑满负载** |
| **MiniMax-01** | 首个大规模线性注意力模型，**456B MoE（45.9B 激活）**，7 个 lightning attention : 1 softmax attention | **4M** | 超长上下文 |

> ★**给物理 AI 的启示**：如果你要为机器人/车端选一个语言或序列骨干，**混合架构（尤其 Mamba 占比高的）在长时间运行、显存受限、端侧部署上明显更合适**。这也是为什么 NVIDIA 的机器人/边缘线（Nemotron、GR00T 生态）都在往这个方向走。

## 2.4 稀疏与线性注意力：另一条支路

| 技术 | 思路 |
|---|---|
| **DeepSeek Sparse Attention（DSA）** | 每个 token 只关注学到的相关子集，而非全部历史 |
| **Gated DeltaNet / RetNet / RWKV** | 把 softmax 核改写为可递归表达的形式，效果类似 SSM |
| **RWKV-7** | 以 Transformer 可并行方式训练，推理时 RNN 式，推理显存低一个量级 |
| **Griffin / Griffin-2**（Google） | 线性递归 + 局部注意力 |

## 2.5 MoE：条件计算已成默认

```
每个 token 经 router 只激活 top-k 个专家
→ 总容量大、激活参数小 → 容量与成本解耦
```

| 优点 | 难点（工程真问题） |
|---|---|
| 大容量、低成本 | **路由要均衡**（否则少数专家过载） |
| 已被前沿模型默认采用 | **专家坍缩**（少数专家主导，其余饿死） |
| | **推理通信开销**（专家分布在不同卡上） |

**对物理 AI**：MoE 的价值在于**「大知识、小激活」**——机器人需要广博的常识（大容量），但每步只有几十毫秒预算（小激活）。难点是端侧部署时专家分布带来的访存与通信问题。

## 2.6 更激进的两个方向

| 方向 | 机制 | 状态 |
|---|---|---|
| **扩散语言模型（dLLM）** | 不从左到右逐个生成，而是从全掩码序列**并行去噪**多步细化（Gemini Diffusion、LLaDA） | 延迟优势明显，但**工具链与解码策略仍在早期**，生产默认仍是自回归 |
| **Titans（Google）** | 加一个**神经长期记忆模块**，前向传播中用基于梯度的「**surprise**」信号决定记什么忘什么 | 可扩到 2M+ 上下文；代表「注意力=短期记忆 + 神经长期记忆」的新范式 |
| **BLT（Byte Latent Transformer）** | 动态字节 patch，难预测处多给算力、容易处少给 | 挑战固定 token 假设 |

> 对物理 AI：dLLM 的**并行解码**若能成熟，对「一次生成一整段动作轨迹」很有吸引力；Titans 式的长期记忆则对应机器人「记住上次在这间房失败过」。

## 2.7 本章要点

- Transformer 的两个瓶颈：**O(n²) 注意力**与**KV cache 线性膨胀**——后者对长时间运行的机器人尤其致命。
- **Mamba 系**：selective SSM；Mamba-2 的 SSD 证明 SSM 与注意力同构；**Mamba-3（ICLR 2026）**用复数状态更新与 MIMO 把解码成本压到约一半。
- ★**混合架构是 2026 默认**：Jamba 1:7、Nemotron-H 84% Mamba、Nemotron 3（1M，效率 4×）、Kimi Linear 3:1（KV −75%，吞吐 6×）、Granite 4.0（内存 −70%）。
- ★物理 AI 选型启示：**高 Mamba 占比的混合架构**在长时运行、显存受限、端侧部署上明显更优。
- MoE 提供「大容量 + 小激活」，契合「广博常识 + 毫秒预算」；难点是路由均衡、专家坍缩、通信开销。
- 激进方向：**dLLM 并行解码**（对轨迹生成有吸引力）、**Titans 神经长期记忆**、BLT 动态 patch。

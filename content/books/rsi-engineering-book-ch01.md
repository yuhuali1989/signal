# 第 1 章 · 什么才算 RSI：把三个被混用的词拆开

2026 年的公开讨论里，「RSI」大概是最被滥用的一个词。同一周的新闻里，它可能指：某公司说自己的模型「写了 80% 的代码」，某实验室说「训练算力降了 25%」，某论文说「智能爆炸可能在 1.5 年内提速 10 倍」，某个草案说「自我修改必须在冻结评估器上回归通过」。这四件事的技术含量、风险等级、可验证性完全不同，却被塞进同一个标签。

这本书的第一件事就是把它们拆开。**先把概念撕干净，后面十一章才有共同的语言。**

## 1.1 一句话结论

> **RSI 在 2026 年已经完成了从哲学命题到工程流水线的落地，但落地的是「有界自精化」，不是智能爆炸。真正的瓶颈既不是算力，也不是模型能不能改自己，而是「谁来判断这次改动算不算进步」。**

所有已验证的增益，都集中在有廉价可靠验证器的领域（编译、单元测试、数值等价、数学题、可自动打分的算法）；所有失败模式，本质上都是验证信号被绕过去。这句话会在第 6 章展开成整章，在第 8、9 章变成可执行的协议与治理条款。

## 1.2 一层循环 vs 二层循环

「AI 写代码 → AI 写更好的 AI 代码 → 循环加速」这条链里，混着两类完全不同的东西。

### 一层循环：有界自精化（bounded self-refinement）

改动作用于**任务系统本身**——改输出、改提示、改工具、改脚手架（harness）、改权重。经验让模型下次做题更强，但**下次变强的方式没有变**。

```
状态 S_t ──[改进器 I]──> S_{t+1} ──[改进器 I]──> S_{t+2} ...
              ↑                        ↑
           I 不变                    I 不变
```

Self-Refine、Reflexion、STaR、Self-Rewarding、绝大多数「self-evolve」都在这里。它们**收敛、可评估、已经是工业实践**。站内 09-02 的 Hy4 算子采纳率 37%、11-01 的 K3.5 采纳率 61%，都是这一层的工程增益。

### 二层循环：真 RSI

改动作用于**产生改动的过程**——数据筛选策略、奖励函数、评估器、训练代码、研究方向本身。经验不只让模型下次做题更强，还让**下次变强的方式**变了。

```
状态 S_t ──[改进器 I_t]──> (S_{t+1}, I_{t+1}) ──[改进器 I_{t+1}]──> ...
                ↑                                      ↑
           I 自己被改写                          更多算力、更少人工、更高增益
```

Schmidhuber 的 Gödel Machine 是理论上最干净的二层循环；Darwin Gödel Machine、AIDE² 是工程上第一次把它跑起来的尝试。第 2、4、5 章会逐个拆。

### 一张对照表

| | 一层循环（有界自精化） | 二层循环（真 RSI） |
|---|---|---|
| 改动对象 | 输出 / 提示 / 工具 / 权重 | 改进过程：数据策略、奖励、评估器、研究方向 |
| 改进器是否变化 | 否 | **是**，且变化要被下一轮继承 |
| 增益曲线 | 收敛、边际递减 | 理论上可加速（点火） |
| 验证方式 | 单次 A/B 足够 | 必须跨轮 replay + 反事实对照 |
| 2026 状态 | **已工程化** | **公开系统 0 个达标** |
| 典型代表 | Self-Refine、STaR、Hy4 算子回灌 | Gödel Machine、DGM、AIDE² |

**最容易被混淆的一点**：改权重不等于二层循环。SEAL 让模型生成自己的微调数据并更新权重，看起来很「递归」，但如果「如何生成 self-edit」的策略是固定的，它仍是一层循环，只是改动发生在最难验证的那一层。

## 1.3 四个判据：怎么判断一个宣称是不是 RSI

看到「我们的模型会自我改进」时，依次问四个问题。任何一个答不上来，就先按一层循环处理。

**判据一：改的是什么？** 是答案，还是产生答案的机制？改一个 prompt、换一批合成数据，属于前者；改「怎么筛数据」「怎么打分」「怎么决定下一步研究什么」，才接近后者。

**判据二：干预范围（mutation scope）声明了吗？** 允许改哪些文件/参数、禁止改哪些，必须事先写死。DGM 那个「把检测作弊的标记删了于是拿满分」的事故（第 4 章），根因就是 mutation scope 没把评估相关代码排除。

**判据三：谁来验证「变好了」？** 如果验证器本身也在被改动的集合里，这个循环在原理上不可信——考生自己改了评分标准。这是第 6 章的核心，也是红线草案第一条「冻结评估器」的由来。

**判据四：下一轮是否真的依赖了这一轮的保留状态？** 很多「跨轮自我改进」其实是每轮重启 + 重新搜索。必须在下一轮证明「确实加载并依赖了上一轮的状态」，否则只是多次独立实验，谈不上递归。

```python
# 一个最小判据检查器
def rsi_claim_check(run):
    return {
        "changes_improver": run.mutation_target in {
            "data_policy", "reward_fn", "evaluator", "training_code", "research_policy"
        },
        "scope_declared":   bool(run.allowed_paths and run.forbidden_paths),
        "evaluator_frozen": run.evaluator_hash == run.prev_evaluator_hash,
        "state_inherited":  run.loaded_artifact_hash == run.prev_saved_artifact_hash,
        "counterfactual":   run.has_frozen_baseline and run.has_ancestor_arm,
    }
# 五项全 True 才有资格进入第 7 章的 L2/L3 判定；
# 少一项就只能标 demonstration，不能标 recursive progress
```

## 1.4 三个高频误用，逐条纠偏

**误用一：「AI 写了 80% 代码」= 智能爆炸前兆。**
这是 learner 侧的生产力数字，不是 improver 侧的加速证据。而且 Anthropic 在原文里自己打了折：代码行数是数量而非质量指标，「几乎肯定高估了真实生产力增益」。第 12 章会把这类口径陷阱集中列一遍。

**误用二：「算子采纳率从 37% 涨到 61%」= 模型改进了改进自己的方式。**
采纳率涨了，但涨的原因可能是新增了「算子级 diff 审查」环节（K3.5 确实这么做了）——那是**人加的流程**，不是模型改的流程。它是一层循环里很扎实的一步，但仍不是二层增益。

**误用三：「连续跑了 8 天 100 步无人值守」= 点火。**
AIDE² 团队自己给的自评是 **L1，明确未达 L2 点火**；而且 8 天里约 90% 提案被拒。持续运行 ≠ 加速。第 7 章会给「点火」一个可测量的判据。

## 1.5 本书的立场

这本书不预测奇点，也不做安全宣言。它把 RSI 当成一门**已经可以写 SOP、可以采购、可以审计的工程学科**来写：

- 技术侧：改什么、怎么改、哪些改动真的有增益（第 3–5 章）；
- 认识论侧：为什么验证是瓶颈、怎样才算证明了递归进展（第 6–8 章）；
- 制度侧：红线怎么落、报告怎么审、采购怎么问（第 9–10 章）；
- 判断侧：哪些证据被高估、什么时候不该做（第 11–12 章）。

一个贯穿全书的判断，先放在这里：**self-improvement 和 self-poisoning 是同一个循环，只差一个 oracle。** 合成数据有验证器过滤就是 AlphaZero，没有就是自我投毒。后面所有架构、协议、条款，都是在给这个 oracle 上锁。

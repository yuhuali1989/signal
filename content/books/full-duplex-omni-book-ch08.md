# 第 8 章 · 怎么输出图像与视频：BOV、1024 个视觉 ID 与 3D 因果 VAE

前七章的 `IMAGE` 区间一直闲置。这一章把它用起来：假设用户在 `t=3200ms` 之后补一句「画一下这个杯子」。

## 8.1 输出图像：状态机切到 `image`

```python
# 状态机（第 7 章）里已有分支
elif idx == BOV: state, v_buf = "image", []
elif state == "image":
    v_buf.append(idx)
    if len(v_buf) == 1024:                 # 32×32 = 1024 个视觉 ID
        pixels = vq_decoder.decode(v_buf)  # [3, 448, 448]
        v_buf = []
elif idx == EOV: state = "text"
```

实际采出的片段：

```
… 41003「会打火」 → 75776 BOV
→ 67102（金属高光）→ 68034（杯盖塑料）→ 67188 → 67045 → … 共 1024 个
→ 75777 EOV → 75779 EOA / EOS
```

每个视觉 ID 落在 `[65536, 73728)`。解码时同样要**区间偏移**：

```python
def vq_decode(ids):
    # ids: 1024 个整数，每个 65536..73727
    z = torch.stack([vq.codebook[i - 65536] for i in ids])   # [1024, 128]
    z = z.reshape(32, 32, 128).permute(2, 0, 1).unsqueeze(0)  # [1,128,32,32]
    return vq.decoder(z)                                      # [3,448,448]
```

`67102 - 65536 = 1566`。又是「一个 ID，两套向量」：`E[67102]` 是 4096 维语义向量，`vq.codebook[1566]` 是 128 维像素重建码。

## 8.2 理解侧连续、生成侧离散：为什么两套表示

| | 理解侧（第 4 章） | 生成侧（本章） |
|---|---|---|
| 表示 | `[64, 4096]` 连续浮点 | 1024 个整数 ID |
| 是否查表 | 不查 | 查 `E` 与 VQ codebook |
| 目标 | 保真、给主干当条件 | 可采样、能算 CE loss |
| 压缩比 | 1024 patch → 64 query | 32×32 = 1024 个 token |
| 训练 loss | 对齐 / 回归 | Cross-Entropy |

这是 Janus 那条「理解/生成解耦」思路的由来：同一模态，读和写用两套完全不同的表示，只共享主干。硬让一条路兼顾两头，要么量化损失理解精度，要么连续向量无法自回归采样。

副作用是**同一张画面在理解侧是 64 个向量、在生成侧是 1024 个 ID**，两边的空间分辨率不一样。想做「看图→改图」这类任务，需要额外的对齐层或重新 quantized 一次，这是早融合统一词表路线的主要工程债。

## 8.3 输出视频：3D 因果 VAE + 时空 token

视频比图像多一维，链路是：

```
视频帧 [T, 3, H, W]
  → 3D 因果 VAE
       空间下采样 8×8、时间下采样 4×、latent 16 通道
       [T/4, H/8, W/8, 16]
  → 时空 patch 化（tubelet，2~4 帧合一块）
  → 时空 token 序列 [T', N, d]
  → 3D DiT：空间注意力 + 时间注意力 + 文本条件交叉注意力
  → VQ 量化（可选）或流匹配直接出连续 latent
  → 3D decoder + 时域插值 → 视频帧
```

站内书 5.8.5 那段时空分离注意力的实现，本质就是让 `[B,T,N,D]` 在 T 维和 N 维分别做注意力：

```python
class VideoSelfAttention(nn.Module):
    def forward(self, x):                     # [B, T, N, D]
        B, T, N, D = x.shape
        x_s = x.reshape(B*T, N, D)
        x = x + self.spatial_attn(x_s, x_s, x_s)[0].reshape(B, T, N, D)
        x_t = x.permute(0, 2, 1, 3).reshape(B*N, T, D)
        x = x + self.temporal_attn(x_t, x_t, x_t)[0].reshape(B, N, T, D).permute(0, 2, 1, 3)
        return x
```

**时间维必须因果卷积**。若 3D VAE 的 encoder 是非因果的，latent 里已经混入未来帧，流式生成无从谈起；这也是理解侧（chunk-causal ViT）和生成侧（causal Conv3d）都必须改因果的原因。

## 8.4 为什么逐 token 采画面不可行（以及真实产品怎么绕开）

理论上 `IMAGE` 区间就在词表里，随时可采。但工程上**逐 token 自回归采一整帧**几乎没有产品这么做，四个原因：

| 原因 | 具体数字 |
|---|---|
| **延迟** | 1024 个视觉 ID 要串行自回归 1024 步（或并行扩散迭代），远超 200ms 预算；一片语音才 8+1+2 个 token |
| **带宽** | 1024 token × 4096 × 2B ≈ 8MB/帧的激活，与 512KB/片的语音差一个数量级 |
| **交互价值低** | 用户在说话、看现场画面时，需要的是「听懂并回应」，不是再看一张生成图 |
| **KV cache** | 生成画面的中间步会把 cache 撑爆，直接挤掉后续对话片 |

所以 2026 年上半年的现实形态是：**理解侧全模态（看/听/说），生成侧只出文本 + 语音**，画面生成走独立的异步分支。站内收录的 GPT-Live-1、SeedRealtime 都是这个形态。

> **2026-11-07 校准：Higgs Realtime Duplex 打破了这个判断，但方式很巧**——它没有让主干逐 token 采图像，而是**每个 160ms chunk 只输出 2 个图像 latent**，交给一个**因果 DiT** 实时渲染面部视频，条件为「一张参考图 + 前两个 latent」。也就是说：
>
> - 主干每片只多付 **2 个 latent**（≈2 个 token 的量级），完全在预算内；
> - 繁重的像素生成外包给专用 decoder，且 decoder 只看最近两片 → 因果、恒定算力、不会撑爆 KV cache；
> - Avatar 与语音在同一时间轴上逐片对齐，口型/表情自然同步。
>
> **修正后的结论**：不是「全双工不出画面」，而是「**全双工不让主干逐 token 采画面**」。把画面压成极低维的连续 latent + 独立的因果生成式 decoder，就能以每片 2 个 latent 的代价持续出画面。这同时说明第 8.1~8.2 节的「1024 个视觉 ID → VQ decoder」是教学路线，真实产品走的是连续 latent 路线——也再次印证上一章讨论的「原版 VQ-GAN 词表不能原样搬」。

另一个重要设计是**零样本换音色 / 换脸**：Higgs 用一段参考音频定音色、一张参考图定长相，两者只作为条件喂给两个 decoder，**不进主干模型**，因此不需要微调、不需要每个客户训一次。这把「配置」变成了 prompt。

## 8.5 生成侧的音画同步

Veo 3 / Seedance 这类音视频联合生成模型，同步靠的是「同一个时间步 latent」：

```
t 步 latent ─┬─→ 视频 decoder → 帧
             └─→ 音频 decoder → 波形片段
```

两个 decoder 共享 `t`，从源头保证口型与声音对齐。这跟第 5 章 TMRoPE 在**输入侧**做的事是镜像关系：输入侧把音视频绑到同一物理瞬间，输出侧把同一 latent 展开成两种信号。全双工里若真要出画面，也应该复用这套时间锚，而不是各自独立生成再对齐。

## 8.7 本章小结

- 生成画面：`BOV(75776)` → 1024 个 `[65536,73728)` 视觉 ID → `EOV(75777)` → VQ decoder 用 `id-65536` 查第二套码本。
- 理解侧连续 64 向量、生成侧离散 1024 ID，是「读写两套表示」的必然结果，也是统一词表路线的主要工程债。
- 视频生成走 3D 因果 VAE（时间 4×、空间 8×）+ 时空分离注意力，时间维必须因果。
- 全双工产品不逐 token 采画面（1024 步延迟、8MB 激活、cache 撑爆），但可以**每片输出 2 个连续 latent + 因果 DiT** 持续渲染面部——Higgs 的做法。
- 音画同步用「同一时间步 latent 展开成两种信号」，与输入侧 TMRoPE 互为镜像。
- ⚠️ 「生成侧必须离散 ID」是本书教学设定；真实产品输出侧为连续 latent + 生成式解码，零样本换音色/脸靠参考条件只进 decoder。

# 第 5 章 · 代表系统（下）：2026 产业侧与三个口径陷阱

第 4 章是实验室里「有 oracle 的窄域」，这一章是 2026 年真实落到流水线里的东西。产业侧的特征很鲜明：**收益更朴素、口径更容易被夸大、治理比算法更早成熟**。

## 5.1 AIDE²（Weco, 2026-07）：外层 Agent 改内层研究 Agent

| 栏 | 内容 |
|---|---|
| **改什么** | 外层改进 Agent 修改内层研究 Agent 的配置、提示、工具与策略 |
| **验证器** | 内部验证集 + 外部**未见基准** |
| **增益** | **8 天 / 100 步无人值守**；最终版本在 **3 个未见基准**上超过团队手工调了两年的版本 |
| **限制** | 约 **90% 提案被拒**；问题由人类选定、评分标准由人类制定；**官方自评 L1，明确未达 L2 点火** |
| **坐标** | ①/④ 边界 × C2（人定目标） |

AIDE² 最值得学的不是结果，是它诚实地公布了**拒绝率**。90% 提案被拒意味着：这个循环的主要工作不是「改进」，而是「筛掉坏改进」。把拒绝率写进报告，比多报两个百分点的分数更有价值——它直接指向第 6 章的瓶颈论。

「L1 未达 L2」这句官方自评也请原样记住。第 7 章会给 L0–L3 的定义，届时你会发现：**持续运行 8 天 ≠ 改进速率加快**，两者是不同的测量对象。

## 5.2 Memento 3 / COAP：冻结基座，改外部可写的东西

**Memento 3**（站内 `memento-3-arc-agi3-2026`）：**LLM 权重完全冻结**，只学习一本外部规则书（可读写记忆），在 ARC-AGI-3 上 RHAE **100.0**。

**Embodied Turing Machines / COAP**（站内 `embodied-turing-machine-coap-2026`）：策略即代码，编码 Agent 在仿真闭环里自己改写技能库，环境直接给成败信号。

这两条把第 3 章「① × C2 优先」的结论推到极端：**不碰权重也能持续变强，而且更稳**。原因不难理解——外部规则书/技能代码是可读、可 diff、可版本化、可单独回滚的；权重不是。当改进对象本身具备「可审计」属性时，验证成本会下降一个数量级。

```python
# 冻结基座 + 外部可写状态：最小形态
class FrozenBackboneAgent:
    def __init__(self, llm, rulebook):
        self.llm = llm.eval()                 # 冻结，永不更新
        self.rulebook = rulebook             # 唯一可变状态，纯文本/代码

    def act(self, obs):
        return self.llm.generate(obs, context=self.rulebook.render())

    def learn(self, trace, oracle_score):
        if oracle_score > self.best:
            patch = self.llm.propose_rule_patch(trace)
            if deterministic_check(patch) and holdout_check(patch):
                self.rulebook.apply(patch)    # 可 diff、可回滚、可人工读
```

## 5.3 Auriga：具身 Physical RSI

| 指标 | 迭代前 | 13 次 Harness 迭代后 |
|---|---|---|
| RoboDojo Score | 45.5 | **64.0** |
| 成功率 SR | 36.2% | **57.7%** |

约束很硬：Zero-shot、单局、**不允许 `env.reset()`**（不能靠重开环境刷分）。这条约束值得单独强调——它堵掉的正是强化学习里最常见的自欺路径。

但要精确归类：**评测前 Harness 被冻结，改进主要由研发团队推动**，所以严格说仍是 L1（一层循环的工程收益），不是「Harness 自己改进了自己」。它和第 3 章的 Memento 3 是同一类：**把改进放在可读可回滚的脚手架上，收益来自脚手架迭代而非权重突变**。

## 5.4 Hy4 / K3.5：产业侧唯一形成闭环的一条线

| 日期 | 事件 | 关键数字 |
|---|---|---|
| 2026-08-28 | 腾讯 Hy4 preview 开源，首次参与自身研发全链路 | 163 名专家 / 203 个工程任务盲测 |
| 2026-09-02 | Hy4 正式版「RSI 二阶段」：自动生成 CUDA→Triton 迁移并回灌训练栈 | 算子采纳率 **37%**，端到端训练算力 **-25%** |
| 2026-11-01 | Kimi K3.5 正式版：新增「算子级 diff 审查」，数值等价性测试后进主干 | 采纳率 **37→61%**；每次自改进自动产出冻结评估器审计报告；72h 存活 79% |
| 2026-11-01 | 首例权重自改被审计拦截 | 第 7 轮在数学子集回归 **-2.3 点** → 自动回滚、零人工 |

这条线的意义不在分数，在于**它是唯一把「提议 → 确定性验收 → 冻结评估器回归 → 采纳或回滚 → 留痕」全链路跑通并公开的产业案例**。特别注意 K3.5 采纳率提升的原因：新增了「算子级 diff 审查」这个**人设计的流程环节**。这再次印证第 1 章的判断——它是一层循环里很扎实的一步，不是改进器自己变强了。

一个容易被忽略的工程细节：**数值等价性测试**是这条链路里的真正 oracle。算子改写有天然可验证性（同样的输入、同样的输出、误差阈值），所以采纳率能被安全地推到 61%。换成「改进数据配比」这类没有等价性判据的改动，同样的流水线立刻失效。第 6 章会把这条推广成通用原理。

## 5.5 三个必须连读的口径陷阱

### 陷阱一：Anthropic「8× 代码量 / >80% 代码由 AI 生成」

原文自己写明：**代码行数是数量而非质量指标，「几乎肯定高估了真实生产力增益」**。同期论文估算「全自动化后进展速度约 1.5 年 ×10」，但明说**证据不足以证明智能爆炸已发生**。把这两个数字从上下文里摘出来当标题，是 2026 年最常见的误引。

### 陷阱二：自动研究任务「97% vs 人类 23%」

数字本身有出处（800 累计小时、约 $18,000），但三个前提必须一起读：

1. **问题由人类选定**；
2. **评分标准由人类制定**；
3. 结果**未能干净迁移到生产级模型**。

反例同样刺眼：同一个系统在开放式研究问题上跑了 6 天、花了 $3,000，产出被原作者**双双拒稿**。所以这组数字证明的是「在人类划定的封闭题上，自动搜索能跑赢人类基线」，不是「AI 会做研究」。

### 陷阱三：「研究品味」官方承认不可测量

区分合格与卓越研究者的那种判断力——**既无法在当今系统中观察到，也不知道如何测量**；公司给不出累积加速的具体数字，因为**没有这个指标**。这句话比任何反方论证都硬：不是「我们还测不准」，是「我们连量纲都没有」。它直接支撑第 7 章「治理级测量是全领域最空白的坑位」和第 12 章「方向设定是最难被算力堆掉的制约」。

## 5.7 本章小结

- 2026 产业侧的可复现增益，几乎全部来自**可读可回滚的脚手架**（规则书、技能代码、算子 diff、harness），不是权重突变。
- AIDE² 的 90% 拒绝率与 L1 自评，是比任何分数都重要的诚实数据。
- Hy4→K3.5 是唯一跑通「提议→确定性验收→冻结回归→采纳/回滚→留痕」的公开产业链路，其 oracle 是算子的数值等价性测试。
- 三个口径陷阱：代码行数被官方打折、97% vs 23% 的三个人类前提、研究品味连量纲都没有。

# 第 2 章：预训练骨干——VLM 如何为 Physical AI 奠基

## 2.1 为什么预训练是 Physical AI 的基石

VLA 和世界模型都严重依赖预训练的视觉-语言模型（VLM）骨干。原因很简单：**机器人数据的规模比互联网数据小多个数量级**。

| 数据类型 | 规模 | 来源 |
|----------|------|------|
| VLM 预训练数据 | 数十亿图文对 | 互联网爬取 |
| Open X-Embodiment | ~100 万条轨迹 | 22 种机器人 |
| 单个实验室遥操作 | 1,000-50,000 条演示 | 人工采集 |
| V-JEPA 2 预训练 | 100 万+小时视频 | VideoMix22M |
| V-JEPA 2 机器人微调 | 62 小时 | Droid 数据集 |

从数十亿到数万，数据量下降 5-6 个数量级。如果没有预训练 backbone 提供视觉和语言的通用表征，VLA 根本无法从如此少量的机器人数据中学到有效策略。

## 2.2 视觉编码器选型

### 2.2.1 三大编码器对比

| 编码器 | 架构 | 训练目标 | 参数量 | 在 VLA 中的应用 |
|--------|------|----------|--------|-----------------|
| CLIP | ViT | 对比学习（图文对齐） | 0.3-0.9B | RT-2 早期实验 |
| SigLIP | ViT | Sigmoid 对比学习 | 0.4-1.1B | OpenVLA、π0 |
| DINOv2 | ViT | 自监督蒸馏 | 0.3-1.1B | 去重、特征提取 |

**SigLIP 为什么取代 CLIP**：CLIP 使用 softmax 对比损失，需要全局 softmax over batch（batch 内所有样本两两计算），显存随 batch size 平方增长。SigLIP 改用 sigmoid 损失，每个图文对独立计算，显存随 batch 线性增长，因此可以用更大的 batch（32K+）训练，学到更好的表征。OpenVLA 和 π0 都选择 SigLIP 作为视觉编码器。

### 2.2.2 视觉 Token 化

无论选哪个编码器，图像最终被转换为一组视觉 token 序列：

```python
# PaliGemma 的视觉编码流程
image_patches = patchify(image, patch_size=16)  # 224×224 → 14×14 = 196 patches
visual_tokens = siglip_encoder(image_patches)    # → 196 tokens × 2048 dim
visual_tokens = linear_proj(visual_tokens)        # → 196 tokens × 2048 dim（映射到语言空间）
```

对于 VLA，图像分辨率和 token 数量直接影响推理延迟：

| 分辨率 | Patch 数 | Token 数 | 推理延迟（A100） | 适用场景 |
|--------|----------|----------|-------------------|----------|
| 224×224 | 14×14 | 196 | ~5ms | π0（50Hz 控制） |
| 336×336 | 21×21 | 441 | ~12ms | OpenVLA（6Hz） |
| 448×448 | 28×28 | 784 | ~25ms | 高精度场景 |

π0 选择 224×224 以满足 50Hz 控制频率；OpenVLA 选择 336×336 以获得更好的视觉理解，代价是降到 6Hz。

## 2.3 语言模型骨干

### 2.3.1 VLA 中使用的 LM 骨干

| 模型 | LM 骨干 | 参数量 | 动作表示 | 备注 |
|------|---------|--------|----------|------|
| RT-2 | PaLI-X | 55B | 离散 token | 闭源，Google 内部 |
| RT-2-X | PaLI-X | 55B | 离散 token | 跨具身扩展 |
| OpenVLA | Llama 2 | 7B | 离散 token（256 bins） | 开源，最广泛使用 |
| π0 | PaliGemma | 3B | Flow Matching | 开源，高频控制 |
| GR00T N1 | Eagle2 VLM | 2B | Diffusion (DiT) | 开源（Apache 2.0） |
| GR00T 1.7 | Cosmos-Reason2 | 2B | Diffusion (DiT) | Qwen3-VL 架构 |

### 2.3.2 从 PaLI-X 到 PaliGemma：效率的演进

RT-2 使用 55B 参数的 PaLI-X，需要 64+ TPU v4 训练，推理延迟 1-3 秒/动作。这远不能满足实时控制需求。

π0 的突破在于选择 PaliGemma（3B）——Google 开源的轻量 VLM，在保持视觉-语言理解能力的同时将参数压缩到 1/18。配合 flow matching 动作头（仅增加 300M 参数），总参数 3.3B，可在单张 A100 上以 50Hz 运行。

### 2.3.3 GR00T 的双系统骨干选择

GR00T N1 使用 Eagle2 VLM 作为 System 1（慢思考），DiT（Diffusion Transformer）作为 System 2（快动作）。GR00T 1.7 升级为 Cosmos-Reason2（Qwen3-VL 架构），支持原生宽高比编码（无需 padding），进一步提升了视觉理解质量。

## 2.4 VLM 对齐训练

VLA 使用的 VLM 骨干并非直接从图文对比训练中获得——它还需要经过**对齐训练**，使其能够理解指令并生成回答。

### 2.4.1 三阶段对齐

```
Stage 1: 视觉-语言预训练（Pretrain）
  数据: 数十亿图文对（LAION、DataComp 等）
  目标: 对比学习 + 图文匹配
  产出: 视觉编码器 + 语言模型的基础对齐

Stage 2: 视觉指令微调（Visual Instruction Tuning）
  数据: 数百万多模态对话（LLaVA-style）
  目标: 指令跟随 + 视觉问答
  产出: 能理解"图中的杯子是什么颜色？"的 VLM

Stage 3: VLA 微调（VLA Fine-tuning）
  数据: 机器人演示轨迹（图像, 指令, 动作）
  目标: 动作生成
  产出: VLA 策略模型
```

### 2.4.2 灾难性遗忘与 Co-fine-tuning

直接在机器人数据上微调 VLM 会导致**灾难性遗忘**——模型忘记了互联网预训练学到的世界知识。RT-2 的解决方案是 Co-fine-tuning：

```
训练批次 = α × VLM数据 + (1-α) × 机器人数据
```

RT-2 的消融实验揭示了配比的关键影响：

| α（VLM 数据比例） | 已知任务成功率 | 零样本泛化成功率 |
|--------------------|----------------|-------------------|
| 0.0（纯机器人数据） | 93% | 12% |
| 0.25 | 92% | 34% |
| 0.50 | 91% | 62% |
| 0.75 | 85% | 71% |

**50% VLM + 50% 机器人数据**是默认配置——在已知任务性能和泛化能力之间取得最佳平衡。纯机器人数据虽然已知任务成功率最高（93%），但泛化能力极差（12%）。

OpenVLA 为了简化训练流程，选择**仅在机器人数据上微调**（不做 Co-fine-tuning），代价是在需要互联网知识的语义泛化任务上表现较差。例如，RT-2-X 能将可乐罐移到"Taylor Swift"图片旁（互联网概念），而 OpenVLA 不能。

## 2.5 世界模型的预训练骨干

世界模型的预训练与 VLA 不同——它不需要语言对齐，而是专注于**视频理解与预测**：

| 模型 | 预训练方法 | 数据规模 | 编码器架构 |
|------|-----------|----------|------------|
| V-JEPA 2 | 自监督掩码预测 | 100 万+小时视频 | ViT-g（1B 参数） |
| Cosmos | 扩散/自回归视频生成 | 2000 万小时→1 亿片段 | DiT / Llama3-style |
| Genie 3 | 自监督视频+动作 | 3000 万视频片段 | Spatiotemporal Tokenizer |

### 2.5.1 V-JEPA 2 的预训练哲学

V-JEPA 2 坚持在**潜在表示空间**中预测，而非像素空间重建。其核心论点是：

- **像素级预测**（如视频生成模型）被迫学习不可预测的噪声细节（草地纹理、光线反射），浪费模型容量
- **潜在空间预测**只学习高层次可预测的概念（物体未来位置、运动轨迹），表征更鲁棒

V-JEPA 2 的预训练目标：

```
L = || P_φ(ẑ_masked; z_context) - ẑ_target ||_1
```

其中：
- `ẑ_target` = EMA 编码器对目标帧的编码（stop-gradient）
- `P_φ` 是预测器（2200 万参数的 ViT-s）
- 损失仅在 masked patch 上计算

### 2.5.2 Cosmos 的预训练哲学

Cosmos 选择像素级生成路线，因为 Physical AI 需要的不仅是理解，还有**可模拟的视觉输出**——如果要用世界模型为 VLA 生成合成训练数据，它必须能输出像素级的视频。

Cosmos 探索了两条预训练路线：

| 路线 | Token 类型 | 模型架构 | 优势 | 劣势 |
|------|-----------|----------|------|------|
| 扩散 | 连续 token | DiT（7B/14B） | 像素质量高、运动流畅 | 推理慢（多步去噪） |
| 自回归 | 离散 token | Llama3-style（4B-13B） | 可用 LLM 推理优化（KV cache） | 像素模糊、需增强器 |

## 2.6 小结

| 维度 | VLA 预训练 | 世界模型预训练 |
|------|-----------|---------------|
| 核心目标 | 视觉-语言-动作对齐 | 世界动力学建模 |
| 数据 | 图文对 + 机器人演示 | 大规模视频 |
| 方法 | 对比学习 + 指令微调 + VLA 微调 | 自监督掩码预测 / 视频生成 |
| 关键挑战 | 灾难性遗忘（Co-fine-tuning 解决） | 物理一致性（数据策展解决） |
| 共享组件 | 视觉编码器（SigLIP/DINOv2） | — |

预训练骨干的选择直接决定了 VLA 和世界模型的能力上限。下一章开始，我们将深入 VLA 训练的完整流程，从数据工程到动作表征。

# 第 6 章 · 主干逐层 shape 与融合发生地

这一章回答「哪里融合了」。答案会有点反直觉：**主干里根本没有「融合层」这个模块**。

## 6.1 逐层 shape 全表

| 段 | 层 | 输入 shape | 输出 shape | 模态还分得开吗 |
|---|---|---|---|---|
| ① | 原始信号 | — | `A[1,1920]` / `V[1,3,448,448]` / `T[1,1]` | ✅ 物理形态就不同 |
| ② | 三个独立 encoder | 上行 | `[1,8]` ids、`[1,1024,1152]`、`[1,1,4096]` | ✅ 参数不共享 |
| ③ | 投影 + resampler | 上行 | `[8,4096]`、`[64,4096]`、`[1,4096]` | ⚠️ 维度刚统一 |
| ④ | 贴四层标签 | 上行 | shape 不变 | ✅ 显式注入 |
| ⑤ | 拼接 | 三段 | `x[1,87,4096]` | ❌ shape 无模态轴 |
| ⑥ | 主干 ×32 | `[1,87,4096]` | `[1,87,4096]` | ❌ 共享参数 |
| ⑦ | 输出头 | `[1,87,4096]` | `logits[1,87,75840]` | ✅ 按 ID 区间再区分 |
| ⑧ | 状态机 | `logits` | 具体模态 token | ✅ 硬约束 |

区分在两端（② 独立参数 + ④ 显式标签，⑦ 输出侧 ID 分区），融合在中间（⑥ 共享主干）。**参数共享程度沿架构呈「分 → 合 → 分」的沙漏形**。

## 6.2 展开主干的一层

```python
# x: [1, 87, 4096]
h    = RMSNorm(x)                                    # [1, 87, 4096]
qkv  = W_qkv(h)                                      # [1, 87, 12288]
q,k,v = qkv.chunk(3, -1)
q = q.view(1, 87, 32, 128).transpose(1, 2)          # [1, 32, 87, 128]
k = k.view(1, 87, 32, 128).transpose(1, 2)          # [1, 32, 87, 128]
v = v.view(1, 87, 32, 128).transpose(1, 2)          # [1, 32, 87, 128]

q, k = apply_3d_rope(q, k, pos_ids)                  # shape 完全不变

scores = q @ k.transpose(-1, -2) / (128 ** 0.5)     # [1, 32, 87, 87]  ★融合在这里
scores = scores.masked_fill(chunk_causal_mask, -float('inf'))
a      = scores.softmax(-1)                          # [1, 32, 87, 87]
out    = (a @ v).transpose(1, 2).reshape(1, 87, 4096)
x      = x + W_o(out)                                # [1, 87, 4096]
x      = x + W_down(SiLU(W_gate(h)) * W_up(h))       # FFN [1,87,11008] → [1,87,4096]
```

32 层里没有 `if modality ==` 分支，没有「视觉层」「音频层」，没有专门的 cross-attention 融合模块。所有跨模态交互，都是 `scores` 这个 87×87 矩阵里的权重。

## 6.3 融合的确切位置

把 `scores` 看成一张表，行是 Q，列是 K：

```
              K: V0…V63 (pos1..64)   K: A_user (67..74)   K: T (86)
Q: V29  ──      橙（模态内）            紫（跨模态）           紫
Q: A67  ──      紫（跨模态）            蓝（模态内）           紫
Q: T86  ──      紫（跨模态）★          紫（跨模态）           灰（模态内）
```

**融合就是那些紫色的格子**。具体到例子：

```
Q(pos86,「这个」) · K(pos29, 金属杯高光)
```

这个点积经 softmax 后就是「这个」指向杯子的权重。它为什么偏偏落在 `pos29` 而不是别的 patch？三股力量叠加：

1. **同 `t=3200`** → TMRoPE 旋转角接近，点积天然偏大；
2. **`(h=3,w=5)` 空间身份** → 该槽位稳定对应画面中央偏右区域；
3. **训练数据共现** → 大量「指代词 + 被举起/注视的显著物体」样本，让模型学会把这个 Q 指向显著性最高的 patch。

## 6.4 权重随层深的变化（示意量级）

| 层 | `Q(T86)·K(V29)` | 在干什么 |
|---|---|---|
| 1 | 0.02 | 几乎只看邻近文本，低层特征对齐 |
| 8 | 0.05 | 开始扫同模态上下文 |
| 16 | 0.14 | 跨模态权重抬头，「这个」开始绑定某个物体 |
| 24 | **0.31** | 指代被消解：哦，是金属杯 |
| 32 | 0.28 ＋ `K(A_user「能微波」)≈0.19` | 两路证据汇合 |

> 这组数字是示意量级，用来说明机制；真实模型可用 attention rollout 或 logit lens 测到同类曲线。

到 `hidden[86]` 这个 4096 维向量里，已经编码了「金属容器 + 微波 → 不行」。**这不是某个模块算出来的，是 32 次 `Q·K` 加权累加出来的**。这也是早融合最容易被低估的一点：融合不是一个可以单独优化的组件，它是训练数据在注意力权重里沉淀出来的统计结构。

想验证自己训的模型有没有真融合，可以探查特定格子的权重：

```python
with torch.no_grad():
    a = model.layers[23].attn_weights        # [1, 32, 87, 87]
    print(a[0, :, 86, 29].mean().item())     # 「这个」→ 金属杯
    print(a[0, :, 86, 67].mean().item())     # 「这个」→ 用户音频
```

若跨模态权重在所有层都接近 0，说明数据配比或位置编码出了问题，不是模型容量不够。

## 6.5 三种融合范式的差别再确认

| 范式 | 融合点 | 交互深度 | 参数代价 | 典型失败 |
|---|---|---|---|---|
| 早融合（本书） | 主干全部层的自注意力 | 最深 | 最省（一套主干） | 文本能力被拉扯、需海量混合数据 |
| 中融合 | 插入的 gated cross-attention 层 | 受限于插几层 | 多一套融合层 | 长程跨模态推理不足 |
| 晚融合 | 决策层拼接 | 几乎无 | 最省但无交互 | 解不开指代、无法共时对齐 |

本例「这个」必须看到杯子，早融合是唯一自然的选择。

## 6.6 KV cache：shape 才是显存瓶颈

```python
# 每层缓存
K_cache: [1, 32, L_cached, 128]
V_cache: [1, 32, L_cached, 128]
# bf16 单层 ≈ 2 × 1 × 32 × L × 128 × 2 B = 16384 × L 字节
# 32 层、L=326000（5 分钟）≈ 171 GB —— 单卡根本放不下
```

所以第 9 章必须处理长会话：滑窗、压缩记忆、分层状态、或 Moshi 式「时间 × 深度」分解（Temporal Transformer 只看 4096 个时间步，17 条子序列由 6 层 Depth 小模型在片内展开，主干序列长度直接除以 17）。

另外，全双工是**持续 decode**：即便用户沉默，模型流也要每 80ms 出一片（哪怕一片 `SIL`）。单路墙钟占比约 50% 的算力空转，多路同拍 batch 才能摊薄成本——这跟在线服务的副本调度是同一笔账。

## 6.7 五个 shape 层面的坑

1. **`L` 会爆炸**：87/片 × 12.5 片/秒 = 1087 token/秒，5 分钟 32.6 万。不折叠就跑不动。
2. **RoPE 的 head_dim 要按三维分段**：`t/h/w` 各占一段分别旋转，别把 128 维整体当一维位置。
3. **`type_emb` 别 concat**：`[1,L,4100]` 破坏 RMSNorm 尺度与残差流。
4. **chunk-causal 掩码按 `t` 而不是按 index**：跳帧时 index 会漂。
5. **别只盯最终 loss**：跨模态权重近乎 0 而 loss 正常下降，说明模型靠文本先验在蒙，部署到需要 grounding 的场景会崩。

## 6.8 本章小结

- 主干 32 层全程 `[1,87,4096]`，无任何模态专属结构。
- 融合 = `scores[1,32,87,87]` 里的 `Q(「这个」)·K(金属杯高光)` 那些格子；权重从 0.02 长到 0.31。
- 早融合让交互最深，但要用结构隔离缓解文本能力退化。
- KV cache 按 `L` 线性增长，5 分钟约 171 GB，必须压缩或做时间×深度分解。
- 调试要点：直接探查跨模态注意力权重，比看 loss 更早发现问题。

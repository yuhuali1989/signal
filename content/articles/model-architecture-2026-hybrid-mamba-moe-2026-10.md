## 引子：三句话讲清格局

1. **Transformer 没有死**，仍是生产默认。
2. 但它**不再独占**——SSM、线性注意力、MoE 各有位置。
3. ★**2026 的真正答案是「混合」**：让便宜的线性/递归层干大部分活，把贵的全注意力留给真正需要精确检索的少数层。

一句被广泛引用的总结：

> **「Transformer 架构的故事不是『Transformer 死了』，而是『Transformer 有了竞争者和舞伴』。」**

## 1. Transformer 的两个结构性瓶颈

| 瓶颈 | 数学表现 | 后果 |
|---|---|---|
| **① 注意力二次复杂度** | 序列长度 n → 计算量 O(n²) | 1M token 意味着 10¹² 量级的两两比较 |
| **② KV cache 线性膨胀** | 每生成一个 token 多存一份 K/V | ★长序列推理显存持续增长 |

**为什么 ② 在物理 AI 里更致命**：语言模型可以「一次对话结束就释放」，但**机器人是长时间连续运行的**——缓存不断膨胀，几分钟就撑不住。

这也解释了为什么**端侧机器人/车端**对 Mamba 类架构格外敏感：它推理时**只存常数大小的状态**。

## 2. SSM / Mamba 系：从 Mamba 到 Mamba-3

状态空间模型用递归隐藏状态压缩历史：

```
h_t = A·h_{t-1} + B·x_t
y_t = C·h_t
```

| 版本 | 进展 |
|---|---|
| **Mamba** | A、B、C 变为**输入相关（selective）**，模型能自行决定记什么忘什么，质量大幅逼近注意力 |
| **Mamba-2** | ★**结构化状态空间对偶（SSD）**：选择性 SSM 与注意力是**同一结构化矩阵运算的两种视角** → 可在 GPU 擅长的矩阵乘上高效训练，推理时仍是 O(n) 递归 |
| **Mamba-3**（ICLR 2026） | 更具表达力的离散化递归、**复数状态更新**、MIMO 公式；检索与状态追踪精度提升，★**解码成本约为同等 Transformer 的一半** |

## 3. ★ 混合架构：2026 的默认答案

纯 SSM 与纯注意力**失败模式互补**：

| | 擅长 | 短板 |
|---|---|---|
| **纯 SSM** | 廉价压缩长上下文 | ★精确召回弱（从很早之前抄回一个名字） |
| **纯注意力** | 精确检索、局部模式 | 长序列昂贵 |

**主流做法**：SSM 层承担大部分序列处理（线性成本），在关键深度插入注意力层保住高保真检索。

### 配比参考（可直接用于选型）

| 模型 | 架构 | 上下文 | 效率收益 |
|---|---|---|---|
| **Jamba 1.5 / 2**（AI21） | attention:Mamba = **1:7**（含 MoE） | 256K | 快至 2.5×，KV cache 降约 10× |
| **Nemotron-H**（NVIDIA 8B/56B） | Mamba-2 + 稀疏注意力，**84% 为 Mamba 层**；56B 中 54 Mamba-2 + 54 MLP 仅含 **10 个 attention 层** | 128K（可扩展） | 比 Qwen2.5 / Llama3.1 **快至 3×** |
| **Nemotron 3**（Nano/Super/Ultra） | Hybrid Mamba-Transformer MoE + **LatentMoE** | **1M** | 内存与算力效率 **4×**，吞吐 3.3× |
| **Kimi Linear**（Moonshot） | Kimi Delta Attention（Gated DeltaNet 扩展）:全注意力 = **3:1** | 1M | ★**KV cache 降 75%**，解码吞吐最高 **6×** |
| **Qwen3-Next** | Gated DeltaNet:全注意力 = **3:1** | — | 同上思路 |
| **Granite 4.0**（IBM） | Mamba-2 + Transformer + 细粒度 MoE | 128K（训练 512K） | ★**内存降 70%**，单张 H100 可跑满负载 |
| **MiniMax-01** | 首个大规模线性注意力模型，**456B MoE（45.9B 激活）**，7:1 | **4M** | 超长上下文 |

> 2026 年 3 月的研究进一步证明：**混合模型能用比任一单一成分更小的参数量和工作记忆**，解决选择性复制与联想召回任务。

## 4. 稀疏与线性注意力：另一条支路

| 技术 | 思路 |
|---|---|
| **DeepSeek Sparse Attention（DSA）** | 每个 token 只关注学到的相关子集，而非全部历史 |
| **Gated DeltaNet / RetNet** | 把 softmax 核改写为可递归表达的形式，效果类似 SSM |
| **RWKV-7** | 以 Transformer 可并行方式训练，推理时 RNN 式，显存低一个量级 |
| **Griffin / Griffin-2** | 线性递归 + 局部注意力 |

## 5. MoE：条件计算已成默认

```
每个 token 经 router 只激活 top-k 个专家
→ 总容量大、激活参数小 → 容量与成本解耦
```

| 优点 | 工程难点 |
|---|---|
| 大容量、低成本 | **路由均衡**（否则少数专家过载） |
| 前沿模型默认 | **专家坍缩**（少数专家主导，其余饿死） |
| | **推理通信开销**（专家跨卡分布） |

**对物理 AI 的价值**：机器人需要**广博常识（大容量）**，但每步只有**几十毫秒预算（小激活）**——MoE 正好对口。

## 6. 更激进的两个方向

| 方向 | 机制 | 状态 |
|---|---|---|
| **扩散语言模型（dLLM）** | 从全掩码序列**并行去噪**多步细化（Gemini Diffusion、LLaDA） | 延迟优势明显，但**工具链与解码策略仍在早期** |
| **Titans（Google）** | 神经长期记忆模块，前向传播中用「**surprise**」信号决定记什么忘什么，可扩到 2M+ 上下文 | 代表「注意力=短期记忆 + 神经长期记忆」新范式 |
| **BLT** | 动态字节 patch，难预测处多给算力 | 挑战固定 token 假设 |

> ★对物理 AI 的含义：dLLM 的**并行解码**若能成熟，天然契合「一次生成一整段动作轨迹」；Titans 式长期记忆对应「记住上次在这间房失败过」。

## 7. 选型建议

| 场景 | 建议 |
|---|---|
| **端侧 / 机器人 / 车端，长时运行** | ★高 Mamba 占比的混合架构（显存/延迟双约束） |
| **云端高并发长上下文服务** | 混合 + 稀疏注意力（KV cache 是主要成本） |
| **要广博知识但预算紧** | MoE（大容量小激活） |
| **延迟极敏感的生成** | 关注 dLLM，但暂不作为生产默认 |
| **超长上下文（>1M）** | 混合架构 + 记忆模块（Titans 思路） |

**三条工程提醒**：

1. **不要用版本号代替能力探测**——同样的"混合架构"，配比与实现差异巨大
2. **延迟预算先行**——先定控制频率（如 50 Hz = 20 ms），再倒推架构
3. **常开监控**——KV cache 峰值、解码吞吐、失败率，这些决定真实可用性

## 8. 小结

- Transformer 的两个瓶颈：**O(n²) 注意力 + KV cache 线性膨胀**，后者对长时运行的机器人尤其致命。
- ★**混合架构是 2026 默认**：便宜层干大部分活，贵的注意力留给精确检索（配比 1:7 到 3:1 区间）。
- **Mamba-3**（ICLR 2026）把解码成本压到约一半，且状态大小恒定。
- **MoE** 提供「大容量 + 小激活」，契合机器人「广博常识 + 毫秒预算」。
- **dLLM / Titans / BLT** 是更远的赌注，值得关注但不宜当下押注。

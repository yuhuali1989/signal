# 第 8 章 · 官方没公开词表：能说什么、不能说什么

## 8.1 先把事实钉死

关于 Higgs Realtime Duplex 的表示，**官方公开的全部内容**是这四类数量：

| 项 | 官方表述 |
|---|---|
| 输入音频 | `one audio token per chunk in`、`6.25 tokens per second` |
| 输出音频 | `two audio frames`、`audio out at 12.5` |
| 输入视频 | `A camera frame, about a dozen tokens, comes once every six chunks` |
| 输出面部 | `two image latents`、`two latents for the face` |

官方**没有**公开：主干词表大小、是否有统一离散词表、音频/视觉 tokenizer 类型、码本结构、embedding 维度、输出采样方式。输出侧明确用了 `latent` 与 `frames` 这类连续表示的词；输入侧的 `token` 则两种可能都有。

> 上一轮校准《全双工全模态工程全书》时犯的错，正是把「本书方案」写成「业界事实」。这一章立一条规矩：**未公开就是未公开，不拿教学基准的 75840 四段词表去补 Higgs 的空白**。

## 8.2 「词表」至少是三种东西

| 含义 | 形态 | 作用 |
|---|---|---|
| ① **主干 embedding 表** | `nn.Embedding(V, d)` | ID → d 维向量进 Transformer；生成时对 V 做 softmax 采样 |
| ② **量化码本 codebook** | VQ/FSQ/LFQ 的整数集 | 最近邻量化成 ID，主要给 decoder 重建像素/波形 |
| ③ **连续投影的「无限词表」** | `Conv2d` / 线性投影 | 任意 patch → d 维浮点，没有有限集合 |

一个反直觉的例子：MAGVIT-v2 的 LFQ 有 `2^18 = 262144` 的 ID 空间，却**没有一张可查的表**（把码本 embedding 维度降到 0，用 `sign(z)` 二值化直接拼出整数）。所以连「有多少个 ID」都不等价于「有一张词表」。

## 8.3 四种组合，以及 Higgs 能定位到哪一格

按「token 离散还是连续 × ID 查主干还是只喂 decoder」分：

| | 输入侧 | 主干查表 | 码本 | 代表 |
|---|---|---|---|---|
| **A 连续投影** | `[d]` 浮点 | 否 | 无 | LLaVA / Qwen-VL |
| **B 统一离散** | 整数 ID | **是** | 有 | Emu3 / Chameleon |
| **C 离散只给 decoder** | 整数 ID | 否 | 有 | MAGVIT-v2 / Cosmos DV |
| **D 连续 latent + 生成解码** | `[c]` 浮点 | 否 | 无 | Wan / Sora / FLUX；**Higgs 输出侧** |

**Higgs 可确定的位置只有一格**：输出侧是 **D 类**——2 个 audio frame 与 2 个 image latent 都是连续表示，交给生成式 decoder，官方文档里没有任何「采样视觉/音频 ID」的描述。

输入侧则**无法确定**：

- 若 `one audio token per chunk` 是一个离散 ID（类似 VQ 码字），那输入侧接近 B 或 C；
- 若它是一个连续向量（音频编码器池化出一个 `[d]`），那输入侧接近 A；
- 两种实现都能满足「6.25 tok/s、每片 1 个」的预算，也无法从公开 benchmark 反推。

> 【推断】从「音色由参考音频在 decoder 侧注入」看，输入侧更像**语义连续向量**而非承载声学细节的 RVQ 多层码字；但这只是动机推断，**不是官方结论**。

## 8.4 与教学基准书的 75840 四段词表对照

《全双工全模态工程全书》前 10 章为了讲透「ID 区间 / logits mask / 状态机」，构造了：

```
[0, 65535]      文本 BPE
[65536, 73727]  视觉 VQ codebook 8192
[73728, 75775]  音频 RVQ 2048
[75776, 75839]  控制符 64
V = 75840, 一个 head 出 75840 logits
```

| | 教学基准书 | Higgs【官方】 |
|---|---|---|
| 词表规模 | 75840，四段分区 | **【未公开】** |
| 输入视觉 | 64 连续向量/片（不查表） | 每 6 片 1 帧、约 12 token，形态未公开 |
| 输入音频 | 8 层 RVQ ID/片 | **1 token/片**，离散或连续未公开 |
| 输出 | 一个 head softmax 采文本/音频/视觉 ID | 连续 frame / latent + 两个生成式 decoder |
| 状态机 | logits mask 切区间 | 【未公开】；话轮决策由模型自己学（第 10 章） |

教学基准的价值在于它是唯一能把「区间 → mask → 状态切换」讲到代码级的设定；Higgs 的价值在于它证明**量产全双工可以不走这条路**。两者不是对错关系，是「教具」与「产品」的关系。

## 8.5 为什么量产实时系统倾向避开视觉离散码本

这是工程动机分析，不是对 Higgs 的断言（它只是未公开，不代表用过或没用过）：

| 问题 | 对全双工的影响 |
|---|---|
| **码本坍缩** | 8192 项里大半是死码，语义粒度变粗；进统一词表还白占 softmax 维度 |
| **逐帧闪烁** | 2D 逐帧 argmin 会让相邻帧在同义码之间跳（Phenaki 对照：逐帧 VQGAN 重建 FVD 306.1 vs 时序感知 65.78） |
| **非因果泄漏** | 双向/非因果 3D 卷积把未来帧信息混进 latent，流式生成不成立 |
| **head 膨胀** | LFQ 级别 262144 视觉 ID 塞进统一表，输出头参数会涨到 GB 级 |

连续 latent + 因果 DiT 一次绕开前三条，还能把「每片出几个 latent」定成常数（第 7 章的恒定算力）。所以「不用视觉离散词表」是**一条合理路线**，但绝不能说成「业界共识」——Hugging Face 上 Emu3、Cosmos Tokenizer 离散版都仍在用码本，只是用途不同（详见全双工全书 ch12）。

## 8.6 可查清单与不可查清单

**能写进设计文档的**：

- 每片四条流的 token/frame/latent 数量与速率【官方】；
- 输出侧是连续 latent，配两个因果生成式 decoder【官方】；
- 参考音频/图只进 decoder、不进主干【官方】；
- 每分钟 2.6K、含文本 2.6~5K、5 分钟 13K~25K【官方/图注】。

**不能写的**：

- 词表大小、区间划分、`which_modality()` 之类的区间判断；
- 「输入是离散 ID」或「输入是连续向量」二选一；
- RVQ 层数、codebook 大小、采样 temperature、logits mask 规则；
- 主干 hidden size、head 维度、位置编码具体形式。

一句话：**本书能讲清 Higgs 的时间结构与预算结构，讲不清它的符号系统**——因为后者压根没公开。任何看起来很具体的词表配置，都来自教学基准书，不属于这个产品。

## 8.7 本章小结

- 官方只给了四条数量，词表、tokenizer、码本、embedding 维度全部【未公开】。
- 词表有三种含义、四种组合；Higgs **输出侧可定位为 D 类连续 latent**，输入侧离散与否无法确定。
- 教学基准的 75840 四段词表是教具，不能拿来补 Higgs 的空白；两者是「教具 vs 产品」。
- 避开视觉离散码本有四条工程动机（坍缩/闪烁/非因果/head 膨胀），但这是路线分析，不是业界结论。
- 本章给出可查与不可查清单：能讲时间与预算，不能讲符号系统。

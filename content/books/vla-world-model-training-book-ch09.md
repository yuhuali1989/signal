# 第 9 章：世界模型实战剖析——V-JEPA 2 / Cosmos / Genie 3

## 9.1 V-JEPA 2：自监督世界模型

### 9.1.1 模型全貌

| 维度 | 配置 |
|------|------|
| 架构 | JEPA（编码器 + 预测器） |
| 编码器 | ViT-g, 1B 参数 |
| 预测器 | ViT-s, 22M 参数 |
| 总参数 | 1.2B |
| 预训练数据 | VideoMix22M (2200万视频, 100万+小时) |
| 动作条件化数据 | 62 小时 Droid 机器人视频 (无标注) |
| 训练硬件 | 大规模 GPU 集群 (具体未公开) |
| 开源 | ✅ (HuggingFace) |

### 9.1.2 两阶段训练详解

**阶段 1: 无动作自监督预训练**

```
目标: 学习世界动力学的通用表征

输入:
  视频片段 → Tubelet Patchify (2×16×16) → patch 序列
  Multiblock Masking → 部分区域被掩码

编码器 E_θ (ViT-g, 1B):
  处理可见 patches → z_context (上下文表示)
  使用 3D-RoPE 位置编码

预测器 P_φ (ViT-s, 22M):
  输入: z_context + mask 位置信息
  输出: ẑ_predicted (被掩码区域的预测表示)

目标表示:
  z_target = EMA_E(x_target)
  EMA 编码器: E 的指数移动平均版本, 参数不更新 (stop-gradient)

损失:
  L = ||ẑ_predicted - z_target||₁  (L1 距离)
  仅在 masked patch 上计算

训练配置:
  渐进分辨率: warmup 16f@256² → cooldown 64f@384²
  迭代次数: 252K
  数据: VideoMix22M (手动调优采样权重)
```

**阶段 2: 动作条件化微调 (V-JEPA 2-AC)**

```
目标: 让世界模型理解"动作如何改变世界"

数据: 62 小时 Droid 机器人视频
  - 无标注! 不需要人工标注动作
  - 模型从帧间变化中推断动作效果

架构变化:
  预测器增加动作输入: P_φ(z_context, a_t) → ẑ_{t+1}
  动作 a_t 从视频帧间变化中自监督推断

训练:
  冻结编码器 E_θ (保持预训练表征)
  仅微调预测器 P_φ
  数据量极小 (62h vs 100万+h 预训练)

产出:
  动作条件化的潜在世界模型
  给定 (当前状态, 动作) → 预测未来潜在状态
```

### 9.1.3 零样本机器人规划

V-JEPA 2-AC 的规划过程：

```
输入: 当前图像 o_t + 目标图像 o_goal
  ↓
规划循环:
  1. 编码: z_t = E(o_t), z_goal = E(o_goal)
  2. 搜索动作 a_t 使 ||P(z_t, a_t) - z_goal|| 最小
     方法: 梯度下降 或 采样 + 选择
  3. 执行 a_t, 观察新状态 o_{t+1}
  4. 重复直到接近目标
  ↓
输出: 动作序列 [a_0, a_1, ..., a_T]
```

**性能**：
- 规划耗时: 16 秒/动作
- 对比: 基于 Cosmos 像素生成的规划需 4 分钟/动作（15× 更慢）
- 部署: 在两个未见过的实验室环境中零样本执行拾取放置任务
- 任务: reaching, grasping, pick-and-place

### 9.1.4 关键工程发现

1. **潜在空间预测比像素生成快 15×**：不需要生成像素，规划速度大幅提升
2. **62 小时数据足够**：预训练提供的世界知识使动作条件化只需极少数据
3. **渐进分辨率省 8.4× GPU 时间**：全分辨率训练 ViT-g 需 ~60 GPU-years
4. **3D-RoPE 是大模型稳定的关键**：取代绝对正弦编码后训练更稳定
5. **EMA + stop-gradient 防止坍缩**：这是 JEPA 不退化为常数的核心机制

## 9.2 Cosmos：世界基础模型平台

### 9.2.1 模型全貌

| 维度 | 扩散路线 | 自回归路线 |
|------|----------|------------|
| 模型规模 | 7B / 14B | 4B / 5B / 12B / 13B |
| Token 类型 | 连续 (CV8x8x8) | 离散 (DV8x16x16) |
| 架构 | DiT | Llama3-style decoder |
| 词汇表 | — | 64,000 |
| 位置编码 | — | 3D RoPE (YaRN) + 3D APE |
| 文本编码 | T5-XXL 交叉注意力 | T5-XXL 交叉注意力 |
| 训练阶段 | Text2World → Video2World | 17帧→34帧→加文本→cooldown |
| 后训练 | 相机控制/机器人/自驾 | 相机控制/机器人/自驾 |
| 推理优化 | — | KV cache + Medusa 推测解码 |
| Enhancer | — | Diffusion Decoder (离散→连续) |

### 9.2.2 扩散预训练详解

**7B 模型的训练配置**：

```
渐进训练:
  Stage 1 (低分辨率):
    分辨率: 512p (640×512)
    帧数: 57
    上下文: 10,240 tokens
    并行: FSDP=64, CP=2
    
  Stage 2 (高分辨率):
    分辨率: 720p (1280×704)
    帧数: 121
    上下文: 56,320 tokens
    并行: FSDP=64, CP=8
    
  Stage 3 (高质量微调):
    同 Stage 2 配置
    数据: 高质量子集
    迭代: O(10K)
    学习率: 线性衰减

两阶段预训练:
  Phase A: Text2World
    条件: 文本提示
    目标: 文本→视频生成
    
  Phase B: Video2World
    条件: 文本提示 + 输入视频帧
    目标: (文本, 当前帧) → 未来视频
    方法: 在 Phase A 基础上微调
```

**14B 模型**：架构相同但参数翻倍，生成更精细的视频细节和更好的运动稳定性。

### 9.2.3 自回归预训练详解

```
架构: Llama3-style Transformer decoder
  - 3D-aware 位置嵌入: YaRN-extended 3D RoPE + 3D APE
  - QK-Normalization: 稳定训练
  - Z-loss: 防止 logits 爆炸
  - T5-XXL 交叉注意力: 文本条件注入

多阶段训练:
  Stage 1: 17 帧纯视频预测 (无文本)
  Stage 2: 扩展到 34 帧
  Stage 3: 加入文本条件 (T5-XXL 编码)
  Stage 4: Cooling-down (高质量子集, 线性衰减)

推理优化:
  - KV cache: 标准自回归加速
  - torch.compile: 计算图编译优化
  - Medusa 推测解码: 多头并行预测
  - 实测: 10 FPS @ 320×512 分辨率

Enhancer (增强器):
  问题: 离散 token 化导致像素模糊
  解决: Diffusion Decoder 将离散 token 映射到高质量连续 token
  架构: 微调自 Cosmos-1.0-Diffusion-7B-Text2World
  效果: 显著提升清晰度
```

### 9.2.4 后训练应用

**机器人操作后训练**：

```
基础模型: Cosmos-Diffusion-7B-Video2World
后训练数据: (当前帧, 动作, 指令) → 未来帧 对
条件注入:
  - 当前帧: tokenize → 作为噪声初始化条件
  - 动作: 编码为条件向量
  - 指令: T5-XXL 编码 → 交叉注意力
迭代: O(10K)
产出: 可生成"如果机器人执行动作A，场景会怎样变化"的视频
```

**相机控制后训练**：

```
基础模型: Cosmos-Diffusion-7B-Video2World
条件: Plücker 线嵌入 (编码相机位姿)
训练数据: DL3DV-10K (3D 场景 + 相机轨迹)
应用: 给定相机轨迹 → 生成对应的场景视频
评估: 在 RealEstate10K 上显著优于 CamCo
```

**自动驾驶后训练**：

```
基础模型: Cosmos 预训练 WFM
条件: 车辆轨迹 + 传感器数据
训练数据: 驾驶视频 + 轨迹标注
应用: 给定自车轨迹 → 生成周围环境视频
```

### 9.2.5 GR00T Blueprint 中的 Cosmos

Cosmos 在 GR00T Blueprint 中的应用：

```
Stage 3 (Neural Trajectories):
  输入: 少量种子演示 + 3D 场景
  ↓
  Cosmos Predict2 WFM: 生成合成视频轨迹
  Cosmos Reason: 基于物理的响应
  ↓

  等价于: 6500 小时人工演示 (590× 加速)
```

### 9.2.6 评估结果

| 评估维度 | Cosmos 14B | 基准 |
|----------|------------|------|
| 3D 一致性 (Sampson 误差) | 接近真实视频 | VideoLDM 显著差 |
| 物理一致性 (像素级) | 直觉物理理解良好 | 复杂动力学仍有困难 |
| 相机控制 (FID/FVD) | 显著优于 CamCo | — |
| 机器人操作 | 可生成合理操作视频 | 需与真实数据混合 |
| 推理速度 (AR+Medusa) | 10 FPS @ 320×512 | — |

### 9.2.7 工程教训

1. **扩散和自回归各有优劣**：扩散像素质量高但慢；自回归快但需增强器
2. **渐进训练是大视频模型标配**：512p→720p 节省大量计算
3. **后训练提升整体质量**：不仅特化场景，还提升保真度
4. **安全护栏必须**：Pre-Guard + Post-Guard 防止有害内容生成
5. **Video2World 是 Physical AI 的关键形态**：给定当前观测预测未来

## 9.3 Genie 3：交互式世界模型

### 9.3.1 模型全貌

| 维度 | 配置 |
|------|------|
| 架构 | 自回归 + 潜在动作 |
| 训练数据 | 3000 万视频片段 (无标注) |
| 训练方式 | 完全自监督 |
| 输出 | 720p @ 24fps 交互式 3D 环境 |
| 一致性 | ~1 分钟 |
| 实时性 | 首个实时交互通用世界模型 |
| 发布方 | Google DeepMind |
| 商业应用 | Waymo 自动驾驶仿真, Project Genie |

### 9.3.2 四组件架构

```
┌──────────────────────────────────────────┐
│            Genie 3 Pipeline               │
│                                            │
│  输入视频                                    │
│    ↓                                       │
│  [Spatiotemporal Video Tokenizer]          │
│    将视频帧转换为离散 token                  │
│    ↓                                       │
│  [Latent Action Model]                     │
│    从帧间变化推断潜在动作 a_t                │
│    (无需人工标注!)                          │
│    ↓                                       │
│  [Dynamics Model]                          │
│    自回归预测: (token_t, a_t) → token_{t+1}│
│    ↓                                       │
│  [Renderer]                                │
│    token → 像素帧 (720p)                   │
└──────────────────────────────────────────┘
```

### 9.3.3 训练过程

**完全自监督训练**：

```
数据: 3000 万互联网视频片段
  - 无需标注 (不需要动作标签、环境标签)
  - 视频中自然包含"动作-后果"关系

训练步骤:
  1. Spatiotemporal Tokenizer 学习
     目标: 将视频压缩为离散 token, 保留时空信息
     
  2. Latent Action Model 学习
     输入: (帧_t, 帧_{t+1})
     输出: 潜在动作 a_t (离散编码)
     目标: 学习"什么动作导致了帧间变化"
     方法: VQ-VAE 风格的量化
     
  3. Dynamics Model 训练
     输入: (token_history, a_t)
     输出: 预测 token_{t+1}
     目标: next-token prediction (自回归)
     
  4. Renderer 训练
     输入: token
     输出: 像素帧
     目标: 高质量视频重建

端到端微调:
  所有组件联合优化
  无游戏引擎参与
```

### 9.3.4 推理与交互

```
用户输入: 文本提示 ("一个有河流的森林")
  ↓
初始帧生成 (Nano Banana Pro 预览)
  ↓
用户进入交互模式:
  - WASD: 移动
  - 箭头键: 相机控制
  - 空格: 垂直移动
  - 文本命令: "下雨" "天黑" "加一棵树"
  ↓
实时生成:
  每帧: (帧历史, 用户动作) → Dynamics Model → 下一帧
  频率: 24 fps
  分辨率: 720p
  一致性维持: ~60 秒
```

| 维度 | Genie 1 (2024.03) | Genie 2 (2024.12) | Genie 3 (2025.08) |

| 维度 | 2D | 3D | 3D |
| 分辨率 | 低 | 360p | 720p |
| 一致性 | 秒级 | 10-20 秒 | ~60 秒 |
| 交互 | 基础 | 有限 | 实时 + 可提示事件 |
| 物理 | ❌ | 基础 | 涌现物理 |
| 实时性 | ❌ | ❌ | ✅ 24fps |
| 应用 | 研究 | 研究 | Waymo 仿真 + Project Genie |

### 9.3.6 商业应用

**Waymo 自动驾驶仿真**：
- Genie 3 生成多样化的交通场景
- 比手工设计的仿真环境覆盖更多边缘案例
- 可生成"如果行人突然横穿"等危险场景

**Project Genie**（2026.01 上线）：
- Google AI Ultra 订阅服务 ($249.99/月)
- 用户可以用文本生成交互式 3D 世界
- 支持世界探索、世界素描、世界混音三种模式
- 2026.05 全球扩展，集成 Google Street View

### 9.3.7 局限

1. **一致性仅 ~1 分钟**：超过后世界会"遗忘"之前的内容
2. **2D 侧滚动限制**：生成的是 2.5D 侧滚动视角，非真正的自由 3D 导航
3. **物理近似**：涌现物理在复杂场景下不准确
4. **动作映射模糊**：潜在动作到用户控制的映射需要用户自己"学习"
5. **无公开 API**：仅限 Google 平台使用

## 9.6 小结

三大世界模型的训练实践揭示了不同范式的优劣：

1. **V-JEPA 2 证明了潜在空间预测的力量**：最高效、最鲁棒，62h 数据实现零样本规划
2. **Cosmos 证明了像素生成的实用价值**：GR00T Blueprint 的 590× 加速是合成数据的里程碑
3. **Genie 3 证明了自监督交互式世界的可行性**：3000 万无标注视频 → 实时 3D 环境
4. **三种范式互补而非替代**：V-JEPA 做理解/规划，Cosmos 做数据生成，Genie 做交互仿真

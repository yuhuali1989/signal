# 第 6 章 · 商业模式：席位制之后，软件公司按什么收钱

## 6.1 一个正在发生的根本变化

Gartner 在 2026 年 7 月的报告里给出判断：**智能体 AI 正在打破 SaaS 的传统席位许可模式，用户增长与收入增长之间的链条已经断裂。**

随之而来的预测是：

| 机构 | 预测 |
|---|---|
| Gartner | 到 2030 年，至少 **40%** 的企业 SaaS 支出将转向**按用量、Agent 或结果计价** |
| IDC | 到 2028 年，**70%** 厂商将调整纯按席位的定价模式；席位制定价**基本过时** |

**变化的本质**：企业买的不再是"工具的使用权"，而是"**工作被完成的结果**"。

## 6.2 定价实验对照表：六家厂商，六种货币

这是本章最有价值的一张表。注意最后一行——**没有两家是一样的**。

| 厂商 | 计价货币 | 具体价格 |
|---|---|---|
| **Salesforce** | 自主解决次数 + Flex Credits + 标准动作 + per-user add-on | **$2 / 次自主解决对话**；Flex Credits 约 **$500 / 10 万**；标准动作约 **$0.10**；per-user add-on **$125–550/月**（Agentforce 1 Edition 为 **$550/用户/月**） |
| **HubSpot** | 解决对话数 | **$0.50 / 次解决对话** |
| **Intercom** | 结果达成 | **不成功不收费**（outcome landed 才计费） |
| **Microsoft** | Copilot Credits | **$0.01 / credit** |
| **SAP** | AI 动作池 + 超额 agent run | 每个 Advanced Full User Equivalent 约含 **200 个 AI 动作**；超出后 agent run **$0.40–1.80** |
| **Workday** | Flex Credits（按 agent skill 分级） | **1 credit**（信息检索）→ **750 credits**（人才库线索识别） |
| **ServiceNow** | Action（经 Action Fabric 执行） | **按 action 计量**（COO 已确认） |

**Salesforce 甚至发明了自己的工作量单位：AWU（Agentic Work Unit）**，用于衡量 Agent 实际执行的离散任务。累计已执行 **70 亿个 AWU**，第二财季 32 亿个，环比 **+97%**。

## 6.3 四种新计价货币的取舍

抽象一下，所有实验都逃不出这四类：

| 货币 | 优点 | 缺点 | 适合场景 |
|---|---|---|---|
| **按用量**（token/credit/API 次数） | 简单、易计量、与成本挂钩 | 客户无法预测账单；与业务价值脱钩 | 基础设施型能力 |
| **按动作**（action/task） | 直观、与工作量挂钩 | "一个动作"的定义权在厂商手里，易争议 | 流程自动化 |
| **按结果**（问题解决/对话解决） | **客户最爱**，风险最低 | 结果定义与归因困难，厂商承担全部风险 | 客服、IT 支持等边界清晰的场景 |
| **按价值分成** | 上限最高 | 极难审计，几乎无人真正做到 | 极少数场景 |

**关键判断**：Intercom 的"不成功不收费"对客户最友好，但对厂商要求极高——你必须能**定义什么叫成功**。所以按结果付费并不会一统天下，它只适用于**结果边界清晰且可自动判定**的场景（如"对话是否被解决"、"工单是否关闭"）。

反之，在财务、供应链这类**结果难以单一归因**的场景，按动作/用量仍是主流。

## 6.4 新出现的商业模式：收费站（Toll Booth）

这是 2026 年最值得关注的一个商业模式创新，也是传统软件厂商最有力的反击。

### 逻辑

当一个外部 AI Agent 要访问你的系统数据或执行工作流时，**它必须走你的通道**——于是你可以按调用收费。

SAP 已经把这条写进了政策：**SAP API Policy v4 Section 2.2.2 禁止外部 AI Agent 未经 SAP 技术栈独立调度 API 调用。** 只允许 Joule（SAP 自家 Agent）在许可侧通行。

### 为什么这个模式威力巨大

一个 Agent 在一个月内可能产生 **5 万次 API 调用**。原本这些活动是"隐形"的（人在界面上点几下，不产生额外费用），现在通过计量变成了显著账单。

换句话说：

> **Agent 越活跃，厂商收入越高。** 原本"减少席位"的威胁，被转化成了"增加调用"的收入。

ServiceNow 的 Action Fabric 与 Workday 收紧 API 治理（影响约 30 家企业，含高盛、摩根大通、Salesforce），都是同一策略。Workday CEO 直言：**对 Agent 访问收费具有可观的财务上行空间。**

### 这个模式的成立条件

不是谁都能收过路费，需要三个前提：

1. **你掌握别人绕不开的数据或流程**（记录系统层的位置）
2. **你的 API 是事实标准**（客户和 Agent 都依赖它）
3. **你能计量并强制执行**（技术上有能力管控调用）

第 4 章的结论在这里闭环了：**走"AI 原生"路线的一个隐藏收益，就是保住了收费站的资格。**

## 6.5 解读金蝶的目标：2030 年 AI Native 收入占比 50%

把金蝶的目标放进本章的坐标系，能读出三层含义。

**第一层：这是结构目标，不是增长目标。**
不是"AI 收入涨到多少"，而是"**占比过半**"。这意味着存量业务的相当一部分要被重新定义为 AI 原生收入，或者被 AI 原生业务替代。

**第二层：它要求存量客户的 AI 转化率。**
Salesforce 的经验值得参考：**超过 50% 的 Agentforce 和 Data 360 订单来自存量客户**。也就是说，AI 收入的主要来源不是新客户，而是**把老客户升级**。金蝶有 6.5 万家企业客户基础（苍穹），这是它做这件事的本钱。

**第三层：它要求定价模式同步切换。**
如果 AI Native 收入占比要到 50%，那么计价方式必须能从"按模块许可"切到"按 Agent/动作/结果"。否则 AI 收入只能以"加购包"的形式存在，规模上不去。

## 6.6 转型期的定价现实：多轨并行，采购变难

一个诚实的观察：**当前没有统一货币，各家都在试。**

Salesforce 甚至同时用四种方式卖 Agentforce（按对话、按 credit、按动作、按用户）。这带来一个副作用：

> IT Pro 报道，企业现在必须建模 **token、credit、action 和可变 AI 消耗**，而不再只是数席位。**采购变得更难，而不是更容易。**

**给厂商的实务建议**：
- 短期：保留席位 + AI 加购的双轨（Salesforce 的做法），降低客户决策门槛
- 中期：给出**可预测的混合包**（如 SAP 的"200 个 AI 动作 + 超额单价"），解决客户对账单不可控的恐惧
- 长期：向结果计费收敛，但只在结果可自动判定的场景先做

**给采购方的建议**：要求厂商提供**消耗模拟**（按月预估账单区间），并在合同中约定超额上限——因为 Agent 消耗的波动性远高于席位。

## 6.7 本章小结

- **席位制的经济基础已被打破**：40% 支出将转向按用量/Agent/结果（Gartner），70% 厂商将调整定价（IDC）。
- **六种货币并存，没有标准**：Salesforce $2/次解决、HubSpot $0.5、Intercom 不成功不收费、Microsoft $0.01/credit、SAP 动作池 $0.40–1.80 超额、Workday Flex Credits 1–750 分级。
- **「收费站」是最有力的反击**：把 Agent 的 API 调用变成收入（SAP API Policy v4 已明文限制外部 Agent），前提是掌握绕不开的数据与流程。
- **金蝶 50% 目标是结构目标**：依赖存量客户升级（Salesforce 50%+ 订单来自存量）、6.5 万客户基础、以及定价模式的同步切换。
- **现实是多轨并行，采购难度上升**——厂商要给可预测的混合包。

# 第 5 章 · 多模态主干：统一序列、解耦路线与冻结时机

## 5.1 两条路线，半年里都没被淘汰

| | 早融合统一序列 | 理解 / 生成解耦 |
|---|---|---|
| 做法 | 文本、音频、视觉进同一条序列、共享主干注意力 | 理解走连续 encoder，生成走独立分支/解码器 |
| 代表 | Chameleon、Emu3、Qwen-Omni 类、Higgs 前台 | **Janus-Pro**（07-12 站内解读）、LLaVA 系 + codec、Wan/Sora 类 |
| 优点 | 参数最省、跨模态交互上限最高、一个 next-token 目标 | 理解侧不量化、保真；生成侧可换 tokenizer 不受拖累 |
| 代价 | 需要海量混合数据；语言能力容易被多模态梯度拉扯 | 两套表示要对齐、融合深度受限于插入层 |

半年里最值得记的不是「谁赢了」，而是**两条路线都被量产验证过，且分界线更清楚了**：要不要让理解侧和生成侧共享同一个离散符号空间。站内《全双工全模态工程全书》ch12 把这条判据写成两问（token 离散还是连续、ID 查主干还是只喂 decoder），这里不再重复推导，只看半年里新增的证据。

## 5.2 ★语言部分什么时候冻、什么时候放

这是用户前几轮反复追问、而 11-06 Qwen3.9-VL 终于给出公开规格的问题【站内 factSheet】：

| 阶段 | 文本配比 | LLM（语言部分） | 学习率 |
|---|---|---|---|
| 阶段一 | **62%** | 参与训练 | 基准 |
| 阶段二 | **48%** | 参与，但配比下调 | 基准 |
| 阶段三 | **55%** | 回升保语言 | — |
| 模态对齐预训练 | — | **全冻** | — |
| 指令微调 SFT | — | **解冻全参** | **压到纯文本阶段的 1/20** |

配套结论：**文本占比低于 50% 即出现可测的语言退化**；最终 MMLU / 数学 / 代码与纯文本基座持平（未退化）。

三条能直接迁移的经验：

1. **对齐阶段冻 LLM 是有理由的**：这一阶段只需要让 projector 学会「把视觉特征翻译成 LLM 能懂的词」，动 LLM 反而引入灾难性遗忘；
2. **SFT 必须解冻**：任务变复杂（对话、推理、OCR、指代），光靠 projector 的翻译不够；但要用 1/20 的低 LR 解冻，避免视觉梯度冲掉语言能力；
3. **配比是调度量不是常数**：62%→48%→55% 先降后升，用文本数据当压舱石。这正好解释了前几轮讨论的「caption 语料为什么不够」——caption 语言分布太窄（描述性短句、无推理/代码/长文档），文本占比不只是数量问题，更是**分布覆盖问题**。

> 【推断】把「50% 红线」读成通用常数是过度外推：它是 Qwen 这份报告在自家配比与基座下的观测值。本书把它当作「存在一条分布红线」的证据，而不是所有模型的配置表。第 10 章会展开数据侧。

## 5.3 长视频：不靠窗口硬扛，靠检索召回

Qwen3.9-VL 支持 **2 小时视频输入**、长视频 QA 榜第一，做法不是把两小时全帧塞进上下文，而是：

```
视频 → 关键帧 CLIP 向量 → 检索召回 → 少量帧进 LLM
```

【站内 factSheet】。这条路线和站内《万亿 CLIP 向量检索》那篇的技术栈完全咬合：1T × 768d fp32 ≈ 3.07PB，靠 MRL/PCA 降维 → PQ 量化 → IVF 分区（或 SPANN 单机万亿）压到可查规模。**检索不是被参数化取代，而是被换了个位置：从「模型的上下文」挪到「模型前面的数据层」**。

视频 token 的三层压缩也成了共识（站内全双工全书 ch04）：空间切 patch → 时间合并帧（tubelet / 3D 因果 VAE）→ 语义 resampler 固定预算。关键差别在于：

| 侧 | 表示 | 有无词表 |
|---|---|---|
| 理解侧（VLM 输入） | 连续 `[d]` 向量 | **通常没有**，`Conv2d` 算出来 |
| 生成侧（视频输出） | 离散 ID 或连续 latent | 离散路线有 codebook；DiT 路线无 |

Hugging Face 上 Emu3 是理解侧也查表的反例（`codebook_size=32768`、`vocab_size=184622`），MAGVIT-v2 / Cosmos Tokenizer 则是有码本但只喂 decoder 的第三类。详见站内《全双工全模态工程全书》ch12 的四种组合表。

## 5.4 全双工：从「能打断」到「时间片 + 后台并行」

半年里这条线的节奏很清楚【站内】：

| 时间 | 事件 | 架构含义 |
|---|---|---|
| 07-09 | GPT-Live 全双工语音，可随时打断 | 交互节奏成为能力 |
| 08-05 | 字节 SeedRealtime，原生音视频全双工，豆包全量上线 | 视觉进全双工 |
| 09-10 | OpenAI 三连发含 GPT-Live-1 | 前后台分离（前台流畅、后台深度推理） |
| 11-05 | Boson **Higgs Realtime Duplex** | **160ms chunk + 六条泳道 + 前后台异步** |

Higgs 把设计推到最具体（站内《Higgs Realtime Duplex 深度拆解》全书）：每片 160ms、音频入 1 token / 出 2 frames、视频每 6 片 1 帧约 12 token、面部 2 latent，合计约 **7 槽位/片 × 375 片 = 2.6K token/分钟**；输出侧连续 latent 配因果流匹配 + 因果 DiT；参考音频/图只进 decoder；前台自己思考与调工具，结果以 payload 回灌输入 chunk。

**半年趋势的判断**：全双工的竞争已经不在「延迟数字」，而在**一条时间轴上能同时跑几条流、慢任务会不会阻塞快流**。语音/视频 token 的定义也随之从「压缩率最高」改成「时间可对齐 + 因果流式 + 速率恒定 + 双流不打架」——token 的第一属性变成时间戳。

## 5.5 统一词表 vs 连续 latent：分界线更清楚

| | 统一离散词表 | 连续 latent + 生成解码 |
|---|---|---|
| 词表 | 一张大表按区间切分（文本/视觉/音频/控制） | 无词表 |
| 输出 | 一个 head softmax 采样，logits mask 切状态 | 因果流匹配 / DiT / 流匹配采样 |
| 代表 | Emu3、Chameleon、早期融合 Omni | Wan2.6、Sora、FLUX、Higgs |
| 适合 | 要一个 next-token 吃下所有模态 | 画质优先、实时输出、避免码本坍缩 |

近半年的证据偏向后者用于**生成侧**：Wan2.6 用 3D 因果 VAE + DiT 拿到 VBench-2.0 90.2（第 6 章），Higgs 用 2 个 latent 配因果 DiT 做实时面部。原因在第 6 章与站内 ch12 都讲过：2D 逐帧 VQ 会闪烁（Phenaki 对照 FVD 306.1 vs 65.78）、码本会坍缩、非因果卷积会泄漏未来帧。

但**理解侧仍有大量模型用离散 ID 且查主干表**（Emu3 就是），所以正确说法始终是「按路线选」，不是「业界不用词表」。

## 5.6 数据侧伏笔：音视频对齐标注成了新瓶颈

全双工与长视频把数据要求推高了一档：

- 需要带**重叠语音、附和、打断、静音、音视频共时事件**标注的语料；
- 需要绝对时间 ID 而不是 token 序号（跳帧后序号会漂移）；
- 需要「哪句话不是对模型说的」这类指向性标签（Higgs 得来速 demo）。

这些都是标注规范问题，不是模型结构问题。第 11 章会把「流式 chunk 的标注与存储」接到多模态 pipeline 上，这里先立一个判断：**和前几轮 VLA 的结论一样，数据分布决定能力边界，架构只是给它让路。**

## 5.7 决策表与回到 Hy4

| 你的目标 | 选 | 理由 |
|---|---|---|
| 复用现成 LLM、理解保真 | 连续投影 + 解耦 | 不量化、材质/OCR 细节损失最小 |
| 一个 next-token 统一理解与生成 | 统一离散词表 | 训练目标最干净，代价是量化与 head 膨胀 |
| 长视频问答 | 关键帧向量检索召回 | 2 小时视频不可能全帧进上下文 |
| 实时交互且要出画面 | 连续 latent + 因果 DiT | 每片算力恒定、避开逐帧闪烁 |
| 多模态训练保语言能力 | 对齐冻 / SFT 低 LR 解冻 + 文本配比 ≥50% | Qwen3.9-VL 公开配方 |

**回到 Hy4**：锚点本身是文本/代码 LLM，不是多模态模型；但腾讯这条线在 10-30 补了 **Hy-Vector-3**（MRL 套娃 + int8 原生的向量模型【站内】），恰好落在「长视频关键帧召回」所需的数据层。也就是说，半年里头部团队不是只堆一个全能模型，而是**主干 + 检索 + 生成解码器分层铺开**——这个分层本身就是第 12 章要收的趋势之一。

## 5.8 本章小结

- 早融合统一序列与理解/生成解耦两条路线并存，分界在「理解侧与生成侧是否共享离散符号空间」。
- ★Qwen3.9-VL 公开配方：文本配比 62%→48%→55%、对齐阶段 LLM 全冻、SFT 以 1/20 LR 解冻、低于 50% 出现可测退化；50% 是观测值不是通用常数。
- 长视频靠 CLIP 关键帧检索召回而非全帧灌入；检索从模型上下文挪到前置数据层。
- 全双工从「能打断」走到 160ms chunk + 六条泳道 + 前后台异步；token 第一属性是时间戳。
- 生成侧近半年偏向连续 latent + 因果解码；理解侧离散查表仍是合法路线。
- 音视频共时标注成为新瓶颈，接第 11 章。

## 5.1 前提认知：基座模型当前不够用，但可以先落地

2026 年的现实是：**基座模型能力仍在爬坡，但产业已经要交付**。业界摸索出的务实思路是——**不硬等模型变强，而是用工程方法降低对模型的要求**。

本章的四种方法都在做同一件事：**把「一个模型解决所有问题」改成「模型只解决它擅长的部分」**。

## 5.2 ★ 方法一：元技能拆解与组合编排

**思路**：不要求模型直接完成复杂长任务，而是定义一组**原子技能（元技能）**，由上层做组合编排。

```
复杂任务：「把 A 箱里的零件装到 B 位置」
   ↓ 拆解
元技能库：[识别] [定位] [抓取] [移动] [对准] [插入] [旋紧] [放置] [校验]
   ↓ 编排（LLM / 规划器 / 状态机）
执行序列：识别→定位→抓取→移动→对准→插入→旋紧→校验
```

| 好处 | 说明 |
|---|---|
| ★降低泛化要求 | 模型只需在**原子动作**上可靠，不必端到端搞定长链条 |
| 可测试 | 每个元技能可单独测成功率、单独优化 |
| 可替换 | 某个技能用传统方法更好就换掉（配合 5.4 精度分层） |
| 失败可定位 | 长链条失败时能定位到具体哪一步 |

> 这是当前**工业落地最主流的方法**——它承认基座模型的局限，用工程结构补齐。

## 5.3 方法二：用 LLM 的代码生成能力加速现场工程

**思路**：让大模型不做控制，而是做**工程加速器**：

| 用途 | 说明 |
|---|---|
| 现场模型微调 | 生成微调脚本、数据准备代码，减少工程师手工调试 |
| 控制代码生成 | 生成传统控制/胶水代码（不需要模型的部分） |
| 任务调度与编排 | 把自然语言任务描述转成执行序列 |
| 故障诊断 | 读日志、定位失败原因、给出修复建议 |

**价值**：把「专家现场调机」的高人力成本压下来——这对规模化部署的经济性至关重要。

## 5.4 ★ 方法三：精度分层（最实用的一招）

**思路**：**不同精度要求交给不同能力层**，不要指望一个模型从粗到精全包。

| 层级 | 交给谁 | 理由 |
|---|---|---|
| **粗操作**（拣选、移动、大致对准） | **VLA / VLM** | 需要语义理解与泛化，模型擅长 |
| ★**精定位**（毫米级对准、精密插入） | **传统视觉方法 / 小模型 / 力控** | ★传统方法在结构化高精度场景下**比大模型更准、更快、更可验证** |
| **安全与合规校验** | 规则引擎 / 传感器硬约束 | 不能交给概率模型 |

```
典型落地形态：
  VLA 负责「找到并抓住那个零件」（粗）
      ↓ 交给
  传统视觉 + 力控负责「对准并插入」（精）
      ↓
  规则引擎负责「力矩超限即停」（安全）
```

> ★**这一条是很多团队的破局点**：把 VLA 用在它擅长的「理解与泛化」上，把「确定性精度」交回传统方法。**端到端不是目的，可靠才是。**

## 5.5 方法四：NVIDIA「三台计算机」架构

黄仁勋提出的物理 AI 计算架构，把闭环拆成三类计算系统：

| 计算机 | 职责 | 对应能力 |
|---|---|---|
| **第一台** | **大规模训练与数据生成** | 把算力转化为物理世界的经验（VLA 预训练、世界模型训练） |
| **第二台** | **高保真仿真与数字孪生** | 机器人在虚拟产线预训练与测试（Isaac Sim / Cosmos） |
| **第三台** | **边缘端实时推理与安全控制** | 部署在机器人本体上，负责实时性与安全 |

> 这套划分的价值在于：**它明确了「训练」「仿真」「部署」是三种不同的算力需求，不该混为一谈**。做预算和架构规划时按这三类分开算，更清楚。

## 5.6 端云协同：端侧实时 + 云端深思

对应第 3.5 节的系统 1 / 系统 2：

| 层 | 跑什么 | 约束 |
|---|---|---|
| **端侧（机器人本体）** | VLA 快反应回路、安全兜底 | ★10–100 Hz、功耗受限、断网也要能安全停下 |
| **云端 / 边缘服务器** | 世界模型规划、大模型推理、重训练 | 秒级可接受；断网时端侧必须能降级运行 |

**设计铁律**：

1. ★**端侧必须能独立安全运行**——云端不可达时，机器人要能**安全停机或降级**，不能失控
2. **云端结果带时效与置信度**——过期或低置信的规划结果不执行
3. **网络不是控制回路的一环**——实时控制绝不能依赖往返延迟

## 5.7 ★ 降级与兜底：让不完美的模型可用

既然模型做不到 99.9%，就要设计**「什么时候不用模型」**：

```
模型输出 → 不确定性估计
   ├─ 高置信  → 执行
   ├─ 中置信  → 执行 + 加强监控 / 降速
   └─ ★低置信 → 降级：
          ① 切换到保守策略（慢速、小步长）
          ② 切换到传统控制/规则
          ③ 安全停机并请求人工
```

| 兜底层 | 说明 |
|---|---|
| **不确定性估计** | 模型要能说「我没把握」（集成、MC Dropout、置信度头） |
| **规则硬约束** | 力矩/速度/空间限位——**不经过模型，硬件层直接生效** |
| **人工接管** | 遥操作通道常备（也用于数据采集） |
| **★可复现的失败记录** | 每次降级都记录现场数据 → 回流训练（接第 7 章数据飞轮） |

> ★**核心思想**：**不要用模型去保证安全，用架构去保证安全。** 模型负责「有多聪明」，架构负责「最多错到什么程度」。

## 5.8 本章要点

- 务实前提：**基座模型仍在爬坡**，用工程方法降低对它的要求，而不是等它变强。
- ★**元技能拆解**：复杂任务拆成原子技能 + 上层编排 → 降低泛化要求、可测试、可替换、失败可定位。
- **LLM 做工程加速器**：生成微调脚本、控制代码、任务编排、故障诊断——压低现场调机的人力成本。
- ★**精度分层**：粗操作给 VLA/VLM，**精定位还给传统视觉/力控**，安全交给规则硬约束。**端到端不是目的，可靠才是。**
- **三台计算机**：训练 / 仿真 / 边缘部署是三种算力需求，规划时分开算。
- **端云协同铁律**：★**端侧必须能断网独立安全运行**；实时控制不依赖网络往返。
- ★**降级与兜底**：不确定性低→保守策略/传统控制/停机；**不要用模型保证安全，用架构保证安全**。

# 第 1 章 · 五个来源、四级证据与一个贯穿例子

## 1.1 一句话结论

> **Higgs Realtime Duplex 真正公开的，不是一个更强的模型，而是「六条泳道在一条时间轴上并行、且慢任务不阻塞快流」的预算账本。它买到的是交互节奏，不是智能水平。**

这本书不做产品评测，也不预测全双工的未来。它只做一件事：把 2026-11-05 Boson AI 公开的那套架构，连同它依赖的基础组件（MoE、chunk-causal、因果流匹配、因果 DiT、GQA、渐进 compaction、MOPD、RSI 闭环）逐层拆开，每个数字都标明出处与可信度。

## 1.3 ★四级证据标注纪律（本书的核心规矩）

上一轮写《全双工全模态工程全书》时踩过一个坑：把「本书所选方案 B 不查表」写成了「视频理解侧没有词表」，最后被 Hugging Face 上的 Emu3、MAGVIT-v2 实例打脸，专门补了一章校准。这本书从第一章就把证据等级写死，全书的每个数字都带标签：

| 标签 | 含义 | 例子 |
|---|---|---|
| **【官方】** | 博客或 docs 正文明确写出 | 160ms chunk、45B MoE、2T token、每片 1 音频 token 入 / 2 出 |
| **【图注】** | 博客配图里的数字，正文未复述 | 每分钟 375 / 750 / 750 / 750、5 分钟窗口 13K~25K |
| **【推断】** | 由官方数字反推的 shape、比例、配置 | 24kHz × 0.16s = 3840 samples、每片约 7 token、KV cache 量级 |
| **【未公开】** | 官方明确没给，本书列出清单但不臆造 | expert 数、active 参数、词表、端到端延迟、定价 |

**凡是【推断】，本书都会给出算式；凡是【未公开】，只在清单里出现，绝不偷偷变成配置表里的一个数。** 这条纪律也是全书与那本教学基准书的最大区别：那边为了讲清机制可以构造 75840 词表和 87 槽位，这边必须区分「Boson 说了什么」和「我们算出了什么」。

## 1.4 三个设计目标与两条硬约束

官方开篇给的是三个必须**同时**满足的目标：

| 目标 | 官方表述 | 可核查的锚 |
|---|---|---|
| **Feels human** | 人类对话中，响应通常在对方说完后 **200ms** 内落地；有时甚至提前；人会附和、插话、帮忙接话、对不是对自己说的话保持安静 | 200ms【官方】是**人类统计**，不是模型延迟 |
| **Smart** | 多数对话是为了把事办成，需要情商（读懂人和场景）与真实推理（把模糊请求拆成任务并执行） | 对应前台自思考 / 工具 / 委派三条路径 |
| **Costs little** | 说话会成为人与 Agent 协作的主要方式，每天数小时；设计目标是 **1 小时模型时间 ≤ 1 小时人工成本的 1/10** | 【官方】是设计目标，不是已公布账单 |

两条派生出来的硬约束，后文反复用到：

1. **全双工每片都在算**，连没人说话时也一样——官方原话 `In full duplex the model processes every chunk, even when nobody is talking, so the context fills fast`。所以上下文不是「聊天变长才涨」，是**墙钟一走就涨**。
2. **每片必须算得完**。任何一步超过 160ms，输入流就堆积、双流立刻失步。这决定了主干规模、解码器步数、以及为什么不能用「多跑几步扩散换画质」。

## 1.5 贯穿全书的例子：Hands-free engineering 的一个时间片

官方四个 demo 分别是：团队会议（讲架构、被中途提问、读白板、边讲边改图）、英语口语教练（计时看图说话、抓出 west/vest、看口型纠音）、得来速（司机点单时保持安静、取餐时确认「司机从没点 animal-style fries」）、以及 **Hands-free engineering**。

本书选最后一个作为唯一贯穿案例，因为它同时覆盖了全部机制：

> 工程师全程在读书。只用语音，模型 diff 两个引擎版本 → 让 Claude Code 在后台造一个缺失的 mass 工具 → 工具还在造的时候跑合规检查并应用修复 → 按指示给设计师发邮件 → 工具落地后报出新的质量数值。

为了能算，本书把它显式化成一条 160ms 时间轴，**并明确标注：以下毫秒编号、片序号、token 排布是本书为讲清机制的推演，官方只给了 demo 描述**：

```
t=3040ms  工程师在读书（静音；摄像头帧照常流入）
t=3200ms  ★本书的锚点片：工程师说「先别看价格，重点比维护成本」
t=3360ms  前台起推理线程，判定旧任务参数失效
t=3520ms  异步发出工具调用，结果尚未返回
t=3680ms  前台开口「好，我按维护成本重算」，同时继续读摄像头
t=3840ms  工具结果 part 1 作为 payload 落进输入 chunk
t=4000ms  part 2；前台不等完整结果就开始说进度
t=4160ms  part 3；模型报出新数值
```

后面每一章都回到的就是 `t=3200ms` 这一片：第 3 章算它装了几个采样点、第 4 章算它在每分钟预算里占几格、第 5 章把它排成一条序列、第 6 章算主干跑一次前向的成本、第 7 章看它输出的两个 latent 怎么变成声音和脸、第 9 章看它的工具结果怎么在 3840ms 回灌。

## 1.7 本章小结

- 五个来源里只有官方博客是一手规格；李沐视频公开渠道只有 44 分钟分享的描述，无逐字稿；官方 docs 属于上一代产品，只能作对照。
- 四级标签【官方】【图注】【推断】【未公开】贯穿全书，【推断】必须给算式，【未公开】不得塞进配置表。
- 三个目标（Feels human / Smart / Costs little）派生两条硬约束：上下文按墙钟增长、每片必须在 160ms 内算完。
- 全书只用 Hands-free engineering 一个例子，锚点是推演出来的 `t=3200ms` 片。

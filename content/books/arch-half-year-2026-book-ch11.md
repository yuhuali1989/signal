# 第 11 章 · 数据侧（二）：WebDataset、bin/idx 与合规管线

第 10 章管「语料是什么」，本章管「怎么存、怎么读、怎么合规」。这里会用到一个贯穿判断：**多模态数据工程的复杂度，主要来自「不同模态的表示形态不同」，而不是数据量大**。

## 11.1 摄取层：Ray Data 成了事实标准

半年里这条线的事件密度很高【站内】：

| 时间 | 事件 | 数字 |
|---|---|---|
| 07-29 | Ray Data 成多模态训练摄取事实标准 | ByteDance **200TB 级批推理**、Spotify 新 ML 平台落地 |
| 07-29 | Ray Data 2.5× 推进 joins / hash-shuffle 与结构化数据 API | 剑指替代 Spark 做 AI 预处理 |
| 07-29 | 论文 `RayData-LLM-Infer`：统一批推理框架 | 吞吐 **2.8×** |
| 07-29 | Rubin 上 Object Store 溢出路径优化 | 多模态预处理吞吐 **+1.6×** |
| 10-13 | **Ray 3.0 GA**：数据加载与推理引擎统一调度 | 离线批 GPU 利用率 **61%→95%** |

**61%→95% 是本章最重要的数字**：它说明离线批推理的瓶颈往往不在 GPU 算子，而在「数据喂不上」。这也是为什么第 7 章把集群层列为四层优化栈之一——模型、注意力、调度都优化完，卡在 I/O 上照样白搭。

## 11.2 ★两条存储路线的分野

这是用户前几轮专门研究过的问题，这里按半年工程实践整理成对照表（【通用工程事实】，非某厂商规格）：

| 维度 | **Megatron-LM 系：WebDataset + Energon** | **DeepSpeed / 常见 LLM 系：JSONL + 自定义 Dataset** |
|---|---|---|
| 存储单元 | tar shards，样本内多文件按 key 对齐（`001.jpg` / `001.txt` / `001.json`） | 每行一个 JSON 对象 |
| 二进制大对象 | 原生支持（jpg/npy/视频片段直接进 tar） | 要么 base64（膨胀约 33%），要么存路径外链（随机小文件 IO） |
| 读取方式 | **顺序流式**读 shard，天然适合多机并行与断点 | 按行解析，文本方便，随机访问一般 |
| shuffle | shard 级 + buffer 级两级；Energon 管样本级编排 | 自己实现 shuffle / 分布式 sampler |
| 配比调度 | Energon 支持多源混合、权重、状态保存 | 需要自己写混合逻辑 |
| 断点续训 | worker 状态可保存 | 依赖自定义 checkpoint |
| 适合 | 大规模多模态预训练、图文/音视频混合 | 纯文本 SFT、小规模实验、快速迭代 |

**Energon 的位置**要说清：它是 WebDataset 之上的**数据集编排层**，负责多源混合、shuffle、worker 分配与状态保存；WebDataset 只管「把样本打成 tar 顺序读」。两者不是竞争关系。

> 【推断】半年里的趋势不是「谁取代谁」，而是**分工固化**：纯文本/小规模继续用 JSONL（改动快、可读性高），大规模多模态预训练转向 WebDataset+Energon（二进制原生、顺序 IO、配比可编排）。选型判据是「样本里有没有大二进制 + 要不要多源配比」，不是框架信仰。

## 11.3 ★bin/idx 到底能放什么

Megatron 的 `IndexedDataset` 是 `.bin` + `.idx` 两个文件：

```
.bin  : 已经 tokenize 好的整数 ID 序列（连续拼接）
.idx  : 文档偏移、序列长度、指针、数据类型等元信息
GPTDataset: 从 bin 按 idx 切出固定长度序列 → next-token 训练
```

关键在 **`.bin` 的语义是「token id 序列」**，不是「任意字节」：

| 路线 | 视觉/多模态产物 | 能否直接进 bin/idx |
|---|---|---|
| Chameleon / 统一离散 | 图像经 **VQ-VAE 量化成整数 ID**（如 8192 词表内的 uint16） | **能**，和文本 token 同构，共享统一词表 |
| Emu3 | 视频/图像 → 4096 个离散 token（codebook 32768），词表 184622 | 能，但需 **int32**（词表超 65536） |
| **LLaVA / Qwen-VL 类** | ViT 输出 **float32 连续矩阵** `[N, d]`，经 projector 映射成连续向量 | **不能直接进**（语义不匹配） |

第三行是这几轮反复确认的结论，但要把话说准：**不是「技术上写不进字节」，而是 bin/idx 的消费者（GPTDataset）期望的是 token id，给它浮点特征它不会当 embedding 用**。所以 LLaVA 类路线只有三种选择：

```python
# ① 在线算：训练时现过 ViT（贵，但简单）
feat = vit(image)                        # [N, d] float32
x = projector(feat)                      # 投影进 LLM 维度

# ② 离线另存：浮点特征放进 tar / npy，走 WebDataset（推荐）
# shard-000.tar 内含: 001.jpg, 001.npy (float32 特征), 001.json (元数据)

# ③ 先量化再进 bin：那就变成 Chameleon 路线（丢细节 + 要训码本）
ids = vq_quantize(feat)                  # uint16 ids → 可写 bin
```

**由此得到一条存储层的判据**：`有没有离散 tokenizer` 决定了能不能用统一 bin/idx；`要不要保真` 决定了是否该走 WebDataset 存浮点。第 5 章讲的「统一离散词表 vs 连续 latent」之争，落到磁盘上就是这两种文件格式的差别。

> ⚠️ 词表大小还决定整数宽度：8192 码本的视觉 ID 用 `uint16` 足够；Emu3 的 `vocab_size=184622` 必须用 `int32`。**别把「Chameleon 用 uint16」外推成所有统一词表都用 uint16**。

## 11.4 多模态样本 schema 与绝对时间

四类样本对存储的要求完全不同：

| 样本类型 | 内容 | 关键字段 |
|---|---|---|
| 图文对 | 图 + caption | 图二进制、文本、来源/许可 |
| 交织文档 | 网页正文连图 | 文档顺序、图在文中的位置 |
| 视频片段 | 帧序列 + 音频 | 帧时间戳、音轨、采样率 |
| **流式全双工 chunk** | 一片音频 + 稀疏帧 + 工具 payload | **绝对时间 ID**、stream_id、边界符 |

第四类是半年里新增的（Higgs 160ms 片、GPT-Live / SeedRealtime）。它带来两个以前没有的要求：

1. **时间必须绝对**：跳帧、静音、payload 突增都会让「第几个 token」漂移，所以位置编码用物理毫秒而非序号；
2. **标注必须含交互事件**：重叠语音、附和、打断、旁人对话、背景噪声、「这句话不是对模型说的」——这些是标签，不是原始信号。

可运行的最小 schema 校验：

```python
def validate_chunk_sample(s):
    """流式全双工样本的最低字段【推断：按官方行为描述整理】"""
    req = ["t_ms", "stream_id", "modality", "payload_ref"]
    assert all(k in s for k in req), f"missing: {set(req) - set(s)}"
    assert isinstance(s["t_ms"], int) and s["t_ms"] >= 0     # 绝对毫秒，不是序号
    assert s["stream_id"] in (0, 1)                            # 0 用户流 / 1 模型流
    assert s["modality"] in ("audio", "video", "text", "control")
    if s["modality"] == "video":
        assert "frame_idx" in s and "abs_time_ms" in s          # 跳帧后仍可对齐
    return True
```

## 11.5 检索是数据层，不是模型层

半年里「检索」这个词重新变热（近半年新闻命中 11 次），但位置变了：

| 场景 | 做法 | 站内落点 |
|---|---|---|
| 长视频问答 | 关键帧 CLIP 向量检索召回后再进 LLM | Qwen3.9-VL（11-06） |
| 预训练数据筛选 | DataComp 从 **128 亿图文对**筛高质量子集 | 《万亿 CLIP 向量检索》 |
| 去重 / 版权 / 审核 | pHash + CLIP 语义向量双路召回 | 内容治理三层防线 |
| 向量模型 | Hy-Vector-3（MRL 套娃 + int8 原生，10-30） | 站内模型库 |

存储账（站内文章）：1T × 768d fp32 = **3.07 PB**，靠 MRL/PCA 降维 → PQ 量化（32~64B/向量，压到 32~64TB）→ IVF 分区；千亿到万亿级走 SSD 路线（SPANN：质心 256MB 入内存 + posting list 顺序读）。**两阶段范式**：粗召回 top-1000（recall 90%）→ int8 精排 top-10（recall 98%）→ 可选 VLM 重排。

> 【推断】把这一节与 11.1 的 Ray Data 放一起看，半年里数据系统的形态是：**前面挂检索做筛、中间用 Ray Data 做摄取与批推理、后面按表示形态分流到 WebDataset 或 bin/idx**。模型上下文不再是唯一入口。

## 11.6 治理：从管出口到管入口

| 时间 | 事件【站内】 | 管什么 |
|---|---|---|
| 07-28 | EU AI Act 第三阶段：开源权重须披露训练数据摘要 | 入口披露 |
| 07-29 | 中国 AI 训练数据合规指引：数据摘要 | 入口披露 |
| 10-13 | 信通院隐式标识方案：元数据 + 隐式水印双轨，涉政涉军进强制审核清单 | 出口标识 |
| 11-04 | 网信办训练数据合规指引：**来源披露分级 + 涉政涉军类目白名单制** | **入口白名单** |
| 11-06 | MLCommons 冻结集清单、可变集与榜单重合度披露 | 评估器治理 |

技术栈上要分清两件事（站内《多模态内容治理的三层防线》）：**NSFW 是纯视觉易题**（单个 CNN/CLIP-NSFW 打分可到 95%+），**涉军涉政是「视觉 + 知识 + 语境」难题**——长尾实体、动态政策清单、对抗性改写，开源模型在这块几乎没有覆盖，因为**训练数据本身需要持牌资质**。所以现实架构是混合的：开源模型管色情/暴恐（L1-L2）、云厂商 API 管涉政涉军、人工兜灰区。

配套还有出口侧的单向管控（站内《L7 单向管控》）：HF 下载与 push 的五元组相同，L3/L4 防火墙按方向拦不住，必须下沉到 L7 按 HTTP 方法 + 路径（`git-receive-pack` / `upload` / `commit`）+ 请求体大小三刀切，或干脆自建只读镜像。**治理不消灭动机，只让越界可见、可拦、可追责**——和第 10 章的去重披露是同一句话。

| 事件【站内】 | 数字 |

三条分别对应「写入前没有验收」「评测集与训练集没有隔离」「测量口径没有冻结」。**它们都不是模型问题，全是数据管线问题。**

## 11.8 落地 checklist 与回到 Hy4

```
□ 样本里有没有大二进制？有 → WebDataset tar，没有 → JSONL 可接受
□ 要不要多源配比 / 断点续训？要 → 上 Energon 或等价编排层
□ 视觉表示是离散 ID 还是 float32？离散 → bin/idx；浮点 → 另存 npy/tar
□ 词表是否超 65536？超 → int32，别用 uint16
□ 流式样本是否带绝对时间 t_ms 与 stream_id？
□ 视频/图像是否走了 pHash + 向量双路去重？
□ 冻结集 hash 是否在训练前锁死、可变集重合度是否披露？
□ 涉政涉军类目是否走白名单 + 服务端复检（不依赖端侧自判）？
□ 出口是否按 L7 方法与路径单向管控？
```

**回到 Hy4**：锚点的 RSI 算子回灌，本质也是一条数据管线——候选内核 → 数值等价性测试 → 冻结评估器回归 → 主干合并 → hash 链留痕。它和本章的 WebDataset 摄取、bin/idx 存储、白名单治理共享同一个结构：**先定「什么算合格样本」，再让流水线自动 accept/reject**。半年里数据侧最实质的进步，就是把这些判定从人工检查变成了可执行字段。

## 11.9 本章小结

- 摄取层：Ray Data 成事实标准（200TB、2.8×、+1.6×），Ray 3.0 统一调度把离线批 GPU 利用率 **61%→95%**；瓶颈常在 I/O 不在算子。
- ★两条存储路线：WebDataset（tar shards，原生二进制、顺序读）+ Energon（配比/shuffle/状态）适合大规模多模态；JSONL 适合纯文本与快速迭代。分工固化，不是取代。
- ★`bin/idx` 的 `.bin` 语义是**整数 token id 序列**：Chameleon 量化后的 uint16 能进，Emu3 的 184622 词表要 int32，**LLaVA 的 ViT float32 连续特征不能直接进**（消费者期望 token id）；三条出路是在线算、离线存 npy/tar、或先量化。
- 流式全双工样本新增绝对时间 ID 与交互事件标注；附最小 schema 校验代码。
- 检索前移成数据层（3.07PB → MRL/PCA/PQ/IVF/SPANN、两阶段召回）；治理从管出口走到管入口（白名单 + 来源分级）。
- 数据即攻击面：投毒、污染、注水三条都不是模型问题；落地给 9 项 checklist。

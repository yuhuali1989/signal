# Janus-Pro 论文深度解读：理解与生成解耦，统一多模态基模的数据与模型双缩放

> 选自《Signal 论文解读》系列 · 多模态生成基模方向
> 论文：Janus-Pro, arXiv:2501.17811（DeepSeek-AI, 2025-01-29）
> 定位：一个模型同时做「看懂图」和「画出图」，且两项都强

## 一、统一多模态基模要解决的核心矛盾

一个理想的多模态基模应该像人一样：既能**理解**一张图（看图说话、文档问答），又能**生成**一张图（文生图）。但把这两件事塞进同一个模型，长期存在一个根本矛盾：

> **理解任务需要的是「高层语义特征」，生成任务需要的是「细粒度像素编码」——两者对视觉表示的要求是冲突的。**

早期统一模型（如 Chameleon、原始 Emu）用**同一个视觉编码器**处理理解和生成，结果往往是「两头都不够好」：为了生成而保留的像素细节拖累了语义理解，为了理解而抽象的语义又丢失了生成所需的细节。

Janus 系列的关键洞察就是：**解耦视觉编码（Decoupled Visual Encoding）**。而 Janus-Pro 在此基础上，做了「训练策略 + 数据 + 模型规模」三重升级，把统一模型第一次真正做到了「理解和生成都 SOTA」。

## 二、核心架构：一条 Transformer，两套视觉编码

Janus-Pro 最精妙的设计是：**LLM 主干只有一条，但视觉的「入口」分成两套**。

### 2.1 理解通路：SigLIP 编码器

- 编码器：**SigLIP-Large-Patch16-384**，提取图像的高维**语义**特征。
- 处理：2D 特征网格展平成 1D 序列 → 经 understanding adaptor（两层 MLP）→ 映射到 LLM 输入空间。
- 目标：让 LLM「看懂」图里有什么。

### 2.2 生成通路：VQ Tokenizer

- 编码器：**VQ tokenizer**（来自 LlamaGen），把图像转成离散 ID。
- 参数：codebook 大小 **16,384**，下采样因子 **16**（图像空间压 16 倍）。
- 处理：codebook 嵌入 → 经 generation adaptor（两层 MLP）→ 映射到 LLM 输入空间。
- 目标：让 LLM 能逐 token「画出」图。

### 2.3 统一自回归主干

- 两套编码后的特征拼成一条多模态序列，送入**统一自回归 Transformer**。
- 基座：**DeepSeek-LLM 1.5B / 7B**（对应 Janus-Pro-1B / 7B），最大序列长度 4096。
- 输出头：文本用 LLM 内置头；图像生成用一个随机初始化的独立预测头。

```
理解:  图像 → SigLIP → understanding adaptor ┐
                                             ├→ 统一 Transformer → 文本头 (答案)
文本:  文本 → embedding ──────────────────────┘

生成:  文本 → embedding ──────────────────────┐
                                             ├→ 统一 Transformer → 图像头 (VQ token)
       (自回归逐token) VQ token → gen adaptor ┘
```

> 解耦的本质：**理解和生成用不同的视觉表示，但共享同一个 Transformer 的世界知识和推理能力**——既避免了表示冲突，又复用了参数。

## 三、训练策略：Janus-Pro 相对原 Janus 的三处关键改动

Janus-Pro 沿用了三阶段训练，但每一阶段都做了优化，这是它「更强更稳」的直接原因。

原 Janus 三阶段：
- Stage I：只训练 adaptor 和 image head；
- Stage II：统一预训练（除编码器外都更新）；
- Stage III：监督微调（解锁理解编码器）。

### Janus-Pro 的三处改动

**① Stage I 延长（打好像素基础）**
- 增加 ImageNet 上的训练步数。即便 LLM 参数固定，模型也能先学会像素依赖、依类别名生成合理图像——相当于先给生成通路「热身」。

**② Stage II 聚焦（丢掉 ImageNet 的低效训练）**
- 原 Janus 在 Stage II 把 **66.67%** 的文生图步数花在 ImageNet 类别生成上，效率极低。
- Janus-Pro 直接**丢弃 ImageNet 数据**，改用正常的稠密描述文生图数据，让模型学会「根据详细描述生成图像」。

**③ Stage III 数据配比调整（平衡理解与生成）**
- 多模态 : 纯文本 : 文生图 的比例，从原 Janus 的 **7:3:10** 改为 **5:1:4**。
- 略微降低文生图占比，在保持强生成力的同时**显著提升了理解性能**。

> 这三处改动传递出一个非常实用的经验：**统一模型的性能瓶颈往往不在架构，而在各阶段的数据配比和训练步数分配**。

## 四、数据管道：真实与合成 1:1，双向扩容

Janus-Pro 的第二个 "Pro" 来自数据规模的扩张，理解和生成两侧都补了大量数据。

### 4.1 生成侧：72M 合成美学数据

- 加入约 **7200 万（72M）** 合成美学图像，使统一预训练阶段**真实数据 : 合成数据 = 1:1**。
- 动机：原 Janus 的真实文生图数据质量参差、噪声多，导致生成不稳定、画面脏。合成美学数据（配公开的 Midjourney 风格提示词）干净、审美一致，直接稳住了生成质量。

### 4.2 理解侧：+90M 样本

- Stage II 预训练追加约 **9000 万（90M）** 样本，涵盖：
  - 图像描述数据（如 YFCC）
  - 文档理解数据（如 Docmatix）
- Stage III 补充 DeepSeek-VL2 的额外数据集。

> 合成数据在这里扮演了「质量稳定器」的角色——不是用来补数量，而是用来**替换掉噪声大的真实数据**，这与「质量 >> 数量」的原则完全一致。

## 六、Janus-Pro 在多模态生成基模版图中的位置

当前统一多模态生成有三条主要技术路线，Janus-Pro 代表了「解耦 + 自回归」这一支：

| 路线 | 代表 | 视觉表示 | 特点 |
|------|------|---------|------|
| 统一离散 token（AR） | Emu3、Chameleon | 单一离散 codebook | 极简，但理解生成互相拖累 |
| **解耦编码（AR）** | **Janus-Pro** | 理解 SigLIP + 生成 VQ | 理解生成解耦，两头都强 |
| 混合（AR+Diffusion） | Transfusion、Show-o | 连续 + 离散混合 | 生成画质高，架构复杂 |

Janus-Pro 的价值在于用一个**优雅且可复现**的方案（解耦编码 + 三阶段训练 + 数据双缩放）证明了：统一多模态基模不必在理解和生成之间二选一。

## 七、对工程团队的启示

1. **表示冲突要靠解耦解决**：理解用语义编码器（SigLIP），生成用像素 tokenizer（VQ），共享 Transformer。
2. **性能瓶颈常在数据配比**：Stage II 丢掉低效的 ImageNet、Stage III 调整 5:1:4 比例，都是不改架构就提升性能的关键。
3. **合成数据是质量稳定器**：72M 合成美学数据 1:1 替换噪声真实数据，稳住了生成。
4. **小模型也能打**：Janus-Pro-1B 的 GenEval 0.73 已超 DALL-E 3，解耦范式对参数量友好。
5. **开源可复现**：代码和模型公开，是研究统一多模态基模的优秀起点。

## 4.1 鸿沟一：可靠性（最致命）

| 数字 | 含义 |
|---|---|
| 实验室成功率 **95%** | 在受控光照、固定相机、已知物体下 |
| 部署后掉到 **60%** | 因为光照、纹理、相机角度、物体位姿都变了 |
| 生产要求 **99.9%** | 工业可接受水平 |
| ★**95% 准确率 = 每天失败约 50 次** | 仓库机器人按每小时数十次操作计 |

**这道鸿沟的本质**：模型的泛化能力**填不满真实世界的长尾**。仿真里见过的材质有限，真实产线上有无限种反光、磨损、遮挡组合。

### 应对

| 手段 | 说明 |
|---|---|
| **域随机化** | 仿真中随机化摩擦、质量、光照、纹理，逼策略学鲁棒性（最经典、最常用） |
| **师生蒸馏** | 在仿真中训练有**特权信息**（完美状态估计）的教师，再蒸馏到只能用真实传感器的学生 |
| **数字孪生实时校准** | 用视觉持续监控真实环境，动态调仿真参数与之同步——★**工业部署中最可靠的方法** |
| **真实→仿真→真实闭环** | 少量真实数据 → 校准仿真 → 仿真中大量训练 → 部署回真实 → 持续循环 |
| ★**降级与兜底** | 不追求 100% 模型正确，而是**识别不确定时交给更保守的策略**（第 5.6 节） |

## 4.2 鸿沟二：数据与仿真

物理 AI 的数据瓶颈远大于语言模型——**互联网没有现成的机器人操作数据**。

| 数据获取方式 | 成本/规模 |
|---|---|
| 人类遥操作 | **50–150 美元/小时**；熟练操作员每天约 **200+ 条高质量轨迹** |
| 开源数据集 | **Open X-Embodiment**：100 万条轨迹、22 种机器人、34 个实验室；DROID 7.6 万+轨迹；RH20T 专注灵巧手 |
| ★**第一人称人类视频** | GR00T 的 EgoScale 用了 **21,000 小时**——绕开遥操作瓶颈的新路径 |
| 合成数据 | 程序化生成 + 域随机化；Cosmos Transfer/Predict 等世界模型生成 |

### 数据效率悖论

> 让机器人学会人类认为「很简单」的任务，常需**数万小时**数据；而业界设想的 **1 亿小时第一人称视频**目标，相当于 **150 个人一生**的观看量。

**应对方向**：跨域复用（人类视频预训练）、仿真放大（真实→仿真→真实）、以及**降低对泛化的要求**（第 5 章的元技能拆解）。

## 4.3 鸿沟三：算力与能耗

| 约束 | 现状 |
|---|---|
| **端侧功耗** | 机器人靠电池；大模型端侧推理需高端 GPU，直接推高单机成本 |
| ★**续航** | 人形机器人当前 **90–120 分钟**，工业需求 **8–20 小时**；固态电池规模化预计 **2035** |
| 实时预算 | 控制回路 10–100 Hz，留给模型推理的时间是毫秒级 |

**应对**：

| 手段 | 说明 |
|---|---|
| **小模型专用化** | 3B 级 VLA（π0、GR00T N1.7）成为落地主力而非 70B |
| **量化与蒸馏** | INT4/FP8 量化 + 云端大教师蒸馏（端侧 NPU 100 TOPS 量级下 7B 模型可跑） |
| **★高效架构** | 高 Mamba 占比的混合架构——常数状态、KV cache 不膨胀（第 2.3 节） |
| **少步化生成** | Flow Matching / 扩散的步数压缩 |
| **端云分工** | 端侧跑实时小模型，云端跑深思大模型（第 5.5 节） |

> ★**必须认清的现实**：**电池是硬件侧最难的一道坎，且近期无解**（固态电池 2035）。所以架构必须按「极低能耗」设计，而不是等硬件进步。

## 4.4 鸿沟四：★评估可信度（最被忽视，但最该先解决）

NVIDIA 机器人负责人公开指出：

> 研究者会「**从 100 次失败里挑出最好看的那次演示**」。1% 的成功率在研究中很常见，且人们会选自己模型表现最好的基准子集来报告。

| 问题 | 后果 |
|---|---|
| 挑最好演示 | 报告的成功率≠真实成功率 |
| 选基准子集 | 横向不可比 |
| 缺乏标准化指标 | ★**无法判断领域是否真在进步** |

### 应对（团队内部应先立规矩）

| 做法 | 说明 |
|---|---|
| **成功率必须报「全部试验」** | 禁止 cherry-pick；记录 N 次试验的完整分布 |
| **固定基准与协议** | 场景、初始条件、随机种子写死 |
| **分层报告** | 分「已知物体/未知物体/未知环境」三档报数，别只报最好的一档 |
| **真实环境指标优先** | 仿真分数只作参考，**真实部署成功率才是验收标准** |
| **长期稳定性指标** | 报「连续运行 8 小时的失败间隔（MTBF）」，而非单次成功率 |

> ★**对甲方/决策者的提醒**：看到任何物理 AI 的能力演示，第一句该问的是——**「这个成功率是怎么算的？试了多少次？」**

## 4.5 四道鸿沟的关系

```
       可靠性鸿沟（95% → 60%）
              ↑
  算力能耗鸿沟 ← 数据鸿沟 → 评估鸿沟（掩盖了前三个）
```

**评估鸿沟最特殊**：它不直接造成失败，但它**掩盖了其他三道鸿沟的真实严重程度**，让团队误判进度。所以**先修评估，再修其他**——否则你不知道自己修没修好。

## 4.6 本章要点

- ★**可靠性鸿沟**：实验室 95% → 部署 60%，生产要求 99.9%，**95% ≈ 每天失败 50 次**。应对：域随机化、师生蒸馏、数字孪生实时校准、真实→仿真→真实闭环、★降级兜底。
- **数据鸿沟**：遥操作 50–150 美元/小时；Open X-Embodiment 100 万轨迹；★EgoScale 用 21,000 小时人类第一人称视频绕开瓶颈；数据效率悖论（1 亿小时 ≈ 150 人一生）。
- ★**能耗鸿沟**：人形续航 90–120 分钟 vs 需求 8–20 小时，**固态电池 2035 才规模化 → 架构必须按极低能耗设计**。应对：3B 小模型、量化蒸馏、高 Mamba 混合架构、少步生成、端云分工。
- ★**评估鸿沟**：「从 100 次失败挑最好看的」、1% 成功率常见、基准子集自选。应对：**报全部试验分布、固定协议、分档报告、真实指标优先、报 MTBF**。
- 四鸿沟中**先修评估**——它掩盖了其他三个的真实严重程度。

# 第 3 章 · 稀疏化：参数还在涨，单步为什么反而更便宜

## 3.1 一张表看清这半年的参数账

近半年 `models.json` 里 93 个模型，把公开了总参/激活的挑出来（【站内】）：

| 模型 | 时间 | 总参 | 激活 | 激活比【推断】 | 备注 |
|---|---|---|---|---|---|
| Hy4 preview | 08-28 | 770B | 49B | **6.4%** | 78 层，256 路由专家 + 1 共享，top-8 |
| Kimi K3 Preview | 09-02 | 1T | 48B | **4.7%** | 256K Agent 工作记忆 |
| MiMo-V2.6 系列 | 09-21 | 万亿级 | 未公开 | — | 100 万上下文 |
| IQuest-Q1 | 09-29 | 320B | 15B | **4.7%** | 稀疏 MoE 基座 |
| Mistral Large 4 | 10-07 | 1.05T | 49B | **4.7%** | 仅用 **4000 块 GPU** 训练 |
| Reflection Beam | 10-05 | 501B | 23B | **4.6%** | 开源前沿 |
| Mellum 2.1 | 10-08 | 12B | 2.5B | **20.8%** | 编码智能体，Apache 2.0 |
| Strata | 10-06 | 125B | 未公开 | — | **24576 个小专家**，12GB 显卡可跑 |
| Qwen3.8-Max | 08-03 | 2.4T | 未公开 | — | Arena 全球第二 |
| DeepSeek V4 | 07-24 | 1.6T | 未公开 | — | 峰谷定价 |

两个一眼可见的规律：

1. **总参从 770B 一路涨到 2.4T，激活参数却稳在 15B~49B**。前沿开源模型的激活比收敛到 **4.6%~6.4%** 这个窄区间。
2. **小模型反而更「稠密」**：Mellum 2.1（12B/2.5B）激活比 20.8%，是前沿大模型的 3~4 倍。因为小模型的容量本来就要靠更多激活来撑，没必要为省这点计算付路由开销。

> 【推断】这背后的经济账：全双工与长程 Agent 都是**按墙钟持续付费**的场景，单步成本（≈激活参数）决定能不能开一整天；总参（≈知识容量）可以用显存与存储换。于是「容量涨、单步不涨」成了半年里最一致的架构选择。第 7 章会看到这笔账怎么一路传导到 PD 分离与硬件分池。

## 3.2 可复算：激活比脚本

```python
# 【推断】比值全部由【站内】总参/激活参数算出，1T 按 1024B 近似
models = [
    ("Hy4 preview",        770,   49),
    ("Kimi K3 Preview",   1024,   48),
    ("IQuest-Q1",          320,   15),
    ("Mistral Large 4",   1050,   49),
    ("Reflection Beam",    501,   23),
    ("Mellum 2.1",          12,  2.5),
]
for name, total, active in models:
    print(f"{name:20s} {active/total*100:5.1f}%  单步约 {active}B 参数")
# Hy4 6.4% / K3 4.7% / IQuest 4.7% / Mistral 4.7% / Beam 4.6% / Mellum 20.8%
```

**为什么这个比值比绝对参数更有信息量**：它直接决定单 token 的 FLOPs、单步墙钟、以及能否塞进 160ms 的全双工片（见站内《Higgs Realtime Duplex 深度拆解》第 6 章）。两个都是「万亿模型」，激活 23B 与激活 200B 的部署成本差一个数量级。

## 3.3 MoE 基础：三个旋钮

```python
class MoELayer(nn.Module):
    def __init__(self, d, n_experts, top_k, hidden, shared=False):
        self.router  = nn.Linear(d, n_experts)
        self.experts = nn.ModuleList([FFN(d, hidden) for _ in range(n_experts)])
        self.shared  = FFN(d, hidden) if shared else None   # 共享专家：每个 token 都过
        self.top_k   = top_k

    def forward(self, x):                       # x: [L, d]
        idx = self.router(x).topk(self.top_k, -1).indices
        out = self.shared(x) if self.shared else 0
        for e in range(self.n_experts):
            mask = (idx == e).any(-1)
            if mask.any(): out = out + self.experts[e](x[mask])
        return out
```

半年里被反复调的三个旋钮：

| 旋钮 | 趋势 | 代表 |
|---|---|---|
| **专家数量**（粒度） | 从几十个 → **256 个** → **24576 个** | Hy4（256+1）、Strata（24576） |
| **top_k** | 保持小常数（Hy4 top-8） | 控制单步 FLOPs |
| **共享专家** | 从无到有（Hy4 的 +1） | 承载通用知识，减轻路由负担 |

**细粒度专家化**是这半年最实质的变化：把少数大专家拆成大量小专家，同样的 top_k 能组合出多几个数量级的「专家组合」，表达力上升而单步成本不变。代价是路由表变大、专家分布变散，**跨设备通信成为瓶颈**——于是下一节的 EP 优化就成了刚需。

## 3.4 通信与训练：稀疏化的隐藏账单

MoE 的专家分布在不同卡上，每个 token 要被 dispatch 到 top_k 个专家所在设备再 combine 回来。这半年的公开进展几乎都在补这条链路：

| 事件 | 数字【站内】 | 解决什么 |
|---|---|---|
| DeepSeek 开源 `DeepEP-Ascend` / `DeepGEMM-Ascend`（09-30） | **EP8 dispatch 373 GB/s** | 国产芯片上的专家并行通信 |
| Mistral Large 4（10-07） | 1.05T/49B，**仅 4000 块 GPU** 训练 | 稀疏化把训练集群规模压下来 |
| GLM-5.4（10-28） | **11.3 万张昇腾 910D** 全参训练 | 国产算力上的前沿全参训练迁移 |
| DeepSeek V4-Pro 技术报告（08-30） | **14.8T token**、MuonScale 优化器、成本较 V3 **再降 40%** | 训练配方本身成为公开规格 |
| DeepSeek V4.2（11-03） | **全量 FP8 训练**；loss spike 检测 = 连续 3 步梯度方差超 **8σ** 触发回退 | 低精度训练的稳定性工程 |
| 昇腾 950PR 商用（11-02） | 原生 FP8、互联带宽对标 NVL144 | 硬件侧对齐稀疏化通信需求 |

一个值得单独记的判断：**「训练配方公开」本身成了半年里的一种架构发布**。08-30 披露 14.8T token 与优化器、11-03 披露 FP8 的 8σ 回退阈值、11-06 Qwen3.9-VL 披露三阶段配比——这些都不是分数，而是「别人怎么把它训出来的」。第 10、11 章会把这条线接过去。

## 3.5 架构没有完全收敛：四条分叉

稀疏化是主线，但半年里同时出现了几个不按 MoE 剧本走的方向，写趋势时不能忽略：

| 分叉 | 事件【站内】 | 意义 |
|---|---|---|
| **无反向传播预训练** | `Dust: Pretraining Transformers Without Backpropagation`（10-05），把扰动从权重空间移到激活空间 | 训练算法本身被重新审视 |
| **扩散语言模型** | DiffusionGemma-26B（06-10） | 生成范式不只有 next-token |
| **状态空间 / 线性注意力** | `Mamba-3: Improved Selective State Space Models`（09） | 长序列的另一条复杂度路线 |
| **决策模型独立成类** | Liquid d1-3B / d1-omni-600M（10-09）、OpenAI Decisions API（10-07）、DecisionsBench（10-22） | 把「选什么」从「生成什么」里拆出来 |

另外 `Strata` 用 24576 个小专家让 **12GB 显卡跑 125B 模型**【站内】，说明稀疏化不只服务超大规模，也在服务端侧。**同一个技术，一头压数据中心成本，一头把大模型塞进消费级显存**——这是它能在半年里成为主线的原因。

## 3.6 回到 Hy4

锚点 Hy4 preview 的 `78 层 / 256 路由专家 + 1 共享 / top-8 / 49B 激活`，把本章四个趋势全占了：大总参（770B）、低激活比（6.4%）、细粒度专家（256 个）、共享专家（+1）。它的 `Gated DSA + IndexCache` 属于第 4 章，而「模型参与自身研发全链路」在 9 月正式版变成算力再降 25%，是第 8 章 RSI 的起点。

**一个可迁移的结论**：看一个模型别只看「多少 B」，先问三个数——激活参数、top_k、专家粒度。这三个数才决定它能不能被部署、能不能开长会话、以及通信瓶颈在哪。

## 3.7 本章小结

- 近半年总参从 770B 涨到 2.4T，激活稳在 15~49B；前沿模型激活比收敛到 **4.6%~6.4%**，小模型反而 20.8%。
- MoE 三个旋钮：专家粒度（256 → 24576）、top_k（小常数）、共享专家（+1）；细粒度化提升组合表达力，代价是 EP 通信。
- 通信与训练补账：EP8 dispatch 373GB/s、4000 GPU 训 1.05T、11.3 万张 910D、14.8T token、全量 FP8 的 8σ spike 回退。
- 训练配方公开本身成了一种发布形态；架构同时存在 Dust 无反向传播、扩散语言模型、Mamba-3、决策模型四条分叉。
- 稀疏化同时服务数据中心降本与端侧可跑（12GB 跑 125B）。

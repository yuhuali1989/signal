# 第 7 章 · 组织与人：从卖许可到交付结果，什么必须重写

## 7.1 一个绕不开的事实：转型期伴随大规模人员结构调整

先直面数据：

| 公司 | 动作 |
|---|---|
| **Oracle** | 计划裁员最高 **3 万人**；核心 ERP 产品 Fusion 增速从 25% 降至 18%，客户流失率从 3% 升至 5% |
| **Salesforce** | 裁撤超 **4000 人**，推进 Agentforce 落地 |
| **行业整体** | 标普 500 软件与服务指数自 2025 年 10 月高点累计跌超 33% |

这不是简单的"降本"。要理解它，必须区分两种裁员：

| 类型 | 原因 | 含义 |
|---|---|---|
| **防御性裁员** | 收入承压，削减成本 | 危险信号 |
| **结构性替换** | Agent 承担了原本由人做的工作，岗位被重新定义 | 转型进行中 |

判断一家公司属于哪种，看一个指标：**裁员的同时，AI/ Agent 相关岗位是否在扩招**。Salesforce 一边裁 4000 人一边把 Agentforce 做成 39 亿美元 ARR，属于后者。

## 7.2 「智能共生者」：一个需要落到岗位上的概念

徐少春的表述是：

> **AI 的本质不是 AI，而是应用 AI 的人。** 技术的终极价值在于赋能于人，而非替代人。未来属于「智能共生者」——那些能够熟练驾驭 AI 工具、实现人机协同创新的企业管理者和员工。

这个概念如果只停留在演讲里，就是空话。要落地，必须回答：**具体到岗位上，人和 Agent 的分工是什么？**

第 4 章给出的分层可以直接翻译成岗位设计原则：

| Agent 类型 | 人的角色 | 岗位变化 |
|---|---|---|
| 信息型 / 辅助型 | 消费者 | 全员使用，岗位本身不变，但**效率基线被抬高** |
| 交易型（执行作业） | 监督者 | 传统作业岗（录入、对账、初审）**大幅缩减**，转向异常处理 |
| 决策型 | 决策者 | 岗位保留且**价值上升**，但要学会与 AI 建议协作 |

金蝶"AI 财务部"的设计完整体现了这一点：15 个智能体分三层，**人只需在关键环节做出决策**。基层执行作业被自动化，高层判断被保留并强化。

## 7.3 FDE 模式：为什么软件公司开始需要「驻场工程师」

这是 AI 时代软件交付方式最显著的变化，也是 Palantir 带火、正在被企业软件行业普遍借鉴的模式。

### 传统交付 vs AI 交付

| | 传统软件交付 | AI / Agent 交付 |
|---|---|---|
| 交付物 | 一套配置好的系统 | 一批**能真正跑通业务流程的 Agent** |
| 成功标准 | 系统上线、验收通过 | **业务指标改善**（如结账天数缩短 60%） |
| 知识在哪 | 在产品与实施方法论里 | 大量在**客户现场的业务细节**里 |
| 失败模式 | 需求理解偏差 | **Agent 不知道客户真正的业务规则** |

关键在第三行：Agent 要真正好用，必须理解客户**特有的**业务规则——而这些规则从来不在产品文档里，只在一线员工的脑子里。

**这就是为什么需要前向部署工程师（Forward Deployed Engineer, FDE）**：把工程能力直接放到客户现场，一边理解业务，一边把 Agent 调通。

### 对中国厂商的特殊含义

中国 SaaS 长期有一个"劣势"：**定制化重、交付成本高**，导致营收增长但亏损（用友亏 9.45 亿、金蝶亏 0.98 亿）。

但在 AI 时代，这个包袱有意外的一面：

- **劣势**：定制化拖累毛利，无法规模化
- **优势**：这些公司**积累了大量贴近客户业务的知识与实施队伍**——而这恰恰是 FDE 模式最稀缺的资源

**转型方向不是"戒掉定制化"，而是把定制化能力产品化**：
1. 把反复做的定制抽象成 **Skill**（金蝶灵基已有 300+ Skill）
2. 把交付方法论沉淀成**可搭建的平台**（苍穹 Agent 平台零代码搭建）
3. 让业务人员自己完成长尾定制（金蝶的表述是"业务人员也能深度参与 AI 重塑"）

## 7.4 人才结构的三个必须补的缺口

从金蝶、SAP、Salesforce 的动作反推，AI 转型期至少要补三类人：

| 缺口 | 为什么需要 | 困难点 |
|---|---|---|
| **Agent 工程**（运行时、编排、记忆、治理、观测） | Forrester 明确指出这是最大的新机会层 | 这是全新工种，市场上人少 |
| **业务知识工程**（把三十年财务/供应链 know-how 转成 Agent 能力） | 金蝶"把三十多年财务积累转化为智能体的专业能力" | 需要既懂业务又懂 AI 的复合人才，最难招 |
| **AI 定价与商务**（设计 credit/action/结果计费） | 第 6 章的定价实验全部是新课题 | 财务、产品、法务要一起重新学习 |

## 7.5 生态：为什么必须开放，开放什么

一个反直觉但重要的判断：**AI 时代，厂商不可能自己做完所有 Agent。**

理由很简单：企业场景是长尾的，每家公司的业务规则都不同。厂商能做的是**提供平台、底座和旗舰场景**，长尾必须交给客户与生态。

金蝶的开放动作清单：

| 动作 | 内容 |
|---|---|
| **开放核心技术** | 2025 年成立"企业管理 AI 生态联盟"，开放**动态领域模型（KDDM）** |
| **支持标准协议** | 苍穹 Agent 平台 2.0 支持 **MCP 与 A2A**，允许多模型混合、外部 Agent 接入 |
| **资金承诺** | 2022 年起承诺五年投入 **20 亿元生态基金** |
| **能力补齐** | 与麒麟软件、达梦数据库战略合作（国产化），投资艺赛旗补 RPA 能力 |

**开放的风险与收益**：

| | 说明 |
|---|---|
| 收益 | 更多 Agent 长在你的平台上 → 平台成为必经之路 → 收费站成立（第 6 章） |
| 风险 | 开放核心技术（如 KDDM）可能被模仿；外部 Agent 可能绕开你的治理 |

所以开放必须**分层**：底座与协议开放（换取生态），**事务执行与治理能力保留**（守住收费站）。

## 7.6 组织改造的五个自检问题

给决策者一份可执行的检查清单：

1. **你的 Agent 团队是独立 BU，还是嵌在业务线里？**（嵌在业务线更好——Agent 必须贴着业务知识做）
2. **有没有 FDE 角色，他们向谁汇报？**（理想是双线：工程能力归研发，业务理解归客户成功）
3. **定制化交付的人，有没有转成 Skill 沉淀的人？**（这是中国厂商化解毛利包袱的关键）
4. **裁员的同时，Agent 工程岗位在扩招吗？**（判断是防御性还是结构性）
5. **你开放了什么，守住了什么？**（协议/底座开放，事务与治理守住）

## 7.7 本章小结

- **转型期的人员调整要区分防御性与结构性**——看 AI 岗位是否同步扩招。
- **「智能共生者」必须落到岗位分工**：执行作业交给 Agent，关键决策保留给人。
- **FDE 模式是 AI 交付的必然**：Agent 需要客户现场的业务知识。中国厂商的定制化包袱在这里可以转化为优势，路径是把定制化**产品化成 Skill**。
- **三个必须补的人才缺口**：Agent 工程、业务知识工程、AI 定价商务。
- **生态要分层开放**：底座与协议开放换生态，事务执行与治理守住换收费站。

# 第 11 章 · 真实产品校准：Higgs Realtime Duplex 逐条对账

前 10 章用的是一组**为讲清机制而构造的教学基准**（80ms 片、87 槽位、75840 词表、8 层 RVQ）。它能让每个 shape 都手算出来，但它不是任何量产模型的参数。

2026-11-05，Boson AI 发布 **Higgs Realtime Duplex**（技术贡献者含李沐 Mu Li、Alexander Smola），官方博客给出了罕见的完整工程细节。这一章用它做标尺，把前十章逐条对账：**哪些是教学示意、哪些必须改、哪些结论反而被印证了**。

> 可用性边界先说清楚：该模型是 **research preview，权重未开放，专用 API 仅 waitlist，无定价**；Boson 在售的是上一代回合制 Higgs Realtime，不是同一个模型。所以本章对齐的是「已公开的架构事实」，不是「可复现的开源实现」。

## 11.1 一句话概括它做了什么

> **切时间，不切轮次**（Slice time, not turns）。

把所有流——你的语音、摄像头、工具结果、后端回复进来；模型的语音、表情、后台工作出去——统统切成 **160ms chunk**。每一步读刚到的输入 chunk、写下一段要播放的输出 chunk。**静音也是一个 chunk**，不是被 VAD 丢掉的空白。带视频时，静音期间画面帧照常流入，模型从不停止听和看。

它因此能：用户还在说就开始推理；边说边在后台调工具、把难题委派给更大的后端模型；结果分批回来时直接拼进后续 chunk，不用「请稍等」也不用重开一轮；用户插话就停、重新规划、决定已在跑的后台任务要不要继续；识别「这句话不是对我说的」而不抢答。

|---|---|---|---|

| 面部输出 | 无 | **2 个 image latent / 片** | 缺 |
| 词表 | 75840，四段分区 | **官方未公开**；输出侧为连续 latent，非离散 ID 查表 | 改 |

| 静音 | `SIL` 控制符，画面没变就跳过视觉片 | **静音即 chunk，视频帧持续流入** | 收紧 |
| 首包延迟 | 120~200 ms | **约 200 ms**（用户说完后） | ✅ 吻合 |

## 11.3 九条必须修正的断言

**①「全双工必选 codec 直接重建」——错。**（第 7 章）
Higgs 用因果流匹配解码器，属于生成式解码，照样 200ms。区别不在「重建 vs 生成」，而在**解码器是否逐 chunk 因果、每片算力恒定**：它每片只出 2 个 audio frame，以参考音频为条件做少步生成，把迭代成本锁在 160ms 片内，而不是对整段语音多步扩散。

**②「全双工产品几乎不输出画面」——错。**（第 8 章）
Higgs 每片都在渲染面部视频。正确说法是「**不让主干逐 token 采画面**」：主干每片只多付 2 个连续 latent，像素生成外包给独立的因果 DiT，条件是一张参考图 + 前两个 latent。既因果、又恒定算力、还不撑爆 KV cache。

**③「生成侧必须有离散 ID 才能采样」——错。**（第 2、7、8 章）
输出侧是连续 latent + 生成式解码。这也顺带回答了「视频词表为什么不能用原版 VQ-GAN」：**量产全双工干脆不用视觉离散词表**，用极低维连续 latent 配因果 DiT，同时避开码本坍缩、逐帧闪烁和非因果泄漏三个坑。本书的四段统一词表仍是最容易讲清「ID 区间 / logits mask / 状态机」的教具，但不是业界共识。

**④「75840 统一词表 / 8 层 RVQ 是通用做法」——未证实。**（第 2、3 章）
官方没有公开词表结构。可确认的只有「每片音频入 1、出 2、视频约 12/帧、面部 2 latent」这些**极稀疏的 token 数**。把本书配置写成「全模态模型就是这样」是过度外推。

**⑤「87 槽位、1087 token/s、171GB KV」——放大约 20 倍的教具。**（第 1、6、9 章）
真实预算是 2.6K~5K token/分钟、5 分钟窗口 13K~25K。**最有价值的修正不是数字，是优先级**：Higgs 把「从源头压每片 token」放在第一位，渐进 compaction 第二位，事后 KV 压缩第三位。本书第 9 章把顺序排反了。

**⑥「80ms / 12.5Hz」——真实是 160ms。**（全书）
片长翻倍但每片 token 降到个位数，总算力大幅下降。决定延迟的不是片长，是「每片能否在片长内算完」。

**⑦「静音时画面没变化就跳过视觉片」——需收紧。**（第 4 章）
合起来的完整规则是：**视觉是否跳过只看画面变化，与用户有没有在说话无关**。用户不说话时可能在看白板、皱眉、把杯子转个面，这些都是回答依据。把音频静音当作跳过视觉片的信号会让模型在停顿那几秒「瞎掉」。

**⑧「全双工比半双工贵 3~10 倍」——需要加限定。**（第 10 章）
这是按本书的宽松预算算的。Higgs 的设计目标是 **1 小时模型时间 ≤ 1 小时人工成本的 1/10**，靠前台 45B 自己能答就自己答、只在必要时委派给大模型来控成本。极紧 token 预算下，长会话成本是可控的。

**⑨「效果已经不错、接近人类节奏」——要补反面证据。**（第 10 章）
Higgs 七项 benchmark 里**只拿了一项第一**（Big Bench Audio 98.9），Full-Duplex-Bench v1.5 得 75.5，**低于 GPT-Live-1 的 80.1 和 TML Interaction Small 的 77.8**。全双工交互本身还没被解决，别把「延迟达标」读成「交互智能达标」。

## 11.4 八条被真实产品印证的结论（不用改）

1. **区分在两端、融合在中间**：主干仍是「一个模型多流」，跨模态理解靠共享序列里的注意力，没有外挂融合模块。
2. **双流/多流只建模不采样**：用户流持续进入，模型流持续输出，两者在同一时间轴上并行。
3. **静音、附和、打断必须是模型生成的行为**，不是 VAD 阈值 + 状态机——Higgs 明确把「何时说、何时听、何时附和、何时忽略」交给模型判断。
4. **绝对时间锚**：按固定 chunk 对齐所有流，等价于本书的「绝对毫秒 ID」，而不是靠 token 序号。
5. **因果性**：解码器（流匹配、DiT）全部冠以 causal，与本书 chunk-causal 的要求一致。
6. **文本能力必须被保护**：Higgs 从文本预训练模型起步、续训约 2T token 的音视频数据，IFEval 94.1 说明语言能力没被拖垮——正是前几轮讨论的「多模态拖累文本」的结构性解法。
7. **指代消解需要深层跨模态融合**：官方 demo 里读白板、看口型纠音、按画面更新架构图，都依赖音视频在同一时间轴上互相注意。
8. **配置即 prompt**：文本 prompt 定人设/权限/工具 + 几秒参考音频 + 一张参考图，零样本换音色换脸、无需微调。参考条件只进 decoder 不进主干，是「主干管语义、decoder 管渲染」这条分界线的漂亮落地。

## 11.5 本书完全没写、但真实产品最看重的三层

**① 前台 / 后台并行（"One model, many threads"）**

```
前台 45B MoE  ←→  持续对话（每 160ms 一片，永不阻塞）
   │ 异步调用
   ├─→ 思考线程：用户还在说就开始推理，可跨多个 chunk
   ├─→ 工具线程：搜索 / 知识库 / 预订 / CRM，结果可分批返回
   └─→ 委派线程：把难题连完整上下文交给更大的后端模型
                    结果回来时作为 payload 落进某个输入 chunk
```

关键细节：**工具结果作为 payload 进入输入 chunk，没有固定的「每片文本 token 配额」**；工具可分阶段返回中间结果，模型不等完整结果就开始说。思考与工具调用的生成可以跨多个 chunk，拼接起来才恢复完整输出流。这更像操作系统多线程，而不是本书第 9 章那张顺序时间片表。

对比路线：Thinking Machines 把全部推理与工具都放后台，前台简单但可能 10 秒以上才答、成本由大模型决定；Boson 选择「前台尽量自己答，只在必要时求助」。

**② 极紧的 token 预算 + 渐进 compaction**

| 流 | 每 160ms chunk | 折算 |
|---|---|---|
| 音频入 | 1 token | 6.25 tok/s |
| 音频出 | 2 token（audio frames） | 12.5 tok/s |
| 视频入 | 每 6 chunk 一帧，约 12 token | ≈12.5 tok/s |
| 面部出 | 2 image latents | — |
| 合计 | 音视频约 **2.6K token/分钟** | 含思考/工具 2.6~5K |

生产里保留**最近 5 分钟的音视频 + 压缩后的文本**，约 13K~25K token；更老的历史只留文本。思考轨迹与工具结果边产生边渐进压缩，只把「进行中工作所需的信息」往前带。**这是全双工能开长会话的前提**，比 KV cache 事后剪枝重要得多。

**③ 训练：多教师 on-policy 蒸馏 + RSI 闭环**

- 从文本预训练模型出发，续训约 **2T token** 的文本/音频/视觉数据，自建 H100 集群、部分基于 Megatron；
- 后训练用 **MOPD（multi-teacher on-policy distillation）**：从同一基座用 GRPO 训出多个专家教师（自然对话、交互行为、动态委派、任务完成），再蒸馏成单一学生；
- 另有**递归自我改进闭环**：让 Agent 系统与模拟环境交互、复盘失败、合成定向数据——正好接上站内第 74/75 轮讨论的 RSI 与治理（这类闭环要能进企业采购，仍需冻结评估器与审计报告的约束）；
- 教师学会的是「**说什么 + 何时行动**」：何时开口/让步、何时起一个推理线程、何时调工具、何时委派。这说明交互节奏是**被训练出来的策略**，不是架构附赠的功能。

## 11.6 效果到底好不好：修正后的结论

| 评测 | Higgs 45B MoE | 最强对手 |
|---|---|---|
| Big Bench Audio | **98.9** | Gemini 3.8 Live Ext. 98 |
| Audio MultiChallenge (APR) | 44.9 | RT-2 xHigh 48.5 |
| Full-Duplex-Bench v1.5 | 75.5 | **GPT-Live-1 80.1** |
| QIVD（流式音视频） | 56.0 | RT-2 xHigh 58.2 |
| ProactiveVideoQA | 31.9 | TML 33.5 |
| τ-Voice（Agent 任务） | 69.8 | GPT-Live-1 Astra 74.5 |
| IFEval | 94.1 | RT-2 xHigh 95.2 |

45B 对 276B（TML Interaction Small）打平，Boson 自己的解读是「领域还早，**数据、架构、训练方法比参数量更重要**」。这个判断对本书第 10 章「全双工买到的是交互节奏，不是智能水平」是强化而非推翻。

修正后的三句话结论：

1. **交互自然度**已能做到约 200ms 响应、自然打断、附和、忽略非对自己说的话，工程上成立；
2. **任务能力**不比同尺寸文本基座更强，但有 2T token 续训 + IFEval 94.1 兜底，没有明显退化；
3. **成本**在极紧 token 预算 + 前台自答策略下可控，目标 ≤ 人工成本的 1/10；但 **Full-Duplex-Bench 仍输给对手**，且权重未开、无定价、仅有演示，量产质量与真实条件下的延迟数字尚未公开。

所以别把 Higgs 当成「全双工已解决」的证据，更准确的说法是：**它第一次把「一条时间轴上跑多条流 + 前后台并行」这套架构跑通并公开了预算账本，而交互智能本身还在早期**。

## 11.7 对本书读者的实操建议

| 你要做的事 | 照本书哪部分 | 按 Higgs 怎么改 |
|---|---|---|
| 讲清 token / 词表 / shape | 第 1~6 章全部 | 保留，但开头声明是教学基准 |
| 自己搭一个最小全双工原型 | 第 5、7、9 章的代码 | 时间片改 160ms；每片 token 压到个位数；输出侧用连续 latent + 因果 decoder |
| 做长会话 | 第 9 章 KV 压缩 | 优先级反过来：先压预算 → 再渐进 compaction → 最后 KV 剪枝 |
| 出画面 | 第 8 章 | 别逐 token 采；每片 2 个 latent + 因果 DiT，参考图零样本定长相 |
| 选解码器 | 第 7 章 | 判据是「逐 chunk 因果 + 恒定算力」，不是重建 vs 生成 |
| 做评测 | 第 10 章六类口径 | 加 Full-Duplex-Bench v1.5、Big Bench Audio、QIVD、τ-Voice、IFEval |
| 训练交互行为 | 本书未覆盖 | MOPD + GRPO 专家教师；把「何时说/停/附和」当可学习策略 |

## 11.8 本章小结

- 前十章是**教学基准**，真实产品（Higgs Realtime Duplex, 2026-11-05）在片长、token 预算、词表、解码器、输出画面、前后台架构六处都不同。
- 九条断言要改，其中最关键的三条：全双工不必用直接重建解码器、真实产品每片都在出画面、生成侧不必是离散 ID。
- 八条结论被印证：区分在两端融合在中间、双流只建模不采样、静音/附和/打断是模型行为、绝对时间锚、因果性、文本能力保护、指代消解靠融合、配置即 prompt。
- 本书遗漏的三层：前台/后台并行（多线程而非顺序时间片）、极紧 token 预算 + 渐进 compaction、MOPD + RSI 闭环训练。
- 效果修正：七项 benchmark 只拿一项第一，Full-Duplex-Bench 输给 GPT-Live-1；架构跑通 ≠ 交互智能解决；研究预览、权重未开、无定价。

# 第 1 章 · 事实底座：用 373 条新闻、93 个模型看这半年

## 1.1 一句话结论

> **2026 年 5→11 月，模型架构的主线不再是「堆参数」，而是三件事：把激活参数压下去（稀疏化）、把时间结构显式建模（全双工与长程）、把上下文成本压进可开长会话的区间（KV 与 compaction）。而数据侧的主线同步从「有多少」转向「配比、口径、可追溯」——两件事其实是同一笔账：算力不再无限，于是架构和数据一起被要求「省得有依据」。**

这本书不写预测，也不复述新闻标题。它用 signal 站内在过去半年沉淀下来的数据做一次可复算的归纳，并把用户点名的「数据相关的事情」单独给两章（第 10、11 章），而不是当附注。

## 1.2 五个数据源与半年时间窗

时间窗：**2026-05-08 → 2026-11-08**（下称「近半年」）。数据源全部来自本仓库：

| 源 | 全量 | 近半年 | 用途 |
|---|---|---|---|
| `content/news/news-feed.json` | 600 条 | **373 条** | 事件时间轴、趋势关键词、治理与数据事件 |
| `content/gallery/models.json` | 158 个 | **93 个** | 架构参数（总参/激活/层数/注意力/上下文/许可） |
| `content/papers/papers-index.json` | 104 条 | **34 条** | 研究方向分布（KV、VLA、世界模型、RSI） |
| `content/benchmarks/benchmarks.json` | 8 类榜单 | 刷新至 11-07 | 能力口径与榜首变化 |
| 站内书籍 / 文章 | 33 部 / 146 篇 | 近半年新增多部 | 技术细节的二手交叉验证 |

复算脚本（不依赖第三方库）：

```python
# 【推断】本章所有统计量由下面这段逻辑产生
import json
from collections import Counter

news = json.load(open("content/news/news-feed.json"))
half = sorted([x for x in news if "2026-05-08" <= x["date"] <= "2026-11-08"],
              key=lambda x: x["date"])

by_month = Counter(x["date"][:7] for x in half)
by_cat   = Counter(x["category"] for x in half)
# 05:66 06:46 07:53 08:72 09:39 10:70 11:27  → 合计 373
```

月度分布：`2026-05` 66 / `06` 46 / `07` 53 / `08` 72 / `09` 39 / `10` 70 / `11` 27。**8 月和 10 月是两个高峰**，9 月是低谷——这个节奏本身在第 2 章会对应到具体事件簇。

关键词命中（标题 + 摘要 + 标签，近半年）：`Agent` 94、`开源` 108、`推理` 75、`数据` 74、`上下文` 59、`成本` 36、`MoE` 32、`芯片` 27、`评测` 24、`具身` 17、`世界模型` 13、`长程` 12、`视频生成` 12、`量化` 11、`检索` 11、`KV` 10、`VLA` 9、`FP8` 9、`FP4` 9。**「数据」与「推理」的出现频率几乎一样高**，这是本书把数据侧独立成篇的直接依据。

## 1.3 ★数据先给自己上了一课：口径不一致

做统计时撞到两个真实问题，它们恰好是「数据相关的事情」最好的开场，也决定了本书后面所有数字怎么读。

**问题一：字段完整度参差。** 近半年 373 条新闻里：

| 字段 | 有值条数 | 覆盖率 |
|---|---|---|
| `category` / `tags` | 373 | 100% |
| `importance` | 208 | 55.8% |
| `whyMatters` | 208 | 55.8% |
| `hot` / `region` | 185 | 49.6% |
| `platform` | **20** | **5.4%** |

后果很直接：**用 `importance >= 4` 筛「重要事件」，5–7 月会一条都筛不出来**，8 月 20 条、10 月 25 条、11 月 20 条，9 月只有 1 条——不是那几个月没大事，是字段后期才补。本书的时间轴因此**按日期全量铺开**，只用 `importance` 做辅助标注，不用它做筛选条件。

**问题二：数组不是全局有序，类目命名中英混用。** 首页组件直接 `getNewsFeed().slice(0, 12)` 且 loader 不排序，所以新批次按日期降序 `unshift` 到最前；历史区间则保留早期批次的顺序。因此任何时间统计都必须先 `sort(by date)`，否则会得到「近半年区间是 10-31 → 11-07」这种荒谬结果。类目字段同时存在 `industry`(81) 与 `产业`(4)、`model-release`(37) 与 `模型发布`(19)、`research`(10) 与 `研究`(12)——做类别占比前必须先归一。

> 这两条不是本站的缺陷展览，而是**任何真实数据工程的常态**：schema 会演进、字段会补录、枚举值会分叉。第 10 章讲预训练语料、第 11 章讲训练 pipeline 时会反复回到这个教训：**先定口径，再谈结论**。

## 1.4 三级证据与待核实标记

沿用站内《Higgs Realtime Duplex 深度拆解》立下的证据纪律，按本书的数据形态改成三级：

| 标签 | 含义 | 例子 |
|---|---|---|
| **【站内】** | signal 的 news / models / papers / benchmarks 收录 | Hy4 preview 770B/49B、Qwen3.9-VL 三阶段配比、Ray 3.0 GA |
| **【报告】** | 厂商技术报告 / 官方博客 / 论文原文（站内条目转引） | DeepSeek V4-Pro 14.8T token、Higgs 160ms chunk、Qwen VLM 训练报告 |
| **【推断】** | 本书基于上述数据的归纳、比值、算式 | 激活比、月度节奏判断、七条趋势 |

另有一条硬规则：新闻库里带 **「单一信源·待核实」** 标记的条目（如 10-07 那条「OpenAI 冻结前沿训练」）**只作为背景出现，不进任何结论或数字表**。

**【站内】不等于「已独立核实」**：它表示「本站收录了这条」，其中多数转引自公开发布。凡本书要拿来做架构结论的关键数字，尽量再与 `models.json` 的 `factSheet` 或站内已有书籍交叉一遍。

## 1.5 贯穿全书的锚点：2026-08-28 的 Hy4 preview

趋势书最容易写成一串互不相干的新闻。本书钉一个具体锚点，每章都回来问「这一章讲的变化，在它身上怎么体现」：

| 项 | 值【站内 models.json / factSheet】 |
|---|---|
| 发布 | 2026-08-28，腾讯混元 Hy4 preview，Apache 2.0 |
| 总参 / 激活 | **7700 亿 / 490 亿**（含 MTP 层 780B） |
| 架构 | MoE，**78 层**，每层 **256 路由专家 + 1 共享专家，top-8** |
| 注意力 | **Gated DSA + IndexCache 跨层稀疏索引复用** |
| 上下文 | **1,000,000** |
| 归一化 / 位置 | RMSNorm / RoPE |
| 训练 | 预训练 + 后训练，**模型参与自身研发全链路优化** |

它一个模型同时踩中了本书六条主线：MoE 稀疏化（第 3 章）、稀疏注意力与 1M 上下文（第 4 章）、多模态与全双工相关的训练栈（第 5 章）、推理与 RSI 回灌（第 7、8 章）、数据配比与算子自改进（第 10 章）、开放权重与训练栈披露（第 11 章）。后续每章末尾都有一节「回到 Hy4」。

## 1.7 本章小结

- 时间窗 2026-05-08→11-08，五源合计 373 条新闻 / 93 个模型 / 34 篇论文 / 8 类榜单；月度双高峰在 8 月与 10 月。
- 「数据」关键词命中 74 次，与「推理」75 次几乎持平，是数据侧独立成篇的依据。
- ★两个真实数据问题：`importance` 等字段仅约 5~56% 覆盖、`platform` 只有 5.4%；数组非全局有序且类目中英混用。**先定口径再谈结论**。
- 三级证据【站内】【报告】【推断】+ 待核实条目不进结论；关键数字尽量与 `factSheet` 交叉。
- 全书锚点是 Hy4 preview（770B/49B、78 层、256+1 专家 top-8、Gated DSA + IndexCache、1M 上下文）。

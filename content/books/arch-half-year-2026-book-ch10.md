# 第 10 章 · 数据侧（一）：配比红线、合成数据与去重披露

前面九章讲的是「模型怎么算」，这一章和下一章讲「拿什么算」。用户点名要一起看数据，本书给整整两章：本章管**预训练语料与训练配方**，第 11 章管**pipeline、存储与治理**。

## 10.1 规模不再是唯一指标

| 项【站内 / 报告】 | 数字 | 说明 |
|---|---|---|
| DeepSeek V4-Pro 训练（08-30） | **14.8T token**，MuonScale 优化器，成本较 V3 降 40% | 配方与规模一起公开 |
| Higgs Realtime Duplex 续训（11-05） | 约 **2T token**（文本/音频/视觉） | 从文本基座续训 |
| Kimi K3 开源权重（07-27） | **594GB MXFP4** | 分发体积 |
| Qwen4（09-22 披露） | 训练中，将扩至 **5–10T 参数** | 参数规模预期 |
| Emu3（外部参照） | 12.3T token 训练，共享词表 184622 | 统一离散路线 |

【推断】把这五行放一起：**规模还在涨，但半年里真正被反复引用的是「配比、优化器、精度、稳定性阈值」**。08-30 那次发布之所以是转折点，不是因为 14.8T 这个数最大，而是它第一次把 MuonScale、成本降幅与训练量一起摆出来——**训练配方从内部资产变成公开规格**。

## 10.2 ★配比红线：Qwen3.9-VL 与 caption 分布

11-06 Qwen3.9-VL 公开的 VLM 训练配比报告【站内 factSheet】，是这半年数据侧最有价值的一份材料：

| 阶段 | 文本 token 占比 | 观测 |
|---|---|---|
| 一 | **62%** | 打底 |
| 二 | **48%** | ↓ 触发可测语言退化 |
| 三 | **55%** | 回升修复 |
| 结论 | **低于 50% 即出现可测语言退化** | MMLU / 数学 / 代码最终与纯文本基座持平 |

配套的冻结策略（第 5 章已展开，这里补数据视角）：**对齐阶段 LLM 全冻**（只让 projector 学翻译）、**SFT 解冻且 LR 压到 1/20**。所以同一批数据在三个阶段的用途完全不同：

```
阶段一/三：文本数据当压舱石（保分布覆盖）
对齐阶段：图文对只训 projector，LLM 不接梯度
SFT 阶段：复杂指令数据才允许低 LR 动 LLM
```

**为什么 50% 不是简单的数量问题。** 前几轮讨论过：只用图文对里的 caption 文本预训练 VLM 是不够的——LAION 级 caption 拆出来约 0.1~0.3T token，数量上勉强够喂 7B（Chinchilla 约 0.14T），但分布是「约 12 token 的描述性短句」，缺推理、代码、数学、长文档、多轮对话。**CLIP 文本塔就是这条路的终点：只学会匹配，学不会生成与推理。**

把范围扩到**交织文档**（MMC4 / OBELICS 这类网页原文连图带正文）性质就变了：文本量升到 1~2T、分布回归自然网页语言。所以业界的实践答案是：「只用 caption」不行，「图文对 + 交织文档 + 纯文本三路混合」可行——但此时本质上已经在做混合路线的 LLM 预训练，只是每篇文档里恰好插着几张图。

> ⚠️ 【推断】50% 是 Qwen 在自家基座与配比下的**观测值**，不是通用常数。本书把它当作「存在一条分布红线」的证据，写进自己的配置表前必须重测。这正是第 1 章证据纪律的用处。

## 10.3 合成数据：只差一个 oracle

站内《RSI 工程全书》第 6 章给过一句可以贴在训练集群墙上的话：

> **self-improvement 和 self-poisoning 是同一个循环，只差一个 oracle。**

```
合成数据 + 验证器过滤  →  AlphaZero / STaR / LADDER（自我改进）
合成数据 + 无过滤回灌  →  模型崩塌 / 多样性崩塌（自我投毒）
```

半年里站内的三条证据正好覆盖两端：

| 端 | 事件【站内】 | 机制 |
|---|---|---|
| 有 oracle | Kimi K3.5 算子采纳率 **37→61%**（11-01） | 新增**算子级 diff 审查**：Triton 内核先过数值等价性测试再进主干 |
| 有 oracle | Hy4 RSI 二阶段（09-02） | 数值等价性是天然可验证判据 |
| 无 oracle | 多智能体共享记忆被 **0.01% 污染**样本劫持 61% Agent（08-31） | 写入记忆前没有确定性验收 |
| 无 oracle | RSI 红线草案（10-23）要求冻结评估器 | 承认弱信号替代强信号是主要失败模式 |

**工程结论**：优先选有确定性验收的合成（编译、单测、数值等价、符号校验）；LLM Judge 只能当参考信号，不能当准入 oracle。一次假成功被写进记忆 / 技能库 / 数据管线后，后续循环会把它当能力证据继续放大——这与第 8 章的记忆投毒是同一类事故的不同形态。

## 10.4 去重、污染与哈希清单

| 事件【站内】 | 做法 |
|---|---|
| SWE-bench Pro 污染质疑（09-01） | DeepSeek 与智谱公布**去重哈希清单**自证 |
| MLCommons 冻结集清单（11-06） | 数学/代码/安全三类必锁；要求披露**可变集与公开榜单重合度** |
| EU AI Act 第三阶段（07-28） | 开源权重须附**训练数据摘要** |
| 中国训练数据合规指引（07-29 / 11-04） | 来源披露分级 + 涉政涉军类目**白名单制** |
| 万亿 CLIP 检索（站内文章） | LAION-5B 去重、DataComp 从 128 亿图文对筛高质量子集 |

一个可运行的最小去重/披露检查：

```python
import hashlib, json

def sample_hash(item):
    # 归一化后取哈希：同一内容不同文件名的重复会被抓出来
    norm = json.dumps(item, sort_keys=True, ensure_ascii=False,
                      separators=(",", ":")).encode("utf-8")
    return hashlib.sha256(norm).hexdigest()

def dedup_with_report(samples, frozen_hashes):
    seen, kept, report = set(), [], {"total": 0, "dup": 0, "frozen_overlap": 0}
    for s in samples:
        report["total"] += 1
        h = sample_hash(s)
        if h in seen: report["dup"] += 1; continue
        if h in frozen_hashes: report["frozen_overlap"] += 1; continue  # 污染拦截
        seen.add(h); kept.append(s)
    return kept, report
```

`frozen_overlap` 这一项就是 MLCommons 那条「可变集与公开榜单重合度」精神的代码形态：**治理不指望消灭刷分动机，只要求它可见、可拦截**。

## 10.5 「训练配方公开」成为一种发布形态

把半年里这些事件串起来看，会看到一条和模型分数无关的产品线：

| 时间 | 公开了什么 |
|---|---|
| 08-30 | V4-Pro：14.8T token、MuonScale、成本降 40% |
| 09-28 | 华为 openPangu-2.0：预训练 / SFT / 后训练 RL 代码全放 |
| 09-29 | 国产开源从「开放权重」走向「**开放全流程**」 |
| 09-30 | DeepEP-Ascend 算子库 + CANN 缺口清单（10-28 GLM-5.4 补全） |
| 11-03 | V4.2：全量 FP8、**8σ loss spike 回退阈值** |
| 11-06 | Qwen3.9-VL：三阶段配比、冻结/解冻时机、1/20 LR |
| 11-06 | MLCommons：冻结集清单与统一报告字段 |

【推断】驱动力是**采购与生态，不是 altruism**：企业要让自改产物进生产栈，就得复现训练条件；国产算力要被采用，就得把迁移缺口摆出来。所以「数据/配方披露」和「RSI 审计报告」是同一件事的两面——**把「怎么做出来的」变成可验证字段，才有人敢用**。

## 10.6 数据侧的三个口径陷阱

1. **token 数 ≠ 有效信息量**：14.8T 与 2T 不可直接比，一个是从头预训练、一个是续训，混合语料的文本占比也未全公开。
2. **「清洗后规模」与「原始规模」**：李沐在公开讲座里提过，捞到更多数据、清洗后往往回到 10T~50T 这个量级【⑤号来源，个人判断】，所以「抓了多少」不是「用了多少」。
3. **跨榜/跨报告的「第一」要先看方向**：第 9 章提过 `ad-vla` 是越小越好；数据侧同理，「去重率越高」不一定越好（可能把难样本也去了）。

## 10.7 回到 Hy4 与本章小结

锚点 Hy4 preview 的「模型参与自身研发全链路」在 9 月变成算子回灌（采纳率 37%），本质是**把模型产出的数据接进训练数据管线**；而 11 月 K3.5 给这条管线补上数值等价性测试与冻结评估器。**半年里 RSI 最实质的进展其实发生在数据侧，不是算法侧**——这一点在第 8 章埋过伏笔，这里收口。

**本章小结**：

- 规模仍在涨（14.8T / 2T / 594GB / 5–10T 预期），但被引用的重点是配比、优化器、精度与稳定性阈值。
- ★Qwen3.9-VL：62%→48%→55%，低于 50% 出现可测语言退化；**50% 是观测值不是通用常数**；caption 分布缺推理/代码/长文档，交织文档才回归自然分布。
- 合成数据只差一个 oracle：确定性验收（数值等价）让采纳率 37→61%，无过滤回灌导致 0.01% 污染劫持 61% Agent。
- 去重哈希清单、冻结集、重合度披露：治理让刷分可见而非消灭动机；附最小可运行 dedup 脚本。
- 「训练配方公开」成为发布形态（全流程开源、8σ 阈值、三阶段配比），驱动力是采购与生态。
- 三个口径陷阱：token 数不可直接比、清洗前后不同、指标方向要确认。

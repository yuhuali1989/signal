## 8.1 物理安全的三层设计

> ★**核心原则：不要用模型保证安全，用架构保证安全。**

| 层 | 机制 | 是否依赖模型 |
|---|---|---|
| **L1 模型层** | 不确定性估计 → 低置信时降级/停机 | 是（但只做触发） |
| **L2 规则层** | 速度/力矩/空间限位、急停、碰撞检测 | ★**否**——硬约束，硬件/固件直接生效 |
| **L3 流程层** | 人员隔离、安全围栏、遥操作接管通道、作业规程 | 否 |

**L2 是底线**：任何经过模型的输出，都必须再经过一层**不依赖模型的硬约束**。模型可以犯错，硬件限位不能失效。

## 8.2 ★ 评估体系：先解决「数字是否可信」

第 4.4 节指出行业存在「从 100 次失败挑最好演示」的问题。团队内部应先立评估规矩：

### 必报的四类指标

| 指标 | 说明 | 为什么重要 |
|---|---|---|
| **① 全量成功率** | N 次试验的完整分布，**禁止 cherry-pick** | 唯一可信的基础指标 |
| **② 分档成功率** | 已知物体 / 未知物体 / 未知环境 三档分别报 | 暴露真实泛化能力 |
| **③ ★MTBF / 连续运行失败间隔** | 连续运行 8 小时的稳定性 | ★单次成功率骗人，长时稳定性才是生产指标 |
| **④ 恢复能力** | 失败后能否自恢复、平均恢复时间、是否需要人 | 决定实际可用性与人力成本 |

### 评估协议（写死）

```
□ 固定场景、初始条件、随机种子
□ 记录每一次试验（含失败）的原始日志与视频
□ 仿真分与真实分分开报，验收以真实为准
□ 跨版本对比必须用同一协议
□ 外部演示/汇报的成功率，须附试验次数与条件
```

## 8.3 可解释性与对抗鲁棒性

| 挑战 | 说明 | 应对 |
|---|---|---|
| **决策不透明** | 端到端模型无法解释「为什么这么动」 | 关键任务保留中间表征可视化、动作归因、决策日志 |
| ★**对抗鲁棒性** | 被篡改的视觉输入可能触发危险动作 | 输入校验、多传感器交叉验证、异常检测 |
| **长尾不可知** | 训练数据无法覆盖所有物理情境 | 依赖不确定性估计 + 降级兜底（第 5.7 节） |

## 8.4 成本构成与 ROI

| 成本项 | 说明 |
|---|---|
| **硬件** | 高精度传感器、灵巧手、力控关节仍然昂贵 |
| **算力** | 大型 VLA 边缘推理需高端 GPU，推高单机成本；云端训练另计 |
| **★维护** | 物理系统磨损与故障率**远高于纯软件**——最易低估的一项 |
| **数据** | 遥操作 50–150 美元/小时；现场调试人力 |
| **安全合规** | 围栏、认证、保险、规程 |

**ROI 测算要点**：

1. **以「替代的人力成本 × 可靠运行时间」为分子**，不要按「实验室成功率」算
2. **把维护成本按全生命周期算**（通常显著高于软件系统）
3. ★**用 MTBF 与恢复时间折算有效产能**——95% 成功率 + 每次失败需人工 5 分钟，有效产能会大幅缩水
4. **先做「看」「抓」类场景**验证 ROI，再进「装」

## 8.5 ★ 架构选型决策树

```
① 任务是否要求亚毫米精度？
   ├─ 是 → ★不要纯 VLA：VLA 负责找与抓，传统视觉 + 力控负责精定位
   └─ 否 → 继续 ②

② 实时性要求（控制频率）？
   ├─ ≥ 50 Hz  → 端侧小模型（3B 级）、高 Mamba 占比混合架构、少步生成
   └─ 秒级可接受 → 可考虑云端大模型 / 世界模型规划

③ 是否需要长程规划或「想一想」？
   ├─ 是 → ★加系统 2（世界模型 / 大模型），与系统 1 分层
   └─ 否 → 单层 VLA 足够

④ 数据从哪来？
   ├─ 有真实遥操作数据 → 微调开源 VLA（GR00T / π0 系）
   ├─ 有第一人称人类视频 → 走 EgoScale 式预训练
   └─ 都缺 → 靠仿真（域随机化 + 数字孪生校准）起步

⑤ 安全要求？
   └─ 一律：模型层不确定性 + ★不依赖模型的硬约束 + 流程隔离
```

## 8.6 落地 Checklist

```
□ 任务已拆解为元技能，且每个技能可单独测成功率
□ 精度已分层：粗操作归模型，精定位归传统方法
□ 端侧可断网独立安全运行；实时回路不依赖网络
□ 有硬约束层（限位/力矩/急停），不经过模型
□ 有不确定性估计与明确的降级路径（保守/传统控制/停机）
□ 评估协议已写死：全量成功率 + 分档 + MTBF + 恢复能力
□ 每次失败都记录并回流训练（数据飞轮已接通）
□ 仿真环境已用真实数据校准（数字孪生）
□ 维护成本已按全生命周期计入 ROI
□ 期望值与「看/抓/装」刻度对齐（没把「装」当近期目标）
```

## 8.7 全书二十条结论

**认知**
1. 数字 AI 的错误是可丢弃的代码，**物理 AI 的错误是已发生的碰撞**。
2. 五个硬约束：**实时（10–100 Hz）/ 可靠（99.9%）/ 能耗 / 安全 / 可解释**。
3. ★2026 是拐点但落差巨大：**实验室 95% → 部署 60%**，95% ≈ 每天失败 50 次。
4. ★**「从 100 次失败挑最好看的」**是行业公开的秘密——先修评估再修其他。

**架构**
5. **VLA 已主导**（ICLR 2026 投稿 164 篇，18×），但生产模型仍是 2–7B 小模型。
6. ★**混合架构是 2026 默认**：Jamba 1:7、Nemotron-H 84% Mamba、Kimi Linear 3:1（KV −75%）。
7. **Mamba 的常数状态**对长时间运行的机器人天然友好（KV cache 不膨胀）。
8. 动作生成三范式：自回归 token / **Flow Matching（连续平滑）** / DiT（多峰）；落地要**少步化**。
9. ★**系统 1（VLA 快）+ 系统 2（世界模型深思）**是架构共识，别指望一个模型又快又深思。
10. 世界模型短期为 VLA 供数据与评估，中长期才谈直接控制。

**落地**
11. ★**元技能拆解**降低泛化要求——工业落地最主流方法。
12. ★**精度分层**：粗操作给 VLA，**精定位还给传统视觉/力控**。
13. **三台计算机**（训练/仿真/边缘）是三种算力需求，预算分开算。
14. ★**端侧必须断网独立安全运行**；实时控制不依赖网络往返。
15. ★**不要用模型保证安全，用架构保证安全**（硬约束不经过模型）。
16. **「看（成熟）→ 抓（可落地）→ 装（早期）」**是期望值管理的最佳刻度。
17. ★**人形是期权不是产能**：公开演示全是遥操作，Figure 退出 BMW 无生产承诺。

**数据与决策**
18. ★**第一人称人类视频**（EgoScale 21,000 小时）绕开遥操作瓶颈，是最值得关注的数据路线。
19. ★**飞轮抄自动驾驶**：影子模式、触发器采集、只回传失败与低置信片段。
20. **ROI 按 MTBF 与恢复时间折算有效产能**，别按实验室成功率算；维护成本按全生命周期计。

## 8.8 本章要点

- ★**安全三层**：模型层（不确定性触发）+ **不依赖模型的硬约束层**（底线）+ 流程层。
- ★**评估四类指标**：全量成功率（禁 cherry-pick）、分档成功率、**MTBF**、恢复能力；协议写死。
- 对抗鲁棒性靠输入校验与多传感器交叉验证；长尾靠不确定性 + 降级。
- ROI 易低估**维护成本**；★**用 MTBF 与恢复时间折算有效产能**。
- 决策树五问：精度要求 / 实时频率 / 是否需规划 / 数据来源 / 安全要求。
- Checklist 十条（元技能、精度分层、断网安全、硬约束、降级、评估协议、失败回流、数字孪生、全周期 ROI、刻度对齐）。
- 全书二十条按「认知 → 架构 → 落地 → 数据与决策」四层收束。

# 第 2 章：经典多模态评测基准

> 选自《多模态评测体系从入门到精通》

## 2.1 多模态理解基准

### 2.1.1 MMMU (Massive Multi-discipline Multimodal Understanding)

**基本概况**：
- 发布者：厦门大学 + 多校联合
- 数据规模：11.5K 多模态问题，覆盖 6 大领域（艺术与人文、商业、科学、健康医学、技术工程、社会科学）
- 问题类型：选择题（A/B/C/D）+ 少数填空题

**真值构建方式**：
```
1. 问题收集：从大学教材/考试中提取图文题目
2. 人工标注：题目验证、答案标注、选项生成
3. 专家审核：每学科领域专家审核题目质量
4. 标注间一致性检查：Kappa ≥ 0.8
```

**评测方式**：
- 零样本 + 少样本（CoT）评测
- 评分方式：准确率（选择题自动判分）
- 细粒度：按学科/难度/认知层次分层统计

**局限**：
- 选择题形式限制——无法评测开放生成
- 题目图片主要来自教材，与真实场景有差距
- 2025-2026 年模型能力大幅提升后，MMMU 接近饱和

### 2.1.2 MMBench

**基本概况**：
- 发布者：上海 AI Lab + 多校联合
- 数据规模：3K+ 问题，覆盖 20+ 能力维度
- 问题类型：选择题 + 判断题
- 特色：细粒度的能力维度分解

**真值构建**：
```
MMBench 的真值主要通过 人工标注 + 双层审核：
1. 图片收集 → 从公开数据集筛选
2. 问题设计 → 按20+能力维度编写
3. 答案标注 → 3人独立标注 + 一致性投票
4. 专家仲裁 → 不一致项由专家裁决
```

**能力维度覆盖**：
| 一级维度 | 二级维度 | 样例 |
|---------|---------|------|
| 感知 | 物体识别/颜色/位置/计数 | "图中有几个苹果？" |
| 推理 | 常识/因果/空间/时间 | "这个人为什么在跑？" |
| 知识 | 科学/文化/专业 | "这是哪个建筑？" |
| 文本理解 | OCR/图表/文档 | "这句话的意思是？" |
| 综合 | 多步推理/矛盾检测 | "图中的描述是否准确？" |

### 2.1.3 COCO Captioning

**基本概况**：
- 发布者：Microsoft COCO 团队
- 数据规模：120K+ 图像，每图 5 个人工标注描述
- 评测任务：看图生成描述
- 地位：多模态理解的"老祖宗"级基准

**真值构建（开创性方法）**：
```
COCO Caption 的真值标注流水线至今仍被广泛借鉴：

          招募标注员（Amazon Mechanical Turk）
                    │
                    ▼
         展示图像给标注员（无任何提示词）
                    │
                    ▼
         标注员写出 5 句不同侧重点的描述
                    │
              ┌─────┴─────┐
              ▼           ▼
       质量审核 → 筛选不通过 → 重新标注
              │
              ▼
        最终 5 reference captions
```

**关键流程参数**：
- 每张图标注时间：~60 秒
- 每标注员配 20 张图/批
- 质量门槛：每张图至少 1 个物体 mention + 1 个关系描述
- 标注间差异：5 个 captions 覆盖不同粒度（物体级、场景级、活动级）

## 2.2 多模态生成基准

### 2.2.1 T2I-CompBench (文生图组合性评估)

**基本概况**：
- 发布者：南洋理工大学
- 评测维度：颜色绑定、形状绑定、纹理绑定、空间关系、计数、复杂组合
- 数据规模：6K 文本 Prompt

**真值构建**：
```
T2I-CompBench 的真值是 prompt 本身——无需人工标注：
Prompt: "一个红色的立方体在蓝色球体的左边"
       ↓
模型生成的图像是否符合这条 prompt 的描述？
       ↓
自动判定：CLIP-based 检测器检查颜色+位置

关键思路：用 prompt 的语义约束作为真值，
通过第三方的物体检测器/颜色分类器自动验证。
```

### 2.2.2 VBench (视频生成评估)

**基本概况**：
- 发布者：南洋理工大学
- 数据规模：覆盖 16 个能力维度
- 评测方式：自动指标 + 人类偏好对齐

**真值构建**：
```
VBench 的真值来自于 人类偏好标注：
1. 收集 2K+ 视频生成样本
2. 每段视频由 5 人从 16 个维度打分（1-5 分）
3. 人类评分作为"黄金真值"
4. 训练一个评分模型来拟合人类偏好
5. 最终用评分模型替代人类做自动评估

16 个维度包括：
┌───── 技术质量：动态质量/帧一致性/清晰度
├───── 语义质量：文本跟随/场景连贯性/风格匹配
└───── 人类偏好：整体质量/偏好度
```

## 2.3 多模态对话评测

### 2.3.1 MMT-Bench

**基本概况**：
- 发布：2025 年
- 覆盖：31 个能力维度，4K+ 多轮对话
- 真值类型：选择题 + 评分标准 rubric

**真值构建**：
```
多轮对话的真值标注比单轮复杂得多：

第1轮：用户发图 + 提问 → 标准答案
第2轮：追问/争辩 → 标准回复
第3轮：基于前文的推理 → 标准回复

每轮都需要独立的 Ground Truth，
同时还要保证跨轮的一致性。

标注流程：
1. 脚本编写多轮对话剧本
2. 标注员按照剧本表演+标注
3. 一致性审核（跨轮逻辑自洽性）
4. 多轮 QA 对清洗
```
